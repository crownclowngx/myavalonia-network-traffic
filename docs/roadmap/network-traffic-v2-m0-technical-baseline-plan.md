## 1. 目标、首要规定与完成层次

用本项目实际插件服务运行一条可重复的代理链路：普通 HTTP/HTTPS、持续 SSE、大二进制通过代理；命中条件的请求抵达受控 B，未命中的请求抵达 A；起停、取消和退出能够释放监听与资源。产出 M1 可以接续的最小边界和技术选择证据。

执行优先级为 **SOLID 与行为正确性 → 可测试性与资源所有权 → 代理闭环 → 最小诊断交互**。

1. **SOLID 是首要规定。** 代理库适配、运行编排、路由决策、有限记录与界面投影按变化原因拆分；不得把 Titanium 会话对象、证书处理或网络回调塞进 Document。
2. **设计模式朴素使用。** 使用普通类、不可变记录、枚举、构造注入和真实替换边界上的窄接口。只使用必要的适配器与组合入口，不为每个类配接口，不引入消息总线、通用管线、规则框架或多层空转服务。
3. **新增与修改的关键代码使用详细中文注释。** 说明设计原因、输入输出、取消、并发、内存所有权、失败和释放语义；测试与脚本也说明所防止的错误。示例见技术设计第 8 节。
4. **单元测试与本地开发门禁齐全。** 状态、错误、取消、并发、资源、协议、记录完整性均有断言；门禁本身有失败注入，不能仅看退出码或测试数量。
5. **同步文档并新增专项文档。** 本计划负责做什么与顺序，技术设计负责怎么做，验证矩阵负责如何证明；实施后再写当前行为、快速开始和带日期证据。
6. **不使用 AIFLOW，不新增或运行 Windows CI、发布门禁。** 允许 Windows 本机 Debug 开发检查；本阶段不运行 Release Smoke、签名、封版、发布覆盖率、重复性发布检查、ZIP 发布或自动部署。原发布规则留待正式发布时使用。

## 5. 逐项执行步骤

### V2-01：先固定依赖与接入边界

1. 记录工作区基线、SDK/运行时、系统与架构；核对 Host 使用的公开 SDK 和共享程序集版本。
2. 按第 3 节审查候选；在 `Directory.Packages.props` 增加精确版本，在 Plugin 增加 `PackageReference` 与 `ManagedPluginPrivatePackage`。BouncyCastle、Abstractions 是否需单独声明按 Build 3.4.1 实际私有依赖闭包处理；禁止把 Host 共享的 `Microsoft.Extensions.*` 复制进插件绕过冲突。
3. 正常 restore 更新三个项目受影响的 lock，审查变更后执行 locked restore 与 Debug 零警告构建。无须发布包；通过构建输出/解析资产核对私有和共享边界。
4. 查阅安装的公开 SDK 文档，确认插件共享服务寿命、Document Scope、Tool、关闭与同步/异步释放入口。缺少可等待退出机制时记录 SDK 缺口和方案，不能借用 Host 内部类。
5. 输出依赖与 API 核对表、第三方声明草稿以及最小 API 编译验证。实际许可未核对、共享程序集冲突未解决时，不进入“依赖已锁定”状态。

### V2-02：先定义可测试的寿命和状态

1. 按技术设计建立 `ProxyOptions`、`ProxyStatus`、`ProxyFailure`、`RequestObservation`、`RouteDecision`、`BodyCaptureSummary` 等最小记录，保留原始/有效目标与流量来源。
2. 定义 `IProxyRuntime` 及其真实/替身共同契约；协调器持有唯一运行实例，不使用静态单例。
3. 明确 Stopped、Starting、Running、Stopping、Faulted、Disposed 转换。停止开始即失效旧代次，迟到回调只能归属原代次，不能复活状态。
4. 以可控 Task/屏障编写起停竞争、启动失败回滚、重复停止、取消和释放测试；禁止用固定长 Sleep 猜时序。
5. 先交付状态和契约测试，再接入真实库；编排层不通过反射探测 Titanium。

### V2-03：建立不依赖外网的验证环境

1. 在现有测试项目建立 `Fixtures/ControlledOrigin`、`TestCertificateAuthority`、`ProxyFixture` 与生成式内容夹具。普通端点可用 Kestrel；相关框架引用只在 Tests，不进入 Plugin。
2. A/B 端点分别记录请求身份、方法、原始路径/Query、多值头、请求体哈希、协议、TLS 信息和开始/完成时间；返回可区分标识。日志写入本轮独立目录。
3. 使用 `source-a.test`、`target-b.test` 等合成名称，由测试作用域内的名称解析/连接映射指向回环地址。先核对候选库是否公开支持；不得修改机器 hosts 或使用公网 DNS 凑通过。
4. 建立两个信任方向：测试客户端验证代理签发的源站证书，代理验证 A/B 的目标证书。仅在本测试进程配置专用根信任，继续验证名称、有效期和链；拒绝无条件返回 true 的校验回调。
5. 自动测试不安装系统根、不改系统代理；端口、证书、临时文件均属于本轮夹具。端口由实际监听取得，若库不支持动态端口，使用有上限的绑定重试，避免先找空闲端口再假定永不竞争。
6. 为 V2-06 增加唯一的开发控制台宿主 `tools/NetWorkTrafficPlugin.TechnicalProbe` 并纳入解决方案。它引用 Plugin、复用同一注册入口，仅启动/停止生产代理并输出结构化测量；A/B 和客户端留在测试进程。这样能单独测代理资源，不复制代理逻辑，也不把夹具或工具随插件交付。新增项目一并生成和审查 lock。

### V2-04：跑通实际代理，随后核定协议范围

1. 在 `TitaniumProxyRuntime` 配置回环显式代理；明确禁用自动系统代理设置、自动信任、自动发现上游代理和不必要的流量日志，实际开关以固定版本核对为准。
2. 执行 HTTP GET/POST、HTTPS CONNECT 后解密转发，验证 A/B 日志、请求体和响应体；只建立隧道且看不到 HTTP 内容不能算 HTTPS 抓包通过。
3. 覆盖端口冲突、上游连接拒绝、延迟、取消、无效证书、回调异常和重复起停。未接纳、取消、上游失败与记录失败分别表达，不自动重放 POST。
4. HTTP/1.1 是强制通过基线。HTTP/2 分别记录客户端请求版本、客户端↔代理的 CONNECT 内协议、代理↔端点协议，验证同连接并发与单流取消。
5. 若 exact HTTP/2 失败，保留失败证据，测试允许协商时的降级行为及界面提示，固定首版限制；不能把降级后的 1.1 响应记作 h2 成功，也不能直接跳过协议调查。

### V2-05：验证内容在响应结束前可见

1. 使用延迟分块 SSE、跨块 UTF-8、跨块事件分隔符、心跳、未知长度与中途断开；夹具先发第一段并等待客户端确认，再发余下数据，证明没有等完整 Body。
2. 选用固定版本支持的增量钩子，不在热路径调用全量 Body 字符串/数组 API。回调中不等待 UI 或磁盘，不保存超出回调寿命的池化内存。
3. 转发和有限记录分开：转发完整数据；记录只保留有界前缀/摘要。记录额度耗尽时标记部分，不截断真实响应。
4. 测量客户端首字节/首事件、插件首条增量记录与端点发出时序。缓冲模式与记录模式各自留证，避免观察器本身改变链路却未发现。
5. 验证取消后两端结束、已接收数据保留部分状态、旧回调不写入新运行；长流不因普通短请求总超时被统一杀死，改用场景截止和空闲预算。

### V2-06：验证大资源与有界记录

1. 生成 128 MiB、1 GiB 二进制，客户端流式计算长度和 SHA-256；分别测有 Content-Length、未知长度、短读与中断。禁止服务端或断言一次构造完整大数组。
2. 观测无记录/仅元信息/有界记录三种模式，比较直连与代理的吞吐、内存、队列、文件和句柄；生成器与客户端不得混入代理资源结论。
3. 对慢记录器、磁盘满/权限失败、单体和总配额注入故障；转发继续或按已声明的运行故障结束，不能把记录失败伪装为完整，也不能无限排队。
4. 冻结本轮测量预算、环境和判定方法后执行。测试限额见技术设计第 7 节；属于探针保护条件，不提前承诺 M1 产品性能。
5. 输出曲线与峰值、实际转发/观察/保存字节、停止耗时和残留；若库自身缓存随完整响应线性增长，M0 阻塞，不能只给插件侧加限额就宣称解决。

### V2-07：验证真正到达目标的域名改写

1. 用纯函数 `RouteTargetResolver` 根据精确源域名及合成条件头产生不可变决策；默认保持路径、编码 Query、方法和 Body。探针条件不是 DSL 产品模型。
2. 对单次请求保存原始地址、有效地址和映射版本，只执行一次决策；不得改共享连接/全局目标使并发请求互相污染。
3. 在适配器中一致应用连接目标、端口、HTTP Host/HTTP/2 authority、上游 SNI 和证书校验名称。客户端仍以原始源域名验证代理证书。
4. A/B 端点日志、B 证书身份与 SNI 共同证明转向，客户端显示 URL 不能替代证据；未命中、跨连接和同连接交错请求必须仍到 A。
5. B 拒绝/超时/证书错误时不回退 A；拒绝映射到代理自身形成循环。包含一次 POST，证明副作用端点未被重试。
6. 对映射后的 SSE/大文件和实际支持的 h2 路径重跑关键断言；不在 M0 做规则编辑器、任意字段修改或真实公司环境映射。

### V2-08：固化生命周期与最小开发入口

1. Plugin 内提供最小诊断 Document：手动启动/停止、监听地址、运行状态、错误、累计字节、记录截断、最近一次受控探针摘要；无自动启动。
2. 以公开 SDK 注册轻量代理状态 Tool，共享运行状态并可显式停止；工具关闭不释放代理。关闭最后 Document 仍继续捕获，重新打开 Tool/Document 能读到同一事实。
3. Document/Tool 只拥有订阅、局部命令与显示状态；关闭页面取消该页面等待，不把页面 CancellationToken 当作插件运行令牌。
4. Standalone 使用相同服务注册与生产 View；退出先停止新请求，再取消在途、等待有界收口、退订回调和释放资源。同步容器释放也必须有经过验证的路径，不能只实现 Host 从不调用的异步释放。
5. Host 联调仅使用用户已指定的开发环境并按公开 SDK 接入；自动门禁不复制插件到 Controls。未开展真实 Host 观察时标记未验证，不能凭 Standalone 代替。

### V2-09：开发门禁随实现同步建立

1. 建立计划中的 `tools/verify-development.ps1`、`DevelopmentChecks.ps1`、`test-development-gate.ps1` 和 `m0-test-map.json`。脚本仅编排标准命令与报告校验，不复制网易云业务检查器。
2. 模板回归、V2 单测、本地协议集成、故障注入全部运行；资源探针以独立测试进程顺序执行，避免夹具资源污染测量。
3. 明确文档检查与完整 M0 两种入口；文档入口不能生成 M0 通过结论。早期未覆盖项使完整 M0 检查失败，禁止删必测清单凑通过。
4. 每轮生成唯一 runId、源码摘要、TRX、场景映射和探针证据；验证零发现、跳过、旧报告、缺场景、超时、损坏 JSON/XML 等均失败。
5. 具体命令设计、超时、证据字段和失败自测以专用验证文档为准。不加入 Windows CI 或发布步骤。

### V2-10：形成可供 M1 使用的结论

1. 审查 SOLID、中文注释、依赖方向、取消与缓冲区所有权；检查替身契约与真实适配器结果一致。
2. 完成普通 HTTPS、持续流、大文件、A/B 目标切换演示。记录代码、自动测试、受控端点、真实客户端、Host、人工验收各自结果。
3. 明确 Titanium 最终版本、HTTP/2 两侧覆盖、证书/系统代理模式、内存与磁盘观测、关闭行为、M1 可复用文件及需要重做的探针夹具。
4. 更新产品方案待决项、路线图 M0 状态、两级 README、专用矩阵；新增当前行为和快速开始，以及当日技术结论记录。没有实际证据的项目保持未验证。
