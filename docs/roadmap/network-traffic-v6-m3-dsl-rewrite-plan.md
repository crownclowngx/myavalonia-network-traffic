## 1. 目标与首要规定

目标流程：**编写规则 → 验证与只读预览 → 保存不可变修订 → 显式启用 → 客户端发起请求 → 按原始输入决策 → 一次提交有效请求 → 查看命中、差异和端点结果 → 停用或切换修订**。

1. **SOLID 是首要规定。** 每项实现都要说明 S/O/L/I/D 的职责、替换契约和依赖方向；不以类数、接口数或“采用 MVVM”代替审查。
2. **设计模式朴素使用。** 普通不可变数据、纯决策函数、构造注入、窄 I/O 适配器、单一共享运行协调和页面 MVVM 即可。不引入通用规则平台、脚本宿主、动态动作插件、消息总线、CQRS 或通用仓储。
3. **注释使用详细中文，说明设计思路。** 重点说明发送边界、原始/有效事实、失败为何阻断、优先级与冲突、字节编码、预算、快照接纳点、取消与所有权。测试、夹具和 PowerShell 检查器同样要求；不写逐行翻译式注释。
4. **单元测试与本地开发门禁齐全。** 正常、边界、错误、并发、寿命、协议、存档、生产 UI 和资源分别证明；门禁本身要有正例和拒绝反例，不能以测试数量替代业务覆盖。
5. **同步总览，新增专用文档。** 本计划管顺序，专项设计管契约，验证矩阵管证据；实现时同步当前说明、快速开始、DSL 手册、样例和带实际日期的实施记录。
6. **不使用 AIFLOW。** 不初始化、不读取其上下文、不生成任务文件，不将其流程作为任何前置。
7. **只做本地 Debug 开发验证。** 不新增或触发 Windows CI，不运行 Release、发布覆盖率、ZIP、签名、上传或发布部署门禁。Windows 本机运行测试属于允许的开发验证；正式发布时再单独使用发布门禁。

优先次序：SOLID 与改写正确性 → 发送前边界及资源有界 → 可追查结果 → 完整操作流程 → 编辑便利性。

## 5. 逐项执行要求

### V6-01：冻结可核对的设计输入

1. 记录当前源码身份、M0～M2 自动与人工状态；保持 SDK/Titanium/Avalonia、插件身份和包版本不变。
2. 以专项设计的固定 A/B/C 端点样例建立独立期望表；覆盖不匹配、全域名、字段定向、冲突、Unknown、正文修改和失败。期望不调用被测引擎生成。
3. 固定语言文法、诊断码、预算、72 场景和产物约定；创建门禁骨架时缺实现必须失败，不预填 passed。
4. 建立 V6-01～16 实施清单，每项记录代码位置、测试 ID、结果及偏差，不能只逐项打勾。

### V6-02：先验证发送前能力

本项先用固定候选和真实生产适配器验证最小机制，不等待完整 DSL/UI。表中 P/B 场景此时只取得前置证据，V6-09 之后仍须通过真实 DSL 规则链重新执行；探针成功不能提前勾选 M3 场景完成。

1. 用生产 Titanium 适配器和受控端点确认：头已到达但 Body 尚未完整时，上游收到的请求头/正文均为零；包括 `Expect: 100-continue` 和 chunked。
2. 确认公开 API 能在长度、时间和内存限额内读取/替换请求体，超限或取消不会先完整缓冲。当前 `MaxBufferedBodyBytes` 为 64 KiB，需查清其覆盖的第三方缓冲路径，再验证计划中的 256 KiB 有界读取；不能只增大该值或因 API 名称包含 Async 就认定有界。
3. 验证 UTF-8 替换、Content-Length、Host/SNI、h1 回退、exact h2 拒绝及默认零重试。记录固定依赖的真实限制。
4. 若现版本没有满足该契约的公开路径，登记具体缺口，先完成不依赖它的语言/纯规划/文档工作；M3 保持未完成。不能用无限读取、先发后改、删掉 Body 场景或未经依据升级依赖来凑完成。

### V6-03：按 SOLID 局部拆分

1. 在 Application/Dsl 提取表达式编译上下文和预算，保留 `DslCompiler.Compile` 的 v1 行为和所有诊断回归；改写入口独立返回 RewriteProgram。
2. 在 Application/Rewrite 定义不可变原始输入、候选计划、动作、轨迹、修订与发送状态。纯函数不访问 Titanium/Avalonia/文件/DI 容器。
3. IFieldSource 继续表达只读字段；发送前 I/O、存储、目标地址检查才设窄接口。普通动作按枚举/类型分支处理，无需每个动作创建工厂和接口。
4. 明确真实、Fake、历史预览替换契约：不能用空 Body 代表未知，不能把取消转换为成功；网络发送端口不交给预览模型。

### V6-04：编译器与诊断

1. 实现专项设计的 `dsl 2;`、独立 rewrite 块、精确 host 作用域、唯一 priority、when、route/set/remove；不支持的语法明确拒绝。
2. 共用 M2 表达式与字段语义，禁止响应字段、时间窗口、group/timeline、effective 引用和任意执行函数进入发送前程序。
3. 静态检查重复名称/优先级、保护头、非法 URI/路径、动作值类型、字段依赖环和单规则写冲突；跨规则实际共命中冲突留给规划器。
4. 保留 UTF-16 错误跨度、稳定诊断码和中文建议；未通过编译的草稿不替换当前修订。

### V6-05：原始输入与 Body 所有权

1. 接纳时先固定共享启用代次/修订，再复制原始 method/URI/有序多值头；读取成本和上限必须在分配前检查。
2. 先用精确 host 和短路条件排除无关规则，确需读取 Body 才取得并发槽和共享内存预留；纯头规则对大上传不做整包读取。
3. 完整、受限、identity 编码的 JSON/urlencoded 表单才用于发送前 Body 提取；partial、未知编码和超限均保留原因并阻断该请求。
4. 原始正文与替换正文分别标识；网络观察回调不能将有效正文重新计作原始正文。所有租约在成功、拒绝、取消和 Stop 中归还。

### V6-06：决策、冲突和失败原子性

1. 全部字段、条件与动作表达式读取原始输入；优先级数值小者先执行，首个 True 路由胜出，后续 route 标记被遮蔽。
2. False 不执行；作用域内 Unknown 或动作值非确定状态导致 block。明确作用域外请求仍正常转发。
3. 收集命中动作并检查写集合：同一字段多写、set/remove 竞争、JSON 父子路径竞争都拒绝整次计划，不能发送部分修改。
4. 计划成功后才产生有效候选；纯预览调用同一规划器，但没有网络副作用。失败显示具体规则/动作/字段来源。

### V6-07：URI、Query 和 Header

1. 路由保留未修改的原始转义路径/Query；路径设置只替换路径，不接受 scheme/authority/query/fragment。
2. Query 按有序多值项处理，指定键 set 替换全部旧值，remove 删除全部；未操作项保留原字节拼写和顺序，不能整串解码重编码。
3. Header 名不区分大小写，set 替换全部同名行、remove 删除全部；未触及行保留多值顺序，拒绝 CR/LF/NUL 和协议控制头。
4. Host/authority/SNI、长度和传输 framing 仅由适配器按候选重建；业务 Cookie、Authorization、Origin/Referer 默认保留，规则可显式修改普通业务头，不自动猜测环境身份。

### V6-08：JSON 动作

1. 仅支持 UTF-8、identity 编码、完整且预算内 JSON；输入/输出、深度/token/路径长度都有限额，重复属性拒绝歧义。
2. set 接受确定的字符串/数字/布尔/null，目标父节点必须存在；固定数组下标只能替换已有项；remove 仅删除对象属性，不移动数组下标。
3. 在独立候选树上修改，统一序列化为 UTF-8，再校验输出限额并生成摘要。候选失败销毁，不覆盖原字节。
4. Body 改变后移除失效的标准实体摘要，重算长度；任意业务签名不自动修复。字节未改则不重排 JSON、不改变空白与数字文本。

### V6-09：一次发送与故障结果

1. 适配器校验候选目标、代理回环、协议模式、取消和运行代次后一次性写回；提交失败只结束当前请求，不能回原始目标。
2. 不持全局锁 await Body/DNS/网络；共享状态锁不承担第三方回调执行，避免停止等待与 UI 互相阻塞。
3. 保持 NetworkFailureRetryAttempts=0；超时或断开若可能已发出，记“发送结果未知”，不自动重试 POST，也不把原始环境当备用目标。
4. 本地拒绝使用结构化原因和客户端可读响应；即使 BeforeRequest 拒绝也创建可追查记录，绝不只增加 rejected 计数后丢失原因。

### V6-10：修订、启用与共享生命周期

1. 独立改写库保存不可变文本/摘要/父修订及命名配置；比较库 generation 原子提交，失败保留旧文件和生效修订。
2. 保存、预览与启用分别操作。保存成功不自动生效；启用已保存修订时比较期望启用代次，多页冲突显式反馈。
3. 代理启动前选择“普通捕获”或“改写（HTTP/1.1）”；普通运行不能直接启用改写，提示先停止再切模式启动，不自动断开用户流量。
4. 改写模式中切修订/停用只影响新接纳请求，在途请求固定旧快照。关闭编辑页不停止共享改写；Stop/插件退出取消运行任务并有界释放。
5. 重启仅恢复库和编辑选择，默认不启用改写、不启动代理；损坏/未知版本/缺修订明确报错，不用空库覆盖原文件。

### V6-11：事实记录、存档与分析回归

1. 记录原始输入、有效计划、实际提交/发送状态、规则 hash/启用代次、逐规则结论、字段差异及错误阶段；列表只存短摘要。
2. 完整原始/有效 Body 的持久化仍服从捕获策略和共享磁盘配额；相同字节可共享不可变正文身份，不复制大文件。没有保存的字节不可导出为完整请求。
3. 原生存档 v2 覆盖新增引用、文件清单、摘要、大小、路径安全、冻结水位和中断恢复；v1 可打开，缺原始/有效事实明确 LegacyUnknown。
4. M2 对新记录继续使用 original；旧记录沿用 v1 可证实事实和限制。不得因 M3 把 RequestHeaders 语义静默换成 effective 后改变旧分组结果。

### V6-12：可操作且可解释的 UI

1. 现有 Document 内增加改写工作区，提供验证、样本预览、保存、启用/停用、修订选择和错误定位；文本是权威输入，基础表单不反向破坏复杂规则。
2. 全局状态明确显示模式、启用修订、影响新请求和 h1 边界；停止入口始终可达。草稿状态和运行状态分开显示。
3. 请求详情提供原始/有效/差异/轨迹，区分“计划目标”“已提交”“端点未知”；失败记录可定位规则和动作。
4. 预览最多 20 条样本，读取冻结原始快照；历史缺 Body 不发网补齐。新编辑、换源、关页取消旧预览，迟到结果不得覆盖新草稿。
