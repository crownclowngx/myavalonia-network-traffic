## 1. 目标与首要规定

交付一条可日常使用的流程：**手动启动代理 → 配置客户端 → 查看实时请求 → 查看请求/响应详情 → 查看流式与大资源 → 筛选 → 保存捕获 → 重新打开**。普通文本、JSON、图片、文件和 SSE 混合出现时，仍可选择记录、滚动和停止代理。

实施优先级：**SOLID 与行为正确性 → 资源所有权和可测试性 → 抓包闭环 → 交互完整性**。

1. **SOLID 是首要规定。** 网络适配、捕获归档、内容解析和页面投影分别承担职责；以技术设计中的 S/O/L/I/D 审查项逐项验收，不能只在文档中声明遵守。
2. **设计模式朴素使用。** 沿用 MVVM、构造注入、不可变快照、窄 I/O 接口及枚举状态。必要时使用适配器；不引入通用消息总线、CQRS、插件式查看器框架、通用仓储或状态机框架，不为普通纯函数创建空转接口。
3. **关键代码、测试和脚本使用详细中文注释。** 解释设计思路、输入输出、预算、取消、并发、缓冲区所有权、失败及释放原因；不能只把代码翻译成中文。注释样例见技术设计第 11 节。
4. **单元测试与开发门禁随功能同步。** 正常、失败、边界、取消、迟到、并发、资源和完整性均要有实际断言；生产 UI、受控协议及门禁自测分别取证。
5. **同步文档并增加专用文档。** 执行计划说明顺序，技术设计说明契约，专用矩阵说明证明方式；实现后再补当前使用说明和带日期实施记录，不预填成功结果。
6. **不使用 AIFLOW。** 不创建、读取或运行其上下文流程作为本次执行前置。
7. **不新增或触发 Windows CI，不运行发布门禁。** 允许 Windows 本机 Debug 开发构建、单测、受控协议和 UI 检查。Release Smoke、发布覆盖率、签名、打包发布、上传、自动部署、干净安装发布验证留到正式发布；真实 Host 的本地功能验证单独登记。

附带路线图及参考项目中的步骤是背景材料，不自动扩展本次授权。只参考网易云的文档组织、职责划分、测试映射与失败注入，不继承音乐业务、账号、发布操作或已验收结论。

## 3. M1 范围与产品决定

| 范围 | 本次要实现的行为 |
| --- | --- |
| 代理接入 | 回环显式代理；手动启动；默认端口继续为 0，展示实际地址；可输入固定端口；不自动修改系统代理或信任库 |
| HTTPS | 沿用每运行内存 CA；展示公开 PEM、指纹、有效期、当前运行身份及客户端接入说明；重启后提示重新配置信任；信任未知不能显示已信任 |
| 列表 | 序号、开始时间、方法、域名、路径、状态码、耗时、观察/保存字节、来源、传输与记录状态；未知值显示未知 |
| 详情 | 概览、Query、请求/响应 Header、Cookie、请求/响应文本与 JSON、流事件、资源元信息；重复字段、原始编码及缺口可查 |
| 基础筛选 | 方法集合、域名/路径关键字、状态码或状态类、来源、进行中/失败、起始时间区间；各类条件 AND，同类多选 OR；不加入 DSL/正则 |
| 流式 | SSE 和 UTF-8 NDJSON；增量显示、半事件/半行、结束/失败、事件淘汰数；暂停/继续跟随仅改变页面滚动 |
| 大资源 | 有界预览、PNG/JPEG 缩略图、文件/视频类型及长度、进度、有限记录或受配额落盘；206 按单次响应记录，不拼接视频 |
| 记录策略 | 仅元信息、有限内容、受配额落盘；默认有限内容；启动时冻结策略，本阶段只做全局策略，按域名/接口配置留后续 |
| 保存回看 | 原生目录格式，保存点击时的记录快照与已经成功写入的正文前缀；重开为只读，保留缺口；导出已有 Body 不补下载 |
| UI / Host | 一个共享捕获源，Document 独立筛选/选择；Tool 显示状态和启停；两主题、三尺寸；最后页面关闭继续捕获，应用退出停止 |

显示名称在 V3 采用“HTTP 工作台”；工程、程序集、PluginId、DocumentId、ToolId 和原示例命令身份保持稳定。关闭/停止文案必须能区分“关闭页面”和“停止代理”。

本次不实现：系统代理切换、持久根证书安装向导、DSL、业务分组、产品化环境映射、请求编辑/重发、HAR/curl 导入、WebSocket/gRPC 专用解析、HTTP/3、视频播放/拼接、自动恢复网络任务、跨插件 Workflow。M0 受控映射继续回归，但不做成 M1 规则编辑界面。

## 5. 逐项执行要求

### V3-01：固定真实基线和最小可行捕获入口

1. 记录实际工作区、SDK、依赖 lock、目标系统、公开 SDK 生命周期；读取 M0 的待验清单，保留所有未验项。
2. 从已安装 Titanium 7.0.13 的公开 API/对应源码核对请求 Body 增量入口、响应 Body 的压缩/解码层、Header/Trailer 访问及终态回调顺序。用短程序编译和受控请求证明，不把建议 API 名当真实签名。
3. 覆盖 POST 上传、chunked/未知长度、gzip/br、HEAD/204/304、100-continue、取消、普通 h2。记录“所见字节处于什么层”及相应长度含义。
4. 请求体若只能全量读取，先停止 V3-05 产品实现，记录限制并选择公开可用的增量方案；禁止用读取完整上传正文凑出详情。单项技术失败不阻止契约、其他纯逻辑测试和文档继续完善。
5. 首批人工验收至少选择一个可配置显式代理和测试根信任的真实程序，以及一个用户实际使用的客户端；在执行人工项前记录名称/版本/配置。未获得实际环境时标未执行。

### V3-02：先确定模型、状态和所有权

1. 按技术设计定义 CaptureSession、TrafficRecord、Request/ResponseSnapshot、BodyDescriptor、ContentViewState、CaptureFailure 和 CaptureQuery；新增类型以用途命名，不照搬一个巨型业务对象。
2. 对请求/响应分别记录传输状态、保存状态、字节表示、长度与缺口原因；只读历史不能携带可执行网络句柄。
3. 固化运行 Generation、SessionId、RecordId、Sequence、Revision；页面另持 QueryRevision/SelectionRevision，防止旧详情覆盖新选择。
4. 明确原始与有效请求分离、重复字段顺序、来源标记和可选 OriginRecordId。M1 来源只有真实代理 Captured；读取历史使用视图模式，不把原来源改成主动请求。
5. 先用纯单测覆盖状态组合、非法转换、未知值及长度口径，再接第三方和 UI。

### V3-03：扩展受控端点和测试数据

1. 复用 ControlledOrigin、ProxyFixture、ProbeProcess、TransferDigest 等夹具；只在 Tests 引入所需 Web/Headless 依赖，不把端点或测试证书带入 Plugin。
2. 增加 Query/重复 Header/多个 Set-Cookie、JSON/文本上传、乱码、压缩、小图、超像素图、NDJSON、206 和失败端点。大内容继续生成式输出，客户端增量哈希。
3. 用 TaskCompletionSource/屏障控制首块、下一块、结束和取消；纯逻辑使用可控时间，不用长 Sleep 制造恰好通过。
4. 所有临时目录、进程、端口和证书有唯一所有者；资源测试留在独立进程，证据引用真实客户端/端点回执。

### V3-04：代理控制可理解且可恢复

1. Document 与 Tool 调用同一个 ProxySessionCoordinator。界面根据状态启用命令，应用层仍执行相同校验，避免禁用按钮成为唯一保护。
2. 显示实际监听地址、当前配置、HTTP 协议范围、活动/拒绝数、公开 CA 信息；提供复制地址/PEM及明确的客户端说明。
3. 将错误区分为阶段与类别：配置、监听、客户端 TLS、上游连接/TLS、空闲、记录和存储。无法观察客户端信任时显示未知，不把 CA 生成成功等同客户端信任成功。
4. 运行中修改端口/策略只形成待应用配置，提示停止后重新启动；不悄悄切换当前会话。默认不自动启动，不安装证书、不修改系统代理。
5. 启动失败回滚监听/目录/记录器；停止取消当前在途但保留部分记录；超时显示 Faulted，实际未释放前禁止重新启动。

### V3-05：双向捕获与有限内存数据路径

1. 在适配器按请求开始、头到达、正文块、终态四类边界交给捕获层；复制借用数据后离开库回调，不持有 SessionEventArgs 到历史记录。
2. RequestBody 和 ResponseBody 有各自描述符，共用全局字节/块/磁盘预算，预算按预留、成功写入、释放区分，不能两个方向各自占用一份“全局 4 MiB”。
3. 正文文件保存连续前缀；首次丢块即停止该方向记录，记录缺口位置/原因，真实转发继续。预览另有有界通道，磁盘变慢不阻塞预览和网络。
4. 请求开始立即出现 Receiving 行；状态和计数更新可合并，正文块不可跳过后假装连续；终态必须可从权威快照补齐。
5. 实现一万条摘要/20 条活动上限、已淘汰计数与有限元信息存储；预算不足时显示记录缺口，不能因抓包记录不足主动重发业务请求。

### V3-06：列表、查询与导航

1. 在 Features/Capture 建立列表与详情模型，MainDocument 只承载页面；共享存储提供摘要和按 ID 详情，Tool 不加载正文。
2. 使用有界视口的 Avalonia 虚拟列表；行模板不做 JSON 解析、磁盘读取或图片解码。选中使用 RecordId，排序采用开始时间再 Sequence，默认最新请求在前。
3. 筛选只作用于已有记录；字符串采用明确的 OrdinalIgnoreCase，时间区间为 `[开始, 结束)`，状态码未知不会落入 2xx。不发网络、不删除底层内容。
4. 输入消抖 200 ms；后台查询使用 Revision 和取消；每页刷新单次投递、批量应用，游标过期时重新取有限快照。
5. 提供清除筛选与“清空当前视图”；后者记录页面游标，不删除文件/停止代理。删除记录使用独立入口且只能删除插件拥有且未被读取/保存的记录。

### V3-07：普通详情与内容完整性

1. 按技术设计解析重复 Query、Header、Cookie；原始行和解析结果可切换，Set-Cookie 不能按逗号拆分；敏感值默认遮罩，显式展开只影响本页。
2. 原始/有效请求分栏，M1 未改写时内容一致也保持模型区分；响应没有到达时显示等待/失败，不伪造状态码 0。
3. 文本增量解码，明确 charset、BOM、未知编码及替换字符；gzip/br 只解码一次，解码量与比例受限，错误不改变已保存字节及真实转发。
4. 完整且在预算内的 JSON 才进入结构树；部分/无效 JSON 显示有限原文和原因，不补括号、不把缺内容当空对象。JSON 深度/节点和格式化输出均受限。
5. 异步详情、解析与复制都绑定选择代次；页面关闭或选中改变后的迟到结果不显示。复制默认使用遮罩投影，显式复制原值才输出原值。

### V3-08：流式查看

1. 将 SSE 基础组件接入实际响应预览路径，补 BOM、CR/LF/CRLF、event/id/retry、心跳、多 data、空 data、未知字段和 EOF；工作台只观察，不执行自动重连。
2. NDJSON 限定 `application/x-ndjson` / `application/ndjson` 的 UTF-8 逐行对象；每行解析独立，错误行保留原因。普通 JSON 数组不冒充逐行流。
3. 每流事件数与字节双限额；显示累计收到、保留、淘汰和解析缺口。大事件不得截成一个看似有效的事件。
4. 暂停跟随保留滚动锚点但继续捕获、解析和有限缓存；继续跟随跳至最新。暂停期间旧事件被淘汰时明确提示范围，不能暗示所有历史仍在内存。
5. 同时显示接收/结束/失败与预览截断/记录完整性；半事件单列未完成片段，不计入完整事件。两侧时序证明首事件在响应结束前可见。

### V3-09：大资源与预算

1. 实现默认有限内容与显式受配额落盘；配额在接收前预留，达到单体/会话/根目录上限即停止相应记录。落盘写失败不能关闭真实响应或变成完整记录。
2. 预览只读取有界内容；PNG/JPEG 先检查尺寸/像素，再受限解码和缩放；部分图片不强行解码。解码任务并发及队列有限，切换选择后释放位图。
3. 文件/视频显示 MIME、Content-Disposition 建议名、接收/保存量、总量和内容范围；未知总量不显示百分比。文件名只作展示，真实存储由内部 ID 决定。
4. 全局记录目录只管理带所有权标记的会话；清理不跟随重解析点，不触碰外部导出目录；删除失败保持实际占用计数并给出诊断。
5. 按专用矩阵测 128 MiB/1 GiB、未知长度、20 路混合及十分钟流；正文、预览、图像、索引、页缓存同时计费，不能只给每个组件单独上限。

### V3-10：保存、回看与异常恢复

1. 使用版本化 manifest、有限元信息索引和 ID 命名 Body 文件，原生格式选择目录而非新压缩容器；详见技术设计第 8 节。
2. 保存先冻结元信息 Revision 与已成功写入长度，租约保护源文件；仅复制这些字节到目标旁临时目录，文件 flush/校验后最后提交 manifest 并原子改名。
3. 保存期间不等待长流结束；Receiving 保留当时状态，重开用“保存时仍在接收，现为只读快照”说明。存档任务取消/磁盘满时保留旧目标，清理自身临时产物。
4. 加载严格校验 schema、文件数/体积、相对路径、重解析点、重复 ID、长度和摘要；缺文件/截断条目按记录降级，不把全体失败吞为成功。
5. 异常退出恢复只检查用户选择或已登记的本插件会话，标记 Interrupted；不恢复监听、不重发、不补下载、不恢复未完成保存任务。
6. 导出明确是“已保存正文”，部分则提示前缀和长度；导出完成只证明这些字节被复制成功，不修改原记录的完整性。

### V3-11：生命周期与竞争收口

1. 多 Document/Tool 共享协调器和捕获存储；每 Document 单独持有查询、选择、预览读取租约、UI 调度及页面取消源。
2. 最后页面关闭继续捕获，关闭 Tool 不停止运行；页面重新打开读取现有会话，不创建第二监听器或重复正文观察器。
3. 先禁止新接纳，再取消网络/保存读取、收口队列与文件、发布终态，最后释放容器。全过程用同一个退出截止，避免多个“十秒”叠加。
4. 用屏障覆盖 Start/Stop、重复 Dispose、停止中保存、删除中读取、旧代次回调、新页面快速打开与旧 UI 投递等竞争；不得在状态锁内等待外部 I/O/UI。
5. 退出超时保留故障和所有权信息，不伪造清理成功；用端口重绑、文件独占打开和独立进程退出证据证明正常路径释放。
