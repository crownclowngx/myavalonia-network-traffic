## 1. 分期原则与总览

先验证代理链路和资源处理，再交付可用抓包；接着完成 DSL 分组与改写，最后串起编辑重发。接口文档增强安排在核心调试流程之后。流式、大资源和生命周期从前期进入验证，M6 不承担“最后才补性能”的角色。

M 表示用户可使用的能力阶段，V 表示方案序号，包版本与交付日期另行管理。下表是建议顺序，不是时间承诺；M0 完成后再估算工期和拆分任务。

| 阶段 | 用户价值/交付目标 | 依赖 | 规模判断 | 当前状态 |
| --- | --- | --- | --- | --- |
| M0 技术基线 | 确认代理、HTTPS、流式、大文件与域名改写可以走通 | 现有模板 | 中，存在选型风险 | 已实现；自动结果见 V2 实施记录，人工未验 |
| M1 可用抓包 | 查看真实流量，支持流式和大资源记录 | M0 | 大 | V3 已实现；人工待验；V4 UX 已接通实现，结果见 [V4 实施记录](../archive/2026-09-30-v4-m1-ux-implementation.md) |
| M2 DSL 分组 | 用自定义字段分析一段时间内的调用过程 | M1 | 大 | V5开发完成，236个测试/207项同轮场景通过；人工未验见 [V5 实施记录](../archive/2026-09-30-v5-m2-implementation.md) |
| M3 DSL 改写 | 可追踪地切换目标环境和修改请求 | M2，复用 M0 改写验证 | 中到大 | V6语言/纯规划/修订基础已实现，发送接入与完整门禁受V6-02能力缺口阻断 |
| M4 请求调试 | 手工发送、编辑重发、模板和结果对比 | M3 | 中到大 | V7无规则独立部分已实现；M3、完整场景、混合压力及人工验收仍待闭合 |
| M5 文档辅助 | 接入现有文档或手工说明，辅助理解和请求构造 | M4 | 中，取决于实际文档格式 | 未开始 |
| M6 稳定交付 | 完成累计回归、长时运行和真实 Host 交付验证 | 核心发布至少 M4；含文档的版本还依赖 M5 | 中 | 未开始 |

建议三个体验节点：M1 后形成基础抓包预览；M3 后形成可按业务分组并切环境的试用版；M4 后形成首个完整业务流程。M4 完成只表示核心能力可用，正式交付仍经过适用的 M6 验证。M5 可以在核心流程试用后再实施，不成为所有交付的固定阻塞。

## 2. M0：技术基线与风险验证

**目标：** 用受控端点验证本项目的真实代理链路，为后续设计选择提供证据。

执行入口为 [V2-01～V2-10](network-traffic-v2-m0-technical-baseline-plan.md)。本阶段以 SOLID 为首要规定，使用朴素设计和详细中文注释，同步单元测试与本地开发门禁；不使用 AIFLOW、Windows CI 或发布门禁。V2 已采用 Titanium 7.0.13、显式代理和进程内测试信任；普通 h2 已覆盖，目标映射限定 h1，当前范围见[运行说明](../reference/network-traffic-m0-runtime.md)。

| 工作项 | 范围与交付物 |
| --- | --- |
| M0-01 依赖与接入 | 核对 Titanium 版本、许可/私有依赖与 Host 兼容；锁定验证版本；只通过公开 SDK 接入 |
| M0-02 最小代理链路 | 本地 HTTP/HTTPS 端点、显式代理客户端、起停、取消、错误状态；记录 HTTP/1.1 及 HTTP/2 实际覆盖 |
| M0-03 流式与大文件探针 | 延迟分块 SSE、跨块字符、持续输出、大二进制、未知长度与中断；测量转发及记录行为 |
| M0-04 域名改写探针 | 受控源域名映射到另一个受控目标，检查路径/参数、Host/authority、TLS 目标身份及并发请求隔离 |
| M0-05 资源与寿命决策 | 明确单监听器所有权、关闭页面/退出 Host、证书与系统代理设置变更恢复策略、预算项目和测量方法 |

**可演示结果：** 一条普通 HTTPS、一条持续输出、一条大文件请求通过代理；指定请求实际到达目标 B，其他请求到达目标 A，端点记录能够证明目标选择。

**退出条件：** 固定依赖版本；测试端点和最小验证可重复执行；记录兼容范围、资源观测及仍有缺口的协议；HTTP/1.1 主流程、HTTPS 和流式验证通过。若 HTTP/2 存在缺口，需先明确受影响场景、客户端可见行为和首版范围，不能静默宣称完整兼容。

**本阶段不交付：** 完整抓包 UI、通用 DSL、正式环境映射配置、正式插件包。探针不写死公司域名或 `at` 作为产品模型。

## 3. M1：可日常使用的抓包与内容处理

**用户流程：** 启动代理 → 接入客户端 → 查看请求列表 → 打开普通/流式/资源响应 → 筛选 → 保存并重新打开记录。

执行入口为 [V3-01～V3-14](network-traffic-v3-m1-capture-plan.md)。首要满足 SOLID，朴素使用设计模式，关键代码、测试和脚本使用详细中文注释并说明设计思路；单元测试、生产 UI、资源和本地开发门禁同步落地。不使用 AIFLOW、Windows CI 或发布门禁，发布阶段另行启用发布验证。

V3 首版实现回环显式代理、每运行内存 CA、双向有限捕获、SSE/NDJSON、PNG/JPEG 受限预览及原生目录快照。系统代理管理、持久根证书安装、按域名记录策略及后续 DSL 不纳入本轮；详细边界与预算见 V3 技术设计，53 项业务场景与门禁失败注入见专用矩阵。`-Mode M1` 已接入本地开发入口，自动通过不代表人工或 Host 验收。

后续体验优化按 [V4-01～V4-12](network-traffic-v4-m1-ux-plan.md)执行：紧凑工具栏和双行列表、独立跟随与锚点、正文模式、分栏/窄屏导航、存档路径选择及状态反馈。V4 继承 M1 的传输/记录事实、共享寿命与资源预算，明确调整筛选和阅读语义；40 项新增业务场景及旧 M0/M1 同轮回归在 V4 矩阵定义。`-Mode UX` 已接通；真实 Host、客户端和人工体验另行登记。首要 SOLID、朴素模式、详细中文注释及本地开发门禁要求不变，不使用 AIFLOW、Windows CI 或发布门禁。

用户于 2026-09-29 确认无法通过正式发布依赖实现的能力可从产品层面降级：HTTP/2 自动单流空闲取消不纳入首版，只提示并保留接收中状态；客户端取消和全局停止仍验证。普通 h2 抓包保留，接入面板、当前说明与 P06 同步披露。

| 工作项 | 范围与交付物 |
| --- | --- |
| M1-01 代理控制 | 启停、端口、接入提示、HTTPS 信任诊断、清晰错误与运行状态；系统代理模式若采用，必须包含恢复 |
| M1-02 列表与详情 | 请求方法/域名/路径/状态/耗时/大小/来源；Query/Header/Cookie/文本/JSON 查看；基础筛选 |
| M1-03 流式查看 | SSE 与明确支持的逐行内容增量组装，接收中/结束/失败状态；暂停跟随与继续跟随 |
| M1-04 大资源 | 有限预览、受限缩略图、视频/文件元信息、进度和按策略落盘；记录上限和磁盘配额 |
| M1-05 保存与回看 | 捕获元信息及响应体索引持久化；重新打开后展示相同完整性；未完成传输不恢复为网络任务 |
| M1-06 UI/Host | 列表虚拟化、批量刷新、页面订阅释放、多页面共享捕获、两主题与主要尺寸验证 |

**验收：** 普通文本、JSON、图片、文件与 SSE 混合出现时可继续滚动、选择和停止代理；大文件传输不导致内存按完整体积增长；达到记录上限可见；暂停 UI 不中断接收；停止和退出有界完成；保存与重开不把部分记录标为完整。

**交付物：** 可运行抓包页、代理状态面板、内容查看器和捕获存储；当前使用说明；预算默认值与测量结果。

**本阶段不要求：** 复杂规则编辑器、业务分组、视频自动播放/拼接、离线补下载、自动恢复抓包。最小 HTTP 数据模型和来源标记应为 M2–M4 预留一致边界。

## 4. M2：DSL 字段、过滤、分组与时间线

**用户流程：** 定义业务字段 → 用样本预览 → 选择时间范围 → 分组 → 查看各组调用过程 → 保存视图 → 对历史记录重算。

详细执行入口为 [V5-01～V5-14](network-traffic-v5-m2-dsl-grouping-plan.md)。以 SOLID 为首要规定，朴素使用设计模式，关键实现、测试与脚本写详细中文注释和设计思路；单元测试、生产 UI、资源预算及本地开发门禁同步交付。不使用 AIFLOW、Windows CI 或发布门禁，发布阶段另行启用发布验证。

V5 首版固定 DSL v1、Query/Header/Cookie/JSON/urlencoded 表单/路径六位置提取、显式多值/回退、三值筛选、类型化组合键、半开时间窗口和保存视图。分析为只读冻结快照，显式刷新；历史重算不补发网络请求，缺口和未确定身份分别呈现。规则草稿、已应用修订及保存视图分离，语法或计算失败保留旧结果；正则、通用 JSONPath、响应提取和自动增量分析不纳入首版。

专用矩阵定义 64 项 V5 业务场景、4 项工程审查、12 组门禁自测及4项人工验收。`-Mode M2` 已在同轮继承 M0/M1/UX，固定检查207项场景；语法、完整性、窗口与预算的当前行为见 [M2 说明](../reference/network-traffic-m2-dsl.md)，实际结果与人工未验见 V5 实施记录。

| 工作项 | 范围与交付物 |
| --- | --- |
| M2-01 最小 DSL | 文法/版本、解析与语义诊断、基本类型与状态、有限函数、字段依赖和预算 |
| M2-02 字段提取 | Query/Header/Cookie/JSON/表单/路径，显式回退、组合字段及来源说明；处理重复键和解析失败 |
| M2-03 过滤分组 | 组合条件、单/多字段分组、未知值分类、统计覆盖范围、可显示的业务列 |
| M2-04 时间线 | 明确窗口边界、请求开始顺序、同刻稳定排序、并行重叠、流式与错误状态 |
| M2-05 规则体验 | 文本编辑、基础表单辅助、错误定位、样本结果、保存修订与 SavedView；语法失败不影响已生效规则 |

**验收：** 同一批请求通过不同 DSL 得到可核对的两种分组；至少覆盖四个提取位置、两个不同业务字段和一个组合键，证明产品不依赖 `at`。窗口边界、凭据变化、缺失/未知、并发、重复业务请求和来源排除均有明确结果。

**交付物：** 最小语言规范、有效/无效样例集、查询与分组引擎、时间线视图、保存视图、规则修订和诊断界面。

**本阶段不要求：** 任意代码执行、请求副作用、跨请求自动业务编排、把时间先后自动推断为因果链。

## 5. M3：DSL 请求改写与环境映射

具体顺序见 [V6-01～16 执行计划](network-traffic-v6-m3-dsl-rewrite-plan.md)。V6 将改写语法单独规划为 DSL v2，M2 v1 保持兼容；先用生产适配器证明 Body 有界读取和候选完成前零上游发送，再接通动作和 UI。固定 Titanium 7.0.13 下改写模式整次运行仅协商 HTTP/1.1，普通捕获 HTTP/2 继续回归；不能将 h1 回退写成 h2 跨 authority 改写通过。

**用户流程：** 配置条件 → 预览命中和最终目标 → 启用 → 发起真实捕获请求 → 检查改写差异和目标结果。

| 工作项 | 范围与交付物 |
| --- | --- |
| M3-01 路由动作 | 精确域名映射，复用业务字段作定向条件；HTTPS 目标相关信息一致 |
| M3-02 请求修改 | 路径、Query、Header 和有界 JSON 的显式设置/删除；重新处理相关长度、编码与协议字段 |
| M3-03 执行语义 | 规则优先级、冲突诊断、一次路由、确定的动作顺序、在途快照与失败策略 |
| M3-04 可追查结果 | 原始/有效请求、规则修订、命中列表、最终地址、字段差异与执行错误 |
| M3-05 性能与并发 | 不同分组并发路由、HTTP/2 适用链路、流式回传、大响应和规则热切换回归 |

**验收：** 全量映射与按字段定向映射均实际到达正确的受控端点；其他请求不受影响；预览不发网；规则失败不静默发往原环境；修改规则不改变已接纳请求的语义；不产生代理循环或无限缓存。

**交付物：** 路由/改写语义规范、可编辑规则、命中诊断与差异页；流式、大资源回归证据。

**边界：** CGate 到预发的示例可由用户规则表达；普通头和域名条件无需读取整个 Body。依赖 Body 的规则在预算内决定，无法提取时按声明策略处理。人工断点、响应 Mock 与文件内容修改不自动纳入本阶段。

V6 首版失败策略固定为 block：作用域内条件未知、动作冲突、正文不支持/超限和目标校验失败均在发送前阻断，不静默回原环境。请求固定接纳时修订；原始/有效快照和实际发送状态分别记录。保存与预览不启用、不发网。测试及门禁要求见 [V6 专用矩阵](../maintenance/network-traffic-v6-m3-verification-plan.md)，仅安排本地 Debug 开发验证，不使用 AIFLOW、Windows CI 或发布门禁。

## 6. M4：手工请求、编辑重发与对比

详细执行入口为 [V7-01～V7-18](network-traffic-v7-m4-request-debugging-plan.md)，配套[请求调试专项设计](../design/network-traffic-v7-m4-request-debugging-design.md)和[专用验证矩阵](../maintenance/network-traffic-v7-m4-verification-plan.md)。SOLID为首要规定，朴素使用设计模式，关键实现/测试/脚本使用详细中文注释并解释设计思路；只执行本地Debug开发验证，不使用AIFLOW、Windows CI或发布门禁，正式发布时另行启用。

V7首版规划HTTP/1.1主动发送、文本/JSON/urlencoded/单个原始文件、环境变量、原始/有效快照提取、冻结预览、显式应用一次当前规则、来源隔离、模板/历史及有界对比。主动请求明确绕行本代理，无自动重试/重定向；未知结果和部分正文不能伪装成功或完整。当前无规则独立部分已接通，`M4Foundation`验证实际分项；原始/有效双快照和规则入口仍被M3阻断。80项新增场景与359项累计要求都不是已通过结果，`M4`入口对此明确失败，不生成完整成功结论。

**用户流程：** 手工新建或从抓包提取 → 编辑 → 选择环境 → 预览最终请求 → 发送 → 对比 → 保存模板。

| 工作项 | 范围与交付物 |
| --- | --- |
| M4-01 请求编辑器 | GET/POST 等方法、URL/Query/Header、文本/JSON/表单及明确支持的文件输入；输入验证与取消 |
| M4-02 环境与模板 | baseUrl 等变量、可替换身份值、未解析变量诊断；模板与具体执行值分开 |
| M4-03 重发来源 | 选择原始或当时有效快照、明确应用/不应用当前规则、内容缺失提示 |
| M4-04 执行与历史 | 复用内容查看器和资源预算、source/originRecordId、主动请求去重或绕行、失败/取消/未知结果 |
| M4-05 对比 | 原请求/新请求、状态/耗时/Header/有界内容差异；保存模板和再次打开 |

**验收：** 能从某组时间线选中请求，修改环境和入参后只发送一次到预览目标；新结果可回溯原记录，原记录不变；重发不污染默认真实用户视图；变量缺失、部分请求体不产生错误的发送；流式响应仍可持续查看。

**交付物：** 请求编辑器、模板/环境存储、执行历史与差异视图、最短端到端使用说明。

**核心产品完成点：** 捕获 → DSL 分组 → 查看时间线 → 条件改写 → 编辑重发 → 对比。M4 是首个完整业务流程里程碑，仍需真实 Host 使用验证；不等同正式发布完成。

## 7. M5：文档地址接入与接口说明

**用户流程：** 输入文档地址或手工说明 → 预览识别结果 → 关联接口 → 在流量和请求编辑页查看说明。

| 工作项 | 范围与交付物 |
| --- | --- |
| M5-01 来源管理 | 地址、获取结果、快照时间、手工说明；访问失败与格式不支持分别反馈 |
| M5-02 结构化导入 | 选择并固定 OpenAPI 支持范围，导入方法、路径、参数、示例和说明；明确不支持项 |
| M5-03 普通页面 | 文档链接关联和人工摘录；公司专有系统取得样例后再评估适配 |
| M5-04 关联与更新 | 接口识别条件、字段解释、模板辅助、导入差异、手工修订保留 |

**验收：** 一份结构化定义、一份普通网页来源和一份纯手工描述均能关联到对应请求；无文档时核心抓包仍可使用；更新导入内容不覆盖手工修订，也不自动改变已有用例或生效规则。

**本阶段不要求：** 万能网页解析、完整 API 管理平台、自然语言自动生成可执行规则、自动发布文档、强制团队账号服务。

## 8. M6：稳定性、真实 Host 与交付收口

| 工作项 | 范围与交付物 |
| --- | --- |
| M6-01 累计回归 | 全部适用业务矩阵、关键失败分支和规则兼容性；各阶段既有证据不得互相代替 |
| M6-02 资源验证 | 长时捕获、混合负载、配额/慢磁盘/解析错误、页面反复开关、取消与迟到任务 |
| M6-03 Host 验证 | 插件加载、依赖隔离、Dock/多文档/Tool、保存恢复、两主题、退出和代理恢复 |
| M6-04 使用与交付 | 快速开始、排错、记录预算说明、已知限制、插件 ZIP 内容和干净安装验证 |
| M6-05 结论记录 | 分开记录已实现、本地自动验证、真实客户端、真实 Host、用户验收和正式发布 |

**退出条件：** 所交付范围的必要验证均有对应结果；停止和退出释放监听与资源，系统设置按所采用模式正确恢复；记录完整性和未知状态如实显示；已知协议/客户端限制可查。正式发布需要另行安排，不能由本规划或本地构建推定已经完成。

## 9. 优先级调整与候选分支

若某阶段需缩减，优先缩减支持格式或编辑器便利功能，不削弱原始/有效记录、来源身份、未知状态、资源预算和停止恢复语义。M2 的 DSL 语义要先于复杂表单编辑器，M3 的域名映射要先于任意 Body 修改，M4 的逐条重发要先于批量编排。

| 后续候选 | 依赖与新增工作 |
| --- | --- |
| 响应替换与 Mock | M3；响应规则、内容编码、流式/大资源失败策略 |
| 人工断点 | M3/M4；等待寿命、超时、取消、并发操作与关闭窗口语义 |
| WebSocket/gRPC 专用分析 | M1–M3；协议解析、双向消息、限额记录与查看器 |
| 一组调用的场景重放 | M4；变量提取、步骤依赖、状态传递、非幂等操作和失败恢复 |
| 标准导入导出 | M4/M5；HAR、curl 等映射、私有字段与不支持数据的损失说明 |
| 跨插件 Workflow | 稳定用例后；公开 JSON 契约、取消、进度和 Host 真实能力核对 |
| 独立成品/跨平台 | 单独发行、证书/代理配置、原生平台行为与资源验证 |

候选只有在选入专项范围后才成为承诺，不自动扩大当前里程碑。

## 10. 状态维护与阶段启动方式

- [ ] M0：V2 技术基线已实现且本地自动验证通过；真实 Host、真实客户端与人工验收仍待执行。
- [ ] M1：V3 可用抓包已实现；已确认的 HTTP/2 空闲降级和自动结果见实施记录，真实 Host/客户端与人工尚待验收。
- [ ] M2：V5 DSL 字段、过滤分组、调用时间线、保存视图和开发门禁已实现；开发验证结果见 V5 实施记录，人工验收未执行，整体里程碑保持未勾选。
- [ ] M3：DSL 请求改写与环境映射。
- [ ] M4：V7-01～18执行方案及设计/验证专用文档已编写；请求编辑、重发、模板与对比尚未实现，完整验收依赖M3闭合。
- [ ] M5：文档地址与手工接口说明。
- [ ] M6：稳定性、Host 与交付验证。

沿用网易云项目“路线图 / 当前行为 / 验证方法 / 历史证据分开”的组织方式。具体实施脚本、测试数量、性能阈值和交付日期应从实际工作产生，不在本轮预填成功结果。
