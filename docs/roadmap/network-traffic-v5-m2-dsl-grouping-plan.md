## 1. 目标与首要规定

目标流程：**定义业务字段 → 定位诊断 → 用样本预览 → 选择时间范围 → 过滤分组 → 展开组内时间线 → 跳转请求详情 → 保存视图与修订 → 对历史快照重算**。

1. **SOLID 是首要规定。** 依专项设计逐项审查 S/O/L/I/D，优先保证职责、替换契约与依赖方向；不能用“已采用 MVVM”代替依据。
2. **设计模式朴素使用。** 采用手写有限文法解析、类型化 AST、纯求值函数、构造注入、普通 MVVM 和只读适配器；不建设通用语言平台、插件式函数系统、消息总线、CQRS、通用仓储或动态脚本引擎。
3. **注释使用详细中文并解释设计思路。** 重点解释值状态、短路与回退、快照身份、多值选择、时间窗口、预算、取消、迟到结果和资源释放。测试与门禁脚本也说明为何这样断言，不逐行翻译代码。
4. **单元测试和本地开发门禁同步交付。** 每项包含正常、边界、失败及必要的竞争路径；生产 UI、资源探针、存储故障及门禁拒绝自测分别验证。
5. **同步总览并新增专用文档。** 本计划安排顺序，设计规定契约，矩阵规定证明方式；实现时补当前行为、快速开始、样例集和带实际日期的实施记录。
6. **不使用 AIFLOW。** 不将其初始化、上下文、任务文件或检查流程作为前置。
7. **不新增或触发 Windows CI，不使用发布门禁。** 允许 Windows 本机 Debug 构建、单元/集成/UI/资源验证；Release、发布覆盖率门槛、打包、签名、上传及发布部署门禁在发布时另行使用。已有发布文档仅保留引用，不成为 V5 阻塞项。

优先级为 **SOLID 与语义正确性 → 可测试与资源有界 → 完整用户流程 → 编辑便利性**。不能为了界面先可用，把语言、存储和聚合逻辑堆入现有 `CaptureWorkspace`。

## 3. 固定范围与取舍

| 路线图工作项 | V5 必须交付 | 明确边界 |
| --- | --- | --- |
| M2-01 最小 DSL | 版本、文法、AST、类型/状态、诊断定位、字段依赖、有限函数、预算与取消 | 不执行 C#/JS、反射、网络/文件/进程函数；v1 不支持正则和通用 JSONPath |
| M2-02 字段提取 | Query/Header/Cookie/JSON/urlencoded 表单/路径六种位置；首值/全部值、显式转换与回退、来源说明 | 只读原始请求；JSON/表单必须是完整且预算内的已记录请求体；不提取响应体、multipart 或流消息 |
| M2-03 过滤分组 | 三值条件、单/多字段及 tuple 组合键、未知分类、统计口径、业务显示列 | 按组数表达，不自动叫用户数；重复业务请求保留；无字段内置 `at` |
| M2-04 时间线 | 半开窗口、同刻稳定排序、并行条带、错误/流式状态、窗口前在途上下文 | 时间线基于一次分析快照，明确刷新时间；不推断因果、不跨会话关联 |
| M2-05 规则体验 | 文本编辑、基础字段表单辅助、错误定位、样本预览、不可变修订、SavedView、历史重算 | 编辑面板放现有 Document 内；不必新建 Host Document 类型；错误草稿不替换有效结果 |

V5 首版使用**显式刷新快照分析**：打开分析后主动应用或刷新；到达新流量只显示“源数据已更新”。默认最近 30 分钟，时间窗口在每次执行时固定；历史记录使用存档的参考时间，不使用打开当天的系统时间。持续自动增量聚合、跨会话联查、全文索引和正则作为后续候选，不通过后台无限重算实现。

分析范围与 M1 列表筛选独立。用户可显式从当前列表条件创建分析草稿，但不得暗中继承关键字、清空本页水位或选择项。来源默认 capture；未来来源与 Unknown 均不能伪装为 capture。保存视图保存定义和修订，不复制捕获正文或把源文件绝对路径写入规则。

不扩展 M3 改写/M4 重发、系统代理、证书安装、协议适配、包版本和发布流程。M0/M1 已确认的 HTTP/2 空闲降级继续有效。

## 5. 逐项执行要求

### V5-01：先固定可核对样例与预算

1. 核对本节基线和前置人工未验项；保留旧阶段证据，不借机升级 Titanium/Avalonia/SDK。
2. 将专项设计的 12 条固定记录、两种分组和有效/无效 DSL 做成合成夹具；预期键、记录身份、未知状态与时间顺序手工可核对，不能由被测引擎生成预期值。
3. 固定语言文法、支持列表、诊断码和初始预算；添加 `m2-profile.json`、必测 ID 清单及门禁骨架时保持未实现项失败，不先填通过结果。
4. 若现有冻结或正文读取不满足上限，登记具体文件和调整点，补同契约回归；不得以改用列表前 N 行掩盖范围缺口。

### V5-02：领域与 I/O 分开建模

1. 普通不可变类型描述 AST、TypedValue、FieldResult、SourceSpan、FieldOrigin、RuleRevision、SavedView、AnalysisResult；只有 I/O、时钟和共享额度需要可替换边界。
2. 定义 `IAnalysisSource` 的快照/有界正文读取，以及 `IRuleLibraryStore` 的版本化读取/原子提交；真实与 Fake 共享取消、缺失和失败契约。
3. AnalysisWorkspace 不直接读取文件/解析 JSON；求值器不依赖 Avalonia、Titanium 或 DI 容器；集合和数组不得从可变捕获模型裸共享。

### V5-03：语言前端

1. 手写词法与递归下降解析，操作符按专项设计优先级；每个 token/节点保留 UTF-16 范围以定位编辑器。
2. 检查语言版本、重复/未知字段、函数签名、类型、分组键、显示列、时间范围、依赖环和禁止动作。
3. AST 深度、token 数、诊断数先检查再扩张；超限产生结构化诊断，不栈溢出、不吞异常成空规则。
4. 编译只返回候选，不修改当前已应用修订；同一草稿的诊断必须带编辑代次。

### V5-04：提取与记录事实

1. 六种来源分别落实大小写、解码、重复键、空值和损坏编码语义；头按行保留，不猜测逗号分隔。
2. JSON 路径只支持点属性、带引号属性、固定数组下标；表单只支持 urlencoded。正则、通配符、递归下降、脚本与 multipart 返回不支持诊断。
3. 先看元信息/记录完整性，再决定是否读取正文；超限、文件缺失、编码错误、未结束和只保留前缀均不能当 Missing。
4. 同一记录一次有界解析供多个字段复用，解析对象用完释放；不得遍历每行时创建一份长期 JSON 树。

### V5-05：求值、条件和组合键

1. 无隐式字符串/数字转换；`first` 与 `all` 明确多值选择；转换失败保留 Invalid 及来源。
2. `firstNonEmpty` 仅跳过 Missing/Null/空字符串；遇到未就绪、不可用或失败停止并保留原因。
3. 布尔短路使用三值逻辑，只有 True 进入匹配集；False 与 Unknown 分别计数。未知不能经 `not` 变成 True。
4. 组合键使用类型化 tuple，不用字符串拼接；默认遮罩所有派生业务字段，保留不泄露原值的组别名与解释入口。

### V5-06：查询与统计

1. 每次分析固定源身份、快照、规则修订、时间锚点和预算；筛选元信息后按需读取正文，避免无关 Body I/O。
2. 单记录复用已求值字段；依赖只求值一次；本轮结束不保留正文缓存。生产冻结源按 RecordId 提供唯一投影；若适配器给出重复身份，整批拒绝以免猜选修订；不同 RecordId 的重复业务请求仍分别计数。
3. 输出记录数、接口数、首次/最后开始、错误数、接收中数与状态覆盖计数；给出分母和缺口，未知分类不冒充业务组。
4. 记录数、组数或总内存超限则整次候选不提交，保留上次有效结果和失败提示；不得只取前 N 组后显示分析完成。

### V5-07：窗口和时间线

1. `[from,to)` 按 StartedUtc 归属，最近窗口的 now 每轮只采一次；历史 last 窗口使用固定的存档参考时间。
2. 组内按 StartedUtc、Sequence、RecordId 稳定排列；使用既有单调耗时数据绘制持续条带，不拿墙钟差替代耗时。
3. 进行中请求端点标“快照时仍接收”，并发画重叠；窗口前开始且在窗口起点仍活动的记录放可选上下文，不进入主统计。
4. 点击记录跳到现有详情；源已切换或记录不可用时显示原因，不能按旧索引打开另一条请求。

### V5-08：编辑和预览

1. Draft、CompiledCandidate、AppliedRevision 分开；验证、预览、应用、保存动作具有明确含义。
2. 基础表单覆盖字段名、提取位置/参数、first/all 和显式转换，生成可插入草稿的文本；不反向覆盖无法表示的复杂表达式。
3. 样本预览显示字段类型、值状态、来源、过滤结论和分组键，默认遮罩；至多 20 条明确选择的样本，不把预览数冒充全量统计。
4. 错误点击定位文本范围，输入/计算/保存错误分层；旧诊断和迟到预览不得覆盖新草稿。

### V5-09：修订和保存视图

1. 修订不可变，SavedView 固定引用具体修订；成功保存不自动改变其他 Document 的已应用版本。
2. 对规则文本、字段引用、窗口、排序和列配置整体验证，按库代次比较后原子写入；冲突提示重载/另存，不静默最后写入覆盖。
3. 写临时文件、提交失败、进程中断、坏 JSON、未知 schema/language、丢修订和达到库限额都保留旧文件；重启不得自动启动抓包或分析。
4. 保存只保存定义；捕获正文、提取出的身份值和会话路径不进入规则库。规则文字本身可能含用户输入常量，日志只记录修订身份与摘要。

### V5-10：历史、取消、多页

1. 实时与历史用同一引擎、同一规则；显示原始保存缺口、当前保留范围和分析时水位，不能从缺失文件重新下载。
2. 新应用/刷新、换源、返回实时、关闭页撤销旧任务；await 后及 UI 提交时再次比对页面/源/规则/操作代次。
3. 每页最多一项分析，容器最多两项；忙碌时反馈且不无限排队。关闭非最后页及最后页都只取消页面分析，不停止共享代理。
4. finally 释放快照、正文预算与解析对象；保存任务不持有 View，迟到保存回执不能激活旧页面状态。

### V5-11：生产 UI 与阅读兼容

1. 主 Document 增加“请求 / 分组”切换，分组页提供窗口、来源、修订、刷新/取消、覆盖范围及保存视图入口。
2. 宽屏为组列表/时间线/请求详情协作；窄屏逐层进入并可返回，规则编辑作为按需面板，不挤掉代理停止入口。
3. 分组列表和时间线按身份虚拟化；显示列引用已编译字段，未知值有文字状态；排序、展开和选择稳定。
