## 1. 目标与首要规定

目标流程：**添加结构化定义地址 / 普通网页来源 / 纯手工说明 → 获取或填写 → 预览识别结果与限制 → 明确提交 → 关联接口 → 在捕获详情、时间线入口和请求编辑页查看说明 → 选择字段与示例生成新草稿 → 复用 M4 预览和显式发送 → 刷新来源并保留手工修订**。

1. **SOLID 是首要规定。** 每项实现先说清职责、依赖方向、替换契约和所有权；不以接口数量、类数量或 MVVM 标签代替实际审查。
2. **朴素使用设计模式。** 沿用纯函数、不可变快照、构造注入、窄 I/O 适配器、显式状态和现有 MVVM。只为获取、持久化等真实替换边界建接口，不建设通用导入框架、动态插件总线、CQRS、事件溯源、工作流或规则生成引擎。
3. **详细中文注释，并解释设计思路。** 说明为什么不跟随外部引用、为什么匹配歧义不能取第一条、为什么导入层与手工层分开、为什么刷新不能改模板、为什么取消后仍需释放缓冲和拦截迟到结果。生产代码、测试、夹具与 PowerShell 检查器均适用。
4. **单元测试和本地开发门禁齐全。** 正常、边界、错误、真实适配、存储、并发、寿命、生产 UI、资源和门禁拒绝反例全部落地；场景、测试方法、参数化执行行分别计数。
5. **同步现有文档并增加专用文档。** 计划写顺序，设计写契约，矩阵写证明方式；当前行为、快速开始、合成样例与实施记录随真实实现建立，不提前声称可用。
6. **不使用 AIFLOW。** 不初始化、不读取其上下文、不生成其任务、计划或更新候选，不作为前置条件。
7. **仅使用本地 Debug 开发验证。** 不新增或触发 Windows CI，不运行 Release、发布覆盖率门禁、ZIP 打包、签名、上传、部署或发布门禁；正式发布时再启用对应验证。本机 Windows 上的 Debug 测试属于本地开发检查。

取舍顺序：SOLID 与事实准确 → 手工数据保护、无隐式副作用 → 有界资源与寿命 → 完整操作闭环 → 编辑便利性。

普通网页来源和纯手工来源均能通过手工录入“方法、路径模板、目标绑定、说明和字段”关联真实请求，不以“只存一个不可关联的链接”代替交付。抓包样本可以复制已观察的方法/路径到待编辑表单，但不推断参数必填、完整枚举或完整响应集合。

**可以独立推进：** 来源库、纯导入器、引用解析、合并、匹配、说明面板、草稿建议，以及与现有无规则 M4 的接入。**完整交付前必须完成：** V6/M3 和 V7/M4 全部必需场景、实际规则/双快照链路及累计回归。原始/有效请求说明只能依据可信快照分别匹配；缺失时明示不可用，不能用同一观察值伪装两份结果。
