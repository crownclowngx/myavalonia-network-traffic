## 1. 目标与首要规定

目标流程：**手工新建 / 从捕获列表或分组时间线提取 → 选择原始或当时有效快照 → 编辑方法、地址、参数及正文 → 选择环境与规则方式 → 预览最终请求 → 明确发送一次 → 查看响应和历史 → 对比 → 保存模板并再次打开**。

1. **SOLID 是首要规定。** 每项实现必须说明职责、依赖方向、可替换契约及所有权；通过评审和可观察行为证明，不能以类数、接口数或 MVVM 标签代替。
2. **朴素使用设计模式。** 使用不可变快照、纯函数、构造注入、窄 I/O 适配器、枚举状态与现有 MVVM。只有真实替换边界才引入接口；不建设通用 API 平台、工作流引擎、消息总线、CQRS、通用仓储或可执行脚本系统。
3. **详细中文注释并说明设计思路。** 重点解释“为什么”：预览为何会失效、发送与远端结果为何分开、部分正文为何不能重发、凭据为何不随模板保存、取消后租约为何不能提前释放。生产代码、测试夹具和 PowerShell 检查器同样遵守。
4. **单元测试和本地开发门禁齐全。** 正常、边界、错误、协议、并发、寿命、存储、生产 UI、资源及门禁拒绝反例分别验证。测试总数不能代替业务场景覆盖。
5. **同步现有文档并增加专用文档。** 本计划负责执行顺序，设计负责契约，矩阵负责证据；实现时再增加当前行为、快速开始、可测试样例及带日期实施记录。
6. **不使用 AIFLOW。** 不初始化、不读取其上下文、不生成其任务与更新候选，不把它作为任何前置。
7. **只做本地 Debug 开发验证。** 不新增或触发 Windows CI，不运行 Release、发布覆盖率、ZIP 打包、签名、上传、部署或发布门禁。Windows 本机的 Debug 测试允许；正式发布时另行启用适用门禁。

优先次序：SOLID 和请求正确性 → 发送边界与完整性 → 资源及寿命 → 可追查结果 → 完整交互 → 编辑便利性。

## 3. 范围和依赖边界

| 路线图工作项 | 必须交付 | 首版明确边界 |
| --- | --- | --- |
| M4-01 请求编辑器 | 常用方法、绝对 URL、Query、多值 Header、无正文/文本/JSON/urlencoded/单个原始文件 | HTTP/HTTPS、HTTP/1.1；无 multipart、WebSocket、gRPC 专用编辑、curl/HAR 导入 |
| M4-02 环境与模板 | baseUrl、普通变量、运行期敏感变量、版本化模板与环境、未解析诊断 | 无脚本、递归变量、自动 OAuth、CookieJar 或跨请求变量提取 |
| M4-03 重发来源 | 原始/当时有效快照、明确规则模式、完整性判定、来源定位 | 一条请求一次用户意图；不批量重放、不自动重签、不从未知快照猜测 |
| M4-04 执行与历史 | 单执行入口、取消、流式响应、独立来源、执行历史、可信终态 | 明确绕行本代理，无自动重试/重定向/认证握手重发；连接失败不自动换目标 |
| M4-05 对比 | 原请求与新请求、两次结果的状态/耗时/Header/有界正文、完整性说明 | 文本按行、JSON 结构、二进制元信息/可信摘要；不做无界全量 diff |

单个原始文件是本期明确支持的文件输入。大文件在发送前流式复制到受配额管理的不可变暂存体，生成摘要；不能把用户路径直接当成持久化请求正文。multipart 和文件批量上传另行规划。

## 4. 执行顺序与每项交付

下列新增路径为拟定代码位置，统一相对 `src/NetWorkTrafficPlugin.Plugin/`；不存在的文件不建立链接。矩阵编号均带 V7 前缀，详细断言见专用矩阵。

### V7-01 · 固定范围、事实和预算

- 核对 V6 缺口、当前 schema、现有内容记录/租约/配额和公开 Host SDK 接入方式，登记事实表与未完成项。
- 固定专项设计中的 HTTP/1.1、单文件、变量语法、正文支持、规则模式、快照选择、持久化和默认来源。
- 拟新增 `tools/m4-profile.json`，写入设计预算、UI 组合、资源负载和场景清单；不预填成功数据。
- 完成条件：范围、依赖、预算和未知事实无矛盾；C01/C02/C08、J01～J05 可追踪。

### V7-02 · 先证明主动发送适配能力

- 在现有受控端点上实现独立探针，核对现有 .NET/依赖能否满足禁用代理、重定向、自动认证/重试、HTTP/1.1、HTTPS 目标身份及真实取消。
- 验证自代理地址/别名拒绝、连接目标检查与连接地址绑定、一个用户意图的端点调用次数、响应头先返回和有限读取。
- 以请求头入口、Body 摘要、Host/SNI、连接及活动任务计数作证；Fake 通过不代表真实适配器通过。
- 完成条件：X01～X08、C03 所需基础能力有证据；不满足则停止受影响发送接入，继续纯模型/文档，不用配置名宣称保证。

### V7-03 · 建立最小模型和端口

- 新增 `Application/Requests/RequestContracts.cs`、草稿校验器及快照转换器；区分 Draft、PreparedRequest、Attempt、Result、Template。
- 端口只覆盖传输、完整正文暂存、库原子提交、调试记录写入；纯变量替换、Header 处理、diff 不各建接口。
- 统一结构化中文诊断、来源 ID 和取消/完整性枚举；禁止 UI 控件、HttpRequestMessage 或任意用户路径进入领域模型。
- 完成条件：A01～A08、S01～S08；Fake/真实端口具有同样缺失、取消和失败语义。

### V7-04 · 请求编辑与协议字段校验

- 新增 `Features/Requests/RequestDraftModel.cs`，实现方法、地址、重复 Query/头行、启用行、正文类型和局部错误。
- URL Query 与参数表基于同一有序模型；无编辑时保留转义，编辑项只编码一次。
- 协议控制头由发送适配器派生；Cookie 与 Authorization 是显式输入，无隐藏账户状态。
- 完成条件：A01～A08；非法方法、URL、头值、冲突或超限在预览前被定位，网络调用为零。

### V7-05 · 环境变量与敏感值寿命

- 新增 `Application/Requests/RequestVariableResolver.cs`，实现单次替换、作用域优先级、baseUrl、不同字段上下文的编码和来源说明。
- 持久化普通环境值和敏感变量名称；运行期敏感变量及其解析正文使用内存租约，不跟随模板、自动历史、临时请求日志、诊断或证据保存。服务器响应/用户文件按内容记录策略处理，不承诺自动识别所有私密原文。
- 环境切换、变量修改或敏感值清除使旧预览失效；缺失与空字符串分别处理。
- 完成条件：E01～E08；含中文、`+`、`%`、引号与 CR/LF 的场景均有确定结果。

### V7-06 · 正文构造、原始文件与暂存租约

- 新增正文构造器及 `Infrastructure/Requests/FileRequestBodyStore.cs`；支持无正文、UTF-8 文本、严格 JSON、urlencoded、单个原始文件。
- 文件选择后有界复制，检测复制期间源变化；正式预览只读受管理的冻结字节。正文变更移除失效摘要/长度，重新派生 Content-Type/framing。
- 完整捕获体可建立受管理副本；部分、缺失、编码未知或不支持的体不能默认为空。用户可明确替换全部正文后重新预览。
- 完成条件：B01～B08、R01/R02/R04；失败无半成品模板、无磁盘越界、无泄漏租约。

### V7-07 · 捕获列表与时间线提取

- 两个入口统一调用快照转换用例，不在 View 中复制 Header/Body 逻辑。
- 读取固定 RecordId/Revision，登记 originSessionId、originRecordId、snapshotKind 和快照摘要；来源记录保持只读。
- schema1 只按其可证事实暴露已观察请求；URI 曾改变而缺乏双快照时不提供伪造的原始/当时有效选项。
- 完成条件：S01～S08、C01/C05；源记录淘汰、历史存档或多次重发均有清楚来源，不递归自动执行。

### V7-08 · 最终预览与 M3 规则接入

- 新增 `Application/Requests/RequestPreparation.cs`；顺序固定为正文冻结 → 变量解析 → 用户输入验证 → 可选 M3 规划一次 → 最终验证 → PreparedRequest。
- 默认不应用当前规则；显式应用时冻结可用的当前修订，展示修订及前后差异。有效快照再应用当前规则必须由用户明确选择。
- PreparedRequest 绑定草稿/环境/规则代次、正文摘要和期限；任何影响发送的编辑使预览失效。预览没有发送能力。
- 完成条件：E05～E08、S04～S08、C02；M3 未闭合时相关入口保持不可用，失败不回退原环境。

### V7-09 · 单执行入口与取消

- 新增 `Application/Requests/RequestExecutionCoordinator.cs` 与 `Infrastructure/Requests/HttpRequestTransport.cs`。
- 一个不可变预览令牌只能被原子接纳一次；重复点击合并同一 Attempt，不按 URL/Body 全局去重。用户再次发送需新令牌与新 AttemptId。
- 实现发送前取消、发送后取消/超时、HTTP 错误、响应中断与结果未知；无自动重试、重定向或失败回原地址。
- 完成条件：X01～X08、C04/C07；受控端点证明本应用单次发送，记录不声称远端业务恰好执行一次。

### V7-10 · 调试记录、响应查看与默认来源

- 最小提取 `Infrastructure/Capture/` 可复用的记录器、有限正文/流解析和配额；新增调试会话，不复制整套捕获器。
- `TrafficSource` 增加 Manual/Replay，摘要不再硬编码 Captured；捕获视图和 SavedView 缺省来源明确保持 capture。
- 主动传输绕行本代理，记录由唯一调试写入者产生；不靠公开 Header 判断去重，不覆盖 `CaptureSessionStore.Current` 的实时捕获。
- 完成条件：H01/H04/H07、U05、R03、C05；主动流量能显式加入分析但不污染默认真实用户视图。

### V7-11 · 模板、环境、历史和恢复

- 新增 `Application/Requests/RequestLibrary.cs` 与 `Infrastructure/Requests/FileRequestLibraryStore.cs`；用 schema、不可变修订、CAS 和同目录原子替换。
- 模板保存未解析草稿、变量引用及必要正文资产；不保存运行期敏感值或已解析目标。文件正文资产持久化成功后才提交模板索引。
- 自动历史保存脱敏执行摘要、关联和结果完整性；响应原文默认仅当前调试会话。显式保存记录使用已有存档能力并说明敏感内容范围。
- 完成条件：H01～H08、E04、B07；损坏/未来 schema 不覆盖，恢复零网络，未完成 Attempt 标为中断/未知。

### V7-12 · 有界请求与结果对比

- 新增 `Application/Requests/RequestComparison.cs`；独立提供请求输入差异和响应结果差异。
- 头名大小写不敏感且保留重复项，文本按行，JSON 按属性/数组位置，二进制仅元信息及有完整性依据的摘要。
- 超预算、未完成或正文缺失返回“部分对比/不可比较”，不能因前缀相同显示相同。
- 完成条件：D01～D08、R05；对比零网络，取消后不覆盖新选中对象。
