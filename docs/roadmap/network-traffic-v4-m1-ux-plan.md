## 1. 目标与首要规定

目标流程：**启动并接入代理 → 快速定位请求 → 连续阅读请求/响应 → 查看实时流且不被打断 → 保存会话快照 → 只读回看 → 返回实时**。扩大有效内容面积，同时保持传输事实、记录完整性和生命周期语义。

实施优先级：**SOLID 与行为正确性 → 阅读稳定性和可测试性 → 信息密度 → 视觉细节**。

1. **SOLID 是首要规定。** 以专项设计中的 S/O/L/I/D 职责、依赖和替换契约逐项审查，不以“使用 MVVM”代替审查结论。
2. **设计模式朴素使用。** 沿用 MVVM、构造注入、枚举状态、纯投影函数及必要的窄平台适配；不建设消息总线、通用状态机、动态查看器框架、万能服务或通用仓储，不为每个属性创建接口。
3. **关键实现、测试和脚本使用详细中文注释。** 说明设计思路、状态归属、滚动触发原因、取消和迟到、预算及释放，不只翻译语句。注释示例见专项设计。
4. **单元测试与本地开发门禁同步交付。** 每项任务包含正常、边界、失败和必要的竞争路径；生产控件交互、资源测量、门禁拒绝自测独立取证，不能只测 ViewModel 属性。
5. **同步文档并新增专用文档。** 本计划、设计、验证矩阵分别维护顺序、契约、证明方式；实现后更新当前运行说明、快速开始及带实际日期的实施记录，保留未验项。
6. **不使用 AIFLOW。** 不创建、读取或运行其上下文流程作为本轮前置，不引入相关任务跟踪文件。
7. **不新增或触发 Windows CI，不使用发布门禁。** 本机 Windows Debug 构建、单测、受控集成、UI 和资源检查属于开发门禁。Release Smoke、发布覆盖率门槛、签名、ZIP 打包、上传、发布部署和干净安装发布验证留到正式发布。

## 3. 固定范围与产品决定

| 范围 | V4 必须交付 |
| --- | --- |
| 主操作栏 | 代理状态/实际地址/复制、同位置启停、保存会话快照、打开、设置；启动/停止中和故障态有准确反馈 |
| 筛选栏 | 关键字、方法、HTTP 状态常用入口；更多筛选承载时间和精确状态码；已生效条件可见并可逐项移除 |
| 请求列表 | 默认双行，方法/路径/状态/耗时优先，域名/带口径的大小次之；接收中、失败、部分保存、元信息缺失不隐藏 |
| 阅读稳定性 | 列表与流事件独立跟随；手动滚离最新位置即暂停对应跟随；保持身份锚点，新增提示可主动返回最新 |
| 详情 | 请求身份摘要；明确请求/响应切换；正文、概览、参数、Headers、Cookie；导出移为动作；JSON 三种视图互斥 |
| 导航 | 可拖动分栏；窄屏保留返回、请求身份及上/下一条；局部搜索、正文查找和 Esc 焦点规则 |
| 文件操作 | 选择存档父目录并生成新子目录、选择现有存档目录、选择新正文文件；取消无写入；完整会话快照语义可见 |
| 状态与反馈 | 统计收至状态栏；诊断按重要性分层；区分未启动、等候请求、无匹配、未选择及只读；反馈不抢焦点 |
| Tool 与设置 | 复用代理信息/配置内容；Tool 仍可独立启停；详细诊断按需展开；改配置只在下次启动生效 |
| 适配与验证 | 明暗主题、主要窗口及 Tool 尺寸、DPI、键盘/焦点；M0/M1 行为与资源预算完整回归 |

本轮默认采用双行列表；单行表格密度模式、列定制、跨进程偏好持久化和自动恢复阅读历史留后续。分栏比例、视图模式等只在当前 Document 寿命内记忆。正文查找限定已有有限文本预览，不扩展为全文索引或 JSONPath。

不扩展协议、DSL、改写、请求重发、系统代理管理、持久证书安装、任意大存档分页、历史会话清理页或跨插件工作流。关闭页面继续捕获、HTTP/2 空闲仅提示、配额、原生存档格式和现有解码边界保持；因 UX 修复而调整的筛选/跟随规则在设计中明确列出。

## 5. 逐项执行要求

### V4-01：建立可比较的基线

1. 核对实际源码、锁定依赖、文档和 V3 未验清单；不借机升级 UI 或代理库。
2. 使用生产 MainView/CaptureView/ProxyPanelView 和合成流量，记录明暗主题、规定尺寸、字体/DPI、列表和正文区域边界。
3. 样本包含多个域名、长路径、中文、不同状态/大小、部分记录、SSE、图片及只读档案；不能只用一条短 GET 截图判断密度。
4. 固定设计中的 DIP 量尺与验证 profile；Avalonia 分隔条、滚动事件、存储选择器、剪贴板及自动化 API 通过本地依赖/编译核实，不把示意接口名当成现有 API。

### V4-02：先建立可测试的状态和职责

1. MainDocument 负责组合；代理模型负责共享状态投影；CaptureWorkspace 保留页面协调，按实际职责提取筛选、详情或阅读状态，禁止继续堆入所有平台逻辑。
2. 列表跟随、事件跟随、筛选草稿/已应用条件、当前方向、正文模式、反馈分别建模；使用普通类型和枚举，不搭通用状态机。
3. 纯单测先固定页面/会话/记录身份、选择代次、操作代次、取消与所有权，平台替身只出现在真正的外部边界。

### V4-03：收紧页面外框和代理设置

1. 顶部第一行放代理控制与文件动作，第二行放常用筛选；统计固定在底部，错误不挤掉停止入口。
2. 状态操作覆盖 Stopped/Starting/Running/Stopping/Faulted；故障仍有释放/重试路径，不把未释放显示为已停止。
3. 设置使用覆盖式侧栏，窄屏使用同一内容的受约束弹层；不得把整块旧代理 Tool 再嵌入页面形成双重标题、启停及嵌套滚动。
4. Tool 保留独立代理控制与关键范围提示；关闭设置或 Tool 不能停止共享捕获。公开证书信息和 h2 限制仍可达。

### V4-04：双行列表与可理解的筛选

1. 以路径为主要识别内容，域名为第二层；常态两行，异常标记不只靠颜色，完整状态和字节口径进入详情。
2. 保持虚拟化及按身份的增量更新；关键字输入期间保留最后有效结果，明确查询状态，避免每次按键先清空整页。
3. 方法选择只有一个有效来源；状态类/精确码规则、传输状态互斥规则、时间边界和非法输入按专项设计执行。
4. “清除筛选”与“清空本页”分离：清除筛选不恢复清空前范围；范围标签可单独移除，活动请求仍按现有查询契约保留。所有操作只作用当前 Document。

### V4-05：跟随以用户阅读意图为准

1. 删除定时刷新无条件滚动的行为；只有确有新数据且对应跟随开启时请求定位。
2. 区分鼠标/键盘等用户滚动与程序恢复锚点；后一种不得误判为用户暂停或形成递归滚动。
3. 暂停时保持顶部可见记录/事件身份和偏移；选择旧请求时暂停列表跟随；流正文的选择与滚动不受列表跟随开关影响。
4. 新增提示只统计明确可证明的当前保留范围；锚点淘汰、换筛选、换会话、只读/实时切换按设计确定重置及提示。

### V4-06：正文优先并保持内容事实

1. 正文/Headers 共用明确方向；Query 始终标注为请求参数，Cookie 区分请求 Cookie 与响应 Set-Cookie，避免方向含义混乱。
2. JSON 树形/格式化/原文互斥，默认格式化；图片、流事件、文本、二进制各显示实际适用视图。
3. 原文是有界解码文本，不宣称是线上逐字节原包；导出仍复制保存的实体字节。失败、截断和缺口提示不得折叠掉。
4. 复制遵守字段显示遮罩；正文查找只检索当前有限文本并标范围，不扫描磁盘全文，不绕过脱敏搜索字段原值。

### V4-07：分栏、导航与可访问性

1. 采用可拖动分隔条，约束两侧最小宽度；Document 内记忆比例，宽窄切换不改选中身份。
2. 窄屏详情保留返回、请求身份及上/下一条；标签使用溢出入口而非无限换行；上一条/下一条基于当前筛选结果。
3. 局部 Ctrl+L 聚焦请求搜索，Ctrl+F 查找当前正文文本，方向键只在列表焦点下切换请求；与 Host 冲突时使用焦点范围内绑定，不占全局命令。
4. Esc 先关闭最上层临时界面，再关闭正文查找，最后窄屏返回列表；恢复原焦点。所有图标按钮有中文可访问名称和提示。

### V4-08：文件操作与异步反馈

1. 保存以当前源会话仍保留的全部可存档记录为范围，包含被筛选隐藏的记录；明确不是全部历史累计请求，也不是当前列表筛选结果。
2. 保存选择父目录，再填写/生成新目录名；打开选择现有存档目录；恢复作为打开菜单次级入口；导出冻结当前记录和方向后选择新文件。
3. 保留捕获根之外、新目标、不覆盖、快照提交水位及取消清理要求；取消平台选择器不启动业务 I/O。
4. 保存期间显示进度/取消，结束后移除取消动作；只读顶部显示模式与返回实时，底层代理状态独立呈现。
5. 错误贴近来源并可查看完整原因；短暂成功反馈不抢焦点，旧操作不能覆盖新操作反馈。

### V4-09：多页面和资源寿命

1. 每个 Document 的筛选、方向、选择、跟随、锚点、分栏和临时面板独立，共享捕获/代理所有者维持唯一。
2. 页面关闭、换记录/方向、选择器/剪贴板返回及旧 finally 分别验证代次和资源归还；异步回调不得访问已分离 View。
3. 详情模式切换不得累计复制字符串、树或位图；查找只保存有界定位状态，不缓存所有匹配；回归 32 MiB 共享内容预算。
4. 带活动流、保存、设置和读取的关闭/停止路径必须实际测量；页面关闭仍不停止代理。

### V4-10：完整界面与负载验证

1. 完成专用矩阵的布局、交互和持续负载场景，实际渲染生产 View，保留控件边界、命中、输入结果及 PNG。
2. 对紧凑性使用量化断言，对遮挡、可读性、选择色和中文排版逐图复核；Headless 不冒充真实 Host 或物理输入。
3. 沿用 M1 的一万摘要、20 并发/5 流、600 秒、20 轮页面循环和资源阈值，增加阅读锚点、独立跟随和正文切换观测。

### V4-11：门禁和证据接通

1. `verify-development.ps1` 已支持 `-Mode UX`，默认仍为 M0，Docs/M0/M1 原语义不变；完整 UX 同轮继承两代检查。
2. UX 在同一轮执行并校验 M0、M1 和 V4 必测集合，复用旧检查器，不靠读取昨天的通过报告继承成功。
3. 新增 UX 专用映射/profile/检查器/自测，固定 40 项 V4 业务场景，逐项映射真实方法和必需参数行；完整顺序及拒绝条件见验证矩阵。

### V4-12：审查和文档收口

1. 提供 A01～A04 的具体代码、测试和设计依据；修复发现后重跑受影响检查，最终行为基线再完成整轮 UX 门禁。
