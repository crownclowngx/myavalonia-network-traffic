## 1. 产品定位与当前基线

产品定位：以 HTTP/HTTPS 抓包为入口，通过领域特定语言（DSL）定义字段提取、过滤分组、调用时间线和请求改写，同时提供手工请求与编辑重发能力的桌面插件工作台。

主要用户是需要排查公司内部及对外接口、切换调试环境、理解一组调用过程的开发与测试人员。首要价值是把真实流量整理成可以解释、定位和再次验证的业务过程。

## 2. 已明确的需求与设计建议

### 2.1 已明确的需求

- HTTP/HTTPS 抓包是中心能力，需要支持流式返回以及图片、视频、文件等大响应。
- 强化过滤、分组和按时间观察接口调用过程；条件可以来自不同位置的请求参数。
- `at` 只是示例字段；字段名、提取位置、组合方式和分组规则由 DSL 定义。
- 支持代理过程中的域名及请求替换，例如将 `cgate.zhaopin.com` 统一映射到 `cgate-pre.zhaopin.com`。
- 支持类似 Postman 的手工请求、从抓包提取请求、修改后再次发送。
- 支持通过可访问地址接入现有接口文档，也支持没有文档时直接手工描述。

### 2.2 本方案给出的建议

- 第一版完整业务流程以 M4 为目标；文档自动接入安排在 M5。
- 使用一套有类型、可诊断的规则模型承载 DSL；界面表单与文本编辑共享同一份规则。
- 请求原始快照、实际发送快照、规则命中记录与重发来源分别保存。
- 首期代理服务由插件服务持有，Document 保存独立筛选和查看状态；关闭观察页不隐式停止代理，运行状态始终可见。具体寿命与退出行为在 M0 固化。
- HTTP/1.1 为最小验证基线，HTTP/2 为 M0 必须调查和验证的兼容项；不默认承诺 HTTP/3、任意客户端或全网流量覆盖。

这些建议在对应里程碑细化；涉及取舍时记录原因，不把建议表述为已经实现的行为。

## 3. 典型使用场景

| 场景 | 用户流程 | 可观察结果 |
| --- | --- | --- |
| S01 日常抓包 | 启动代理 → 目标客户端接入 → 查看、搜索、筛选请求 | 看清实际捕获范围、请求状态、参数和响应 |
| S02 环境映射 | 定义域名条件 → 预览规则 → 启用 → 发起请求 | 原始域名与实际目标同时可见，命中规则可追查 |
| S03 调用分组 | 定义业务字段 → 选择时间范围 → 分组 → 展开时间线 | 每组请求数、开始与结束时间、耗时、异常和并发关系 |
| S04 定向映射 | 复用业务字段 → 仅对某个分组启用环境映射 | 同域名下不同请求按条件进入指定目标 |
| S05 编辑重发 | 从记录提取 → 修改输入或环境 → 预览 → 发送 → 对比 | 新结果关联原始记录，并区分真实捕获与调试来源 |
| S06 流式与大资源 | 查看持续返回、图片或文件传输 → 按需预览和保存 | 不等待整段响应结束才能查看，记录完整性清晰 |
| S07 文档辅助 | 填写文档地址或手工说明 → 关联接口 | 查看流量时能看到接口名称、字段含义和示例 |

S02/S04 的 CGate 地址是需求示例，本次编写没有访问这些服务或修改代理设置。自动验证使用受控本地目标；真实环境的验证结果单独记录。

## 6. 核心数据对象

| 对象 | 含义与约束 |
| --- | --- |
| CaptureSession | 一次捕获范围、起止时间和记录策略；标明接入来源与采集覆盖范围 |
| TrafficRecord | 一次观察到的请求及其响应、状态、时间和来源；不被重发覆盖 |
| RequestSnapshot | 原始业务请求与实际发送请求分开；记录是解析后的 HTTP 表示，不承诺逐字节网络包复原 |
| BodyArtifact | 请求/响应体的内存或磁盘引用、编码、已保存范围和完整性；UI 按需读取 |
| DerivedField | DSL 提取结果及来源路径；值、缺失、未就绪、无效和超预算分别表达 |
| RuleSetRevision | 可复现的规则修订；执行记录保存所用修订、命中动作与差异 |
| SavedView | 过滤、分组、时间范围、排序、显示列和字段定义修订；可重算已有记录 |
| RequestDraft / Template | 正在编辑或已保存的待发送请求；环境值在发送时解析 |
| ExecutionRecord | 一次主动发送的结果；保留来源记录、目标和规则修订，不与捕获事件重复计数 |
| InterfaceDescription | 接口说明、识别条件、文档地址/快照时间、手工补充与关联示例 |

网络通信终态（成功、失败、取消、仍在接收）与记录终态（完整、部分、仅元信息、保存失败）分别保存。请求成功不代表本地记录完整。

## 7. DSL 设计方向

### 7.1 表达范围与示意

DSL 面向流量领域，先提供字段访问、比较、布尔运算、集合判断、字符串处理、显式转换、组合键和有限动作。可视化编辑与文本编辑使用同一语义模型，语法错误不能替换正在生效的有效规则。

下例只说明设计意图；`firstNonEmpty`、属性路径及块语法在 M2 定稿，不是可运行配置：

```text
field caller = firstNonEmpty(
    original.query["at"],
    original.headers["at"],
    original.cookies["at"],
    original.json("$.at")
);

route "CGate 切换预发" {
    when original.host == "cgate.zhaopin.com";
    target.host = "cgate-pre.zhaopin.com";
}

view "CGate 调用轨迹" {
    where original.host == "cgate.zhaopin.com"
          and source == "capture";
    within last(30m);
    group by caller;
    timeline by startedAt;
}
```

`caller` 也可由租户与用户编号组合、按域名选择提取路径、或从路径中提取业务编号；不在领域模型中内置 `at` 或 CGate 专用行为。

### 7.2 最小语义要求

- Query/Header 多值保留，DSL 明确选择首值、全部值或聚合；Header 名按协议处理大小写，JSON 属性保持自身大小写语义。
- 缺失与空值不等于解析失败、尚未接收完整或超过预算。回退函数如何处理各状态必须写入语言规范。
- 布尔条件只有明确为真才命中；未知结果单独统计和展示。无法取得身份的请求进入“未提取/未确定”范围，不虚构一个用户。
- 字段依赖能检查循环；正则、JSON 深度、表达式执行、集合规模均有预算与取消能力。规则不提供任意网络、文件或进程执行。
- 展示/统计规则可对保存记录重算，但无法恢复未记录的内容；结果标明规则修订和数据覆盖范围。
- 路由/修改规则在发送前求值，每条请求固定一份规则快照；编辑规则不改变在途请求的执行语义。
- 记录规则、筛选规则和改写规则分别表达；隐藏记录不等于停止采集，预览规则不发送请求。

## 8. 分组、时间窗口与调用顺序

分组支持单字段和组合字段；保存视图可以重复应用到实时记录与历史捕获。每组至少提供请求数、接口数、首次/最后开始时间、错误数与接收中数量，点击后进入组内时间线。

时间语义建议：窗口按代理观察到的请求开始时间归属，使用 `[开始, 结束)`；绝对时间用于展示，单调计时用于耗时，同一时刻以记录序号稳定排序。窗口前开始但仍在接收的请求可作为额外上下文展示，不计入窗口内开始数量。

并发请求显示重叠，流式请求显示持续状态，不能把响应结束顺序当作请求开始顺序。单机观察顺序不证明客户端点击顺序或请求间因果关系；明确的 trace/parent 字段可由后续规则增加关联。

人数统计须有身份语义依据：按动态凭据分组得到的是凭据组数；只有映射到稳定用户身份后才显示去重用户数。所有统计限定为当前捕获和保存范围。手工请求和重发默认独立标记，业务行为视图可以排除它们。

## 9. 请求改写与重发

请求改写先支持精确域名条件和目标映射，再扩展条件化路径、Query、Header 和有界 JSON 修改。默认保留未声明修改的业务输入；目标连接、HTTP Host/authority、TLS SNI 与目标证书校验需要共同验证。Cookie、Origin/Referer、签名或身份对环境的依赖单独表达，域名替换不保证业务身份自动跨环境通用。

规则默认匹配原始请求，按明确优先级执行；路由采用首个匹配规则确定目标，后续非路由动作有确定顺序。不得隐式反复对改写结果重新路由。相同优先级、字段写冲突和动作不兼容应能诊断。运行时失败使用已声明的失败策略；环境映射失败时不静默退回原环境。

手工与重发共用一个请求执行入口：选择原始或当时有效快照 → 修改 → 解析环境变量 → 确定是否应用当前规则 → 展示最终目标和差异 → 明确发送 → 保存结果。解析或预览失败时不发送；发送后超时表示结果可能未知，不自动重试非幂等请求。

每次重发保留新的执行身份、源记录、规则修订与响应，不修改原始捕获。主动请求经过自身代理时要关联去重或明确绕行，避免循环和统计翻倍。请求体没有完整保存时说明缺口，不能把部分文件当成完整请求重发。首版支持逐条手工重发；整段调用自动编排留作候选。

## 10. 流式响应与大资源策略

| 内容 | 处理目标 | 完整性与预算 |
| --- | --- | --- |
| 普通文本/JSON | 有界读取、格式化、搜索 | 超预算提供有限预览；完整文件与预览范围分开 |
| SSE/逐行消息 | 增量解码、消息组装、事件时间线、跟随最新 | 网络块不等于业务消息；跨块字符、行和事件必须正确组装 |
| 图片 | 元信息和受限缩略图，按需查看/保存 | 同时限制压缩体积、解码像素和并发；不在列表中解码全部图片 |
| 视频/文件 | 类型、大小、接收进度、磁盘记录 | 未知长度不伪造百分比；分段关联有依据，不自动承诺完整视频合并 |

响应体记录提供“仅元信息 / 有限内容 / 完整落盘并受配额限制”三类策略，按域名、接口或内容类型配置。完整保存应在内容到达前决定；已转发且未记录的数据不能事后补回。按需保存通常指导出已记录内容，重新下载必须另算一次明确的请求。

传输、记录、分析和 UI 分开控制资源。队列或磁盘跟不上时，依策略停止相应内容记录、标明缺口，并在可行范围内维持转发；客户端速度等协议背压仍然存在，不承诺代理绝不影响耗时。

必须定义的预算包括：单请求内存、单体记录量、捕获总磁盘配额、UI 预览量、事件保留数、图像解码量、DSL 解析与执行时间、索引和分组缓存。M0 建立测量方法，M1/M2 固化默认值；本方案不把未经测量的数值写成性能承诺。

## 11. 接口文档与手工描述

支持结构化定义地址、普通文档网页地址和手工说明。结构化定义先选择一个明确支持范围的 OpenAPI 导入子集；普通网页先提供来源关联与人工摘录，专有文档系统在取得样例后增加适配。能够访问网页不等于能够准确恢复接口契约。

文档信息可以辅助接口命名、字段解释、请求模板和分组；手工补充和导入来源分开保存，刷新前展示差异，不覆盖用户修订。文档版本、获取时间和实际接口版本分别记录。抓包样本只生成草稿，不能仅凭样本判断字段必填性、全部枚举和完整错误集合。

自然语言说明先作为可保存的内容。自动从描述生成定义或规则是后续可选能力，不作为首版依赖。

## 12. 工程边界与待定事项

插件内部建议按代理适配、记录存储、规则语义、查询分析、请求执行、文档接入、UI 投影划分职责。使用真实替换边界上的窄接口，领域逻辑不直接依赖 Titanium 会话对象，UI 不承载转发和解析工作。现阶段不为每项能力预建独立程序集。

Host 提供生命周期、Document/Tool 和公开交互端口；插件负责业务。Standalone 复用插件实现，不能替代真实 Host 的加载、Dock、关闭恢复和依赖隔离验收。工作台命令按需接入，跨插件 Workflow 和独立产品发行留待明确需求后规划。

| 待定事项 | 建议方向 | 最晚处理阶段 |
| --- | --- | --- |
