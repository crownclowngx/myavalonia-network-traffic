## 1. SOLID 具体落点

| 原则 | 本轮设计 | 必须能证明的结果 |
| --- | --- | --- |
| S 单一职责 | 代理适配器解释库回调；捕获服务维护记录；记录器落盘；解析器生成投影；Document 管界面状态 | 修改 JSON 预览不触及监听/证书；调整文件格式不修改 View；MainDocument 不增长为抓包总管 |
| O 开闭原则 | 在内容服务内用小型类型分派选择文本、JSON、SSE、NDJSON、图片；增加格式仅增加对应处理与测试 | 不在网络、存储和每个 View 同时添加 MIME 字符串分支；暂不建设可扩展查看器注册平台 |
| L 里氏替换 | IProxyRuntime、正文读写和存档端口的替身/真实实现遵守同一取消、长度、终态、释放契约 | 替身能产生短读、失败、迟到；真实适配器有同类契约集成测试，不能永远空成功 |
| I 接口隔离 | 只读捕获查询、正文范围读取、存档保存/加载按调用者拆分 | 页面拿不到库会话；Tool 不依赖正文解码；查询不能调用隐式网络操作 |
| D 依赖倒置 | Application 声明 I/O 端口；Infrastructure 提供实现；公开 SDK/控件仅留在组合与 Features | 纯模型、查询、状态/解析单测无需启动 Avalonia、文件系统或 Titanium |

保留现有 IProxyRuntime 和 IBodyRecordSink，扩展前核对全部消费者。只给实际 I/O 替换点增加接口；过滤器、预算计算、状态转换、SSE/NDJSON 组装器使用普通类或纯函数。所有服务由 AddNetWorkTrafficPluginServices 构造注入，不使用静态可变全局状态、ServiceLocator 或 Host 内部服务。

## 3. 最小模型与不可破坏的约束

| 对象 | 必需字段/语义 |
| --- | --- |
| CaptureSession | SessionId、Generation、开始/结束时间、策略快照、预算版本、捕获范围、Observed/Retained/Evicted/Rejected 计数、运行是否中断 |
| TrafficRecord | RecordId、SessionId、单调递增 Sequence、Revision、Source、OriginRecordId、开始/完成时间、单调耗时、请求/响应快照、结构化 Failure |
| RequestSnapshot | 原始/有效 URI、Method、协议、Header 多值序列、Query 原文、BodyDescriptor；规则修订可空，M1 不创建规则 |
| ResponseSnapshot | 可空 StatusCode、协议、Header 多值序列、ContentType/Encoding、BodyDescriptor；尚无响应头时整体可空 |
| BodyDescriptor | Direction、Representation、ObservedBytes、CommittedBytes、ExpectedBytes、BodyId、相对位置、TransportState、CaptureState、Reason、首缺口偏移、摘要范围 |
| ContentViewState | 加载/可用/不支持/无内容/失败、PreviewTruncated、DecodeFailure、预览范围、事件/行淘汰数；独立于网络状态 |
| CaptureFailure | Stage、Kind、可安全展示的中文说明；原始底层异常只保留受控诊断分类，不把认证头/完整 URL 写入错误信息 |
| CaptureQuery | 方法集合、域名/路径关键字、状态码条件、Source、传输状态、开始时间 `[from,to)`、排序方向；不含 DSL |

1. RecordId 唯一且与 URL 无关；重复业务请求必须保留。Source 采用类型化值，M1 正常捕获为 Captured；SyntheticProbe 身份放测试证据，不通过客户端 Header 伪造来源。
2. 原始/有效请求是不同语义，未改写时可共享不可变值；M0 受控映射回归仍必须保存两者。History/Live 属于阅读模式，不能覆盖原 Source。
3. Header 用有序多值条目，不转成 `Dictionary<string,string>` 丢失重复值；名称比较忽略大小写，值和出现顺序保留。Header/URI 超出记录预算只影响记录，不改真实请求。
4. Query 保留原始编码和重复键；拆分为首个 `=` 两侧，区分 `a`、`a=`、缺少键和值。URI Query 的 `+` 不默认当空格，表单内容解码另行采用表单规则；非法百分号序列保留原文和诊断。
5. Cookie 视图从 Header 派生，保留重复项；Set-Cookie 每行独立解析，Expires 中的逗号不是分隔符。解析失败时仍可读原始行，不自动“修复”后回写请求。
6. UTC 用于显示/时间筛选，耗时使用单调时钟；开始同刻由 Sequence 稳定排序。未获得状态/长度/完成时间用 null，不能用 0、空字符串或当前时间冒充真实值。
7. 正文是 HTTP 表示，非逐字节 PCAP。Representation 明确区分编码实体字节、解码实体字节、未知；ExpectedBytes 只能与同层字节比较，原 Content-Length 可另作头字段保留。
8. 索引只暴露 BodyId 与范围；读取端口验证会话所有权和范围，不允许 UI 直接用网络给出的文件名读写路径。

## 4. 运行、传输、保存和预览四类状态

运行沿用 Stopped → Starting → Running → Stopping → Stopped；任一阶段可进入 Faulted，容器释放后为 Disposed。并发同配置 Start 共享一个启动任务；不同配置明确拒绝；停止中的 Start 不排队复活。

每个请求/响应 Body 单独记录：

| 维度 | 状态 | 规则 |
| --- | --- | --- |
| 传输 | Receiving / Completed / Cancelled / Failed | 只由真实传输事实与停止处理确定；无响应 Body 的请求也有明确终态 |
| 保存 | MetadataOnly / Partial / Complete / Failed | 不随 HTTP 2xx 自动完成；None 模式不保留产品记录，内部测量仍可计数 |
| 预览 | 未加载 / 正在接收 / 可用 / 不支持 / 失败，加独立截断标记 | 解析失败不改变传输/保存；截断预览可能对应完整落盘文件 |
| 阅读模式 | Live / SavedSnapshot / Recovered | 历史 Receiving 显示“保存时接收中”，不是活跃网络任务 |

`Complete` 必须同时满足：该方向传输 Completed、写入关闭/提交完成、没有记录缺口、CommittedBytes = ObservedBytes，且已知同层 ExpectedBytes 与 ObservedBytes 相同。空 Body 可 Complete/0，但有正文未记录不能使用这个例外。

网络失败、短读、取消但已有数据为 Partial（记录器正常）；写入/提交失败为 Failed。MetadataOnly 表示未选择保存正文；配额导致未保存也要带明确原因，不能伪装用户选择。预览用省略号不改变文件完整性；文件存在也不证明完整。

终态单调：重复 AfterResponse 或停止后的迟到回调不能重复结束、减两次活动数或更新新 Generation。Crash 恢复不推断 Receiving 已完成，保留原状态并加 Interrupted；保存时已经 Completed 的事实也不能因历史阅读被改为失败。

## 5. 捕获热路径与预算

### 5.1 有界复制和双通道

网络回调只校验身份、复制有界头信息/字节、更新计数并尝试入队；不等待磁盘、UI、JSON 或图像解码。第三方借用内存只在回调内有效，跨回调必须转为自有缓冲区。单个超大块按剩余额度截取，不先复制整块再截断。

正文队列由请求和响应共享，字节与块数双限额，正在写入的块仍计费。一次 TryWrite 失败使该方向正文永久进入前缀记录状态，不接受后续块填出“有洞的完整文件”。终态控制消息独立预留有限名额，不能和正文抢满后静默丢失。

预览通道与磁盘记录分开，持有独立且总量受限的副本。磁盘配额满不会阻塞 SSE 的持续观察；预览队列若丢原始字节，必须停止该流的连续解析并显示 PreviewGap，不能把缺字节后的数据拼为正确事件。已经完成的事件环可淘汰最旧事件，淘汰计数与原始字节缺口分别表达。

元信息更新按 RecordId 合并；一个有限 dirty-ID 集合/游标供页面拉取。游标落后时刷新有限快照，终态权威状态仍在存储中。不建立无限通知队列，不让每一字节触发 PropertyChanged。

完整头信息、事件环与解析结果不随一万条摘要全部常驻：活动流按预算持有组装器，已结束/未选中内容采用受总额约束的缓存并按需释放。重新选中时只从已记录正文重建可得范围；若实时事件曾显示但正文已停止记录，明确提示这段实时预览未保存，不能假装能够从存档重建。

| 项目 | M1 初始默认/硬边界 | 达限行为 |
| --- | --- | --- |

| 摘要保留 | 10,000 个已结束 + 20 个活动；摘要内存总额 16 MiB | 最旧已结束优先淘汰；活动不淘汰，展示淘汰计数；过长列截断展示 |

| 网络正文队列 | 全局 4 MiB + 256 块，包含正在写入块 | 停该方向记录，保留连续前缀与原因 |

| SSE/NDJSON | 每流最近 256 事件且共 256 KiB；单事件/行最多 64 KiB UTF-8，组装最多 65,536 UTF-16 单元 | 环淘汰并计数；超长行/事件丢该条并显式报告，有限扫描到分隔符后可恢复 |
| 内容总内存 | 32 MiB：预览队列、decoder 组装、解析树/事件、图片解码与缓存都纳入 | 原子预留，不按类别各自再占 32 MiB；不足时取消/降级预览 |
| 解压与 JSON | 解压输出每体最多 1 MiB，超过 64 KiB 后限制膨胀比 100:1；JSON 输入/输出各≤1 MiB，深度 64、节点 10,000 | 展示原有限内容和失败原因，不修改转发 |
| 图片 | 首批 PNG/JPEG；编码输入≤4 MiB、源像素≤4,000,000、每边≤8,192；缩略最长边 512 | 先探头后解码；不满足则仅元信息 |
| 图片并发与缓存 | 解码并发 1、等候最多 2；缩略图缓存≤8 MiB，并计入内容 32 MiB | 只保留当前选择的有效任务；释放旧位图 |
| 页面刷新 | 100 ms 合并周期，每页最多一个 UI 投递，每次最多 200 条增量；查询消抖 200 ms | 下一批继续，不塞无界 Dispatcher 工作项 |
| 时间与关闭 | 连接 5 秒、响应头 10 秒、响应空闲默认 30 秒；活跃流无短总截止；退出总截止 10 秒 | 超时明确分类；释放未完成保持 Faulted |

正文磁盘配额不包含用户指定的外部导出目标，但导出必须预估额外空间，复制缓冲固定且目标大小不得超出本次快照已保存字节；目标旁临时副本算该保存任务占用。托管根目录内保存则同时计入根目录配额，不能靠临时目录绕过。

正文内存不是文件大小：Disk 记录 1 GiB 仍只持有固定队列/复制缓冲。满 1 GiB 的单 Body 加元信息超过默认会话 1 GiB，预期为部分记录；完整 1 GiB 探针显式用 2 GiB 会话 profile，并在证据标注，不能隐式扩大默认值。

## 6. 协议、正文与格式处理

### 6.1 代理与 HTTPS

保持 127.0.0.1 显式代理、每次运行新内存 CA、不修改系统代理/hosts/系统信任。接入面板说明监听地址、CA 指纹、信任配置和移除方式；只导出公开证书，不保存私钥。

端口、记录策略及预算等普通偏好可以保存，但保存偏好不保存“正在运行”意图，也不保存测试根或私钥。记录根目录优先使用已核对的公开 SDK 插件数据目录能力，Standalone 注入独立开发目录；若公开 SDK 未提供该能力，显式使用本插件在当前用户数据目录下的专用目录并记录路径。目录不可用时默认有限记录的启动应明确失败，用户可主动选择仅元信息，不能静默改变记录策略。

客户端是否信任属于观察结果：未见客户端 TLS 成功前显示未知；一次成功只证明该连接，不宣称机器全局信任。证书固定/pinning 或不走显式代理的客户端标为不支持/未捕获，不自动绕过校验或改变系统配置。

普通 h1/h2 延续 M0；映射运行仍仅 h1。显示两侧实际协议，重定向作为客户端发出的多条请求保留；不会为了补记录自行跟随重定向。HTTP/3、WebSocket、gRPC 专用解码不在 M1 已支持声明中，按实际观察范围显示限制。

### 6.2 字节层与解码

V3-01 用端点生成的编码体、代理观察字节和客户端结果三方比对固定 API 的语义，写入 Representation。不能假定 `OnResponseBodyWrite` 一定给压缩前或压缩后的字节。请求上传也要独立验证。

保存实际观察到的实体表示和对应编码说明；gzip/br 按表示决定是否解码，保持原 Header 信息但不对解码体再次解压。未知 Content-Encoding 保留原数据并提示不支持。Transfer-Encoding 的 framing 不当正文展示，无法证明层次时预览降级且不比较不同层的长度。

文本首批支持 UTF-8、UTF-16 LE/BE 及 US-ASCII；有效 charset 优先，无声明时检查 BOM，仍未知则对 text/JSON 使用标注的 UTF-8 回退；冲突显式诊断。增量 decoder 保留跨块尾部，结束/中断时处理残余字节并标 DecodeFailure。不通过乱码内容反推合法 JSON。

### 6.3 SSE 与 NDJSON

SSE 字段/换行规则参照 [WHATWG SSE 解析与解释规范](https://html.spec.whatwg.org/multipage/server-sent-events.html#parsing-an-event-stream)（核对日期 2026-09-29）。支持 UTF-8/BOM、CR/LF/CRLF、多 data、event/id/retry 和注释心跳；以空行分派，EOF 半事件不计完整事件。工作台只展示 retry/id，不执行 EventSource 自动重连。

M0 严格 UTF-8 data-only 组件需扩展/替换并保留原边界测试；UTF-8 错误时显示替换字符与诊断，不让解析异常杀死转发。未知字段忽略语义但原始有限文本可查。超预算事件不展示为合法截短事件。

NDJSON 以 LF/CRLF 分行，空行忽略并统计；完整行各自进行有界 JSON 解析。正常 EOF 的非空末行可按完整 JSON 验证，异常/取消结束的末行标未完成。坏行不隐藏后续合法行；超长行在有限内存中丢弃到换行并标缺口。M1 不推断任意流都是 NDJSON。

### 6.4 图片和文件

图片只处理有完整可解码输入的 PNG/JPEG，先核实头部尺寸再分配；解码器若无法在完整像素分配前约束尺寸则该实现不能接入。限并发也限制排队，取消不能强制终止底层解码时仍占用原名额至完成，不靠重复超时创建新解码器。

视频/文件仅展示 HTTP 元信息、接收量与保存量；无容器时长等真实数据就显示未知。206 保存 Content-Range 与本次 Body，不能以单段长度推断整个文件。文件建议名需规整路径分隔符/保留名，仅用于用户导出命名，不影响内部 ID 路径。

## 7. 查询、页面与用户操作语义

| 操作 | 对捕获/存储的影响 | 页面行为 |
| --- | --- | --- |
| 修改筛选/排序 | 不改变捕获，不删除记录、不发网 | 新 QueryRevision；旧结果取消/忽略 |
| 暂停跟随 | 接收/记录/解析继续且遵守同一预算 | 保留滚动锚点，显示新增/淘汰计数 |
| 继续跟随 | 不补抓丢弃数据 | 定位到最新，说明现存范围 |
| 清空当前视图 | 只设置本页起始游标，不清共享存储 | 另一 Document 不受影响；活动记录仍有可见入口 |
| 删除已结束会话 | 仅删除显式选定且无租约的托管文件 | 活动/保存/预览持有租约时拒绝并说明；不得删除外部存档 |
| 关闭最后页面 | 共享捕获继续 | 释放页面计时器、取消源、读取/位图租约 |
| 停止代理 | 停新接纳，取消在途，保留已记录数据 | 所有页面显示同一个终态 |
| 打开存档 | 不联网、不启动代理、不改实时 Source | 独立只读数据源；实时代理若已启动仍独立运行 |

每页只保存有界摘要集合和当前详情；全局元信息服务管理共享缓存。查询在快照 Revision 上计算，实际展示范围标明保留数/淘汰数/元信息缺口。完整路径筛选可通过有限磁盘索引完成，不能只筛已截断列文本却声称搜完整 URI。

详情请求携带 SessionId + RecordId + SelectionRevision；加载、解码后及 Dispatcher 执行时都校验，避免“取消已发生但 UI 委托排队中”覆盖当前页。旧 finally 只能清自己的忙碌状态和取消源。

生产 UI 列表与详情宽屏并列，窄屏切换；停止按钮常驻，错误/限额提示不覆盖按钮。Query/Header/Cookie 默认遮罩常见认证值，点击展开仅作用本页；工作台仍保存真实捕获信息，界面要在保存时说明存档包含这些内容，诊断日志与自动证据始终使用合成样本。

## 8. 本地存储、保存与重开

### 8.1 原生格式与写入

首版采用专用目录结构，无需引入数据库或 ZIP 解压依赖：

```text
capture-<id>/
  manifest.json                 # schemaVersion、快照身份、配额、记录/文件清单及哈希
  records.jsonl                 # 按序有限元信息；每行有 RecordId/Revision
  bodies/<recordId>.request.bin # 内部生成 ID，不能来自 URL/文件名
  bodies/<recordId>.response.bin
```

工作会话允许追加元信息修订日志和稀疏索引；物理日志计入 64 MiB，不无限追加。终态优先持久化，进度按 1 秒或 64 KiB 合并；达到上限可读但标记录缺口。需要压实时先预留临时额外空间，提交前保留旧文件，失败保持可读旧版本。被淘汰且无租约的正文可回收，但只在成功删除后扣除物理占用。

manifest 至少包含 schemaVersion、producerVersion、SessionId、SnapshotId、SnapshotRevision、CreatedUtc、Mode、记录策略/预算版本、捕获范围/淘汰计数、每个文件的相对路径/长度/SHA-256。BodyDescriptor 的摘要标明 committed-prefix 范围；哈希一致只证明前缀完整复制，不证明网络体完整。

### 8.2 一致性快照

1. 短锁内冻结全部所选记录的元信息 Revision、传输状态、成功写入长度和文件租约；网络继续。
2. 单写入者将这些已写字节 flush，形成可读取水位；尚在排队/写入中的字节不进入快照。快照所有权与后续淘汰/删除隔离。
3. 在用户目标的同一父目录创建唯一临时目录。最多一个存档保存任务，固定 64 KiB 复制缓冲，逐文件只复制冻结长度；保存期间追加的数据不进入本次存档。
4. 写 records 和各 Body，校验长度/增量摘要，最后写 manifest 并 flush；同卷改名发布为新目录。M1 默认不覆盖已有存档，名称冲突返回可理解错误。
5. 任一阶段取消/写失败均不报告成功，清理自己的临时目录并归还租约；清理失败登记残留及实际占用。退出总截止到达时保留 recoverable 标记，不阻塞无限等待。

保存十分钟 SSE 不需要等待 SSE 结束。页面展示“快照于某时刻，包含已保存 N 字节”；断流/记录队列截断/用户仅元信息的原因随快照保存。

存档同时冻结预览覆盖/淘汰/缺口计数，正文文件仍是回看内容的唯一依据，不把内存中的实时尾部补接到已截断前缀。重开后只能解析已保存范围，并显示“原实时预览包含未落盘内容”；记录完整性与当时一致，内容可回看范围不得扩大。

### 8.3 加载和异常恢复

加载只支持已声明 schemaVersion；未来版本返回不支持，禁止猜测兼容。限定最多 10,020 个记录、每条元信息 256 KiB、元信息总 64 MiB、目录正文总量按 manifest/profile 且不超过 2 GiB；所有长度先用 long checked 运算验证。

只接受规范化后仍在所选根内的相对路径，拒绝绝对路径、`..`、盘符、UNC、重复路径/ID、符号链接/重解析点及伪造扩展跳转。读取前后检查实际长度，篡改/短读降级对应记录并保留诊断，不直接执行目录中的任何文件。

意外终止恢复扫描受限制：仅已登记/用户显式选定的托管会话；读完整元信息行，尾部破损单列；未提交 manifest 的目录标未完成，不能显示为正式保存成功。网络终态与文件检查分别报告，不做自动补抓或请求重放。

## 9. 生命周期、取消与错误处理

关闭页面 → 撤销本页代次/取消读取 → 解除计时器与订阅 → 释放预览/图片租约；不调用共享 Stop。Tool 隐藏时同样停止 UI 投影工作，重新显示拉新快照。

显式 Stop/插件 Shutdown → 状态进入 Stopping并撤销运行资格 → 停接纳/取消传输 → 终结记录/排空队列 → 在剩余总截止内 flush/关闭文件 → 释放库/证书/监听 → 发布 Stopped。存档读取/保存有自己的用户取消源，但 Shutdown 会加入统一截止；重复 Stop/Dispose 复用同一任务。

页面取消只取消页面等待；不能把点击者 CancellationToken 直接作为共享代理令牌。资源等待不持有状态锁；释放失败保留 Faulted 和未释放对象身份。h2 单流空闲/取消不得终止其他流，必须用集成证据证明；无法保证时缩小明确支持范围并阻止声明 M1 完整通过。

错误采用阶段/类别和安全中文文案：例如“正文记录失败，转发仍在继续”“保存未完成，旧存档未改变”“响应空闲超时，已有内容为部分记录”。禁止把所有异常折叠成空列表、空 Body 或“完成”。

## 10. 性能测量与证据

代理资源使用原独立技术探针，端点/客户端仍在测试进程。补充加载生产 View 的 UI 测量宿主，固定一万摘要、20 并发、5 条流和小图/文件混合负载；不能用只有代理的内存证明整页有界。

测量记录启动/预热基线、250 ms 采样曲线、私有内存/托管堆/工作集、队列、元信息/预览/位图内存、磁盘预留/提交、UI 投递、首次事件时序、保存/停止时间和句柄。M0 原阈值保持，M1 初始代理门槛沿用私有增量≤256 MiB、大小文件中位峰值差≤64 MiB；UI 专项以固定数据量测增量与响应，见验证矩阵。

预算是检查上限，实际峰值和失败记录才是结果；不能从常量值生成测量报告。坏图片、慢盘、解析膨胀与迟到要进入同一资源观察，正常请求快不代表失败路径有界。

## 11. 中文注释与设计思路样例

下面是设计示意，不代表现有方法或可直接编译代码。实施应把说明放在真正维护约束的代码附近。

```csharp
/// <summary>
/// 尝试接纳一段由代理库借出的正文；返回后调用方可立即归还原缓冲区。
/// 这里仅复制预算允许的连续前缀，不等待磁盘或界面，以免记录功能反向阻塞转发。
/// 第一次入队失败后永久停止该方向的文件记录；后续仍统计观察字节，
/// 但不能继续拼接文件，否则会把中间缺块的内容误报为完整正文。
/// 请求和响应共用预算，正在写入的块也必须计费，直到写入或失败清理完成。
/// </summary>
public bool TryRecord(BodyIdentity body, ReadOnlySpan<byte> borrowedBytes);

// 设计原因：取消不能撤回已经排入 UI 队列的委托，因此执行时再核对选择代次。
// 旧读取的 finally 只清理自己的令牌；否则快速切换记录会把新任务的忙碌状态提前清除。
if (selectionRevision != currentSelectionRevision || isDisposed)
    return;

// 这里只提交冻结的已写入长度。源文件仍可能增长，但追加部分不属于本次保存时点。
// 文件摘要覆盖的是这段已提交前缀，不能借“哈希正确”推断网络响应也完整。
```

测试注释说明“故意卡在哪个屏障、制造什么竞争、断言防止哪种回归”；脚本注释说明“为什么拒绝缺证据/旧证据、超时如何只终止本次拥有的子进程”。不为自解释赋值堆砌注释，关键不变量必须详细。
