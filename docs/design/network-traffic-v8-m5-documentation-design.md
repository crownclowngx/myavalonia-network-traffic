# V8 · M5 文档辅助专项设计

> 编写日期：2026-10-03。状态：**待实现的目标契约，不是当前可用能力说明**。
> 配套：[V8-01～18 执行计划](../roadmap/network-traffic-v8-m5-documentation-plan.md)、[V8 专用验证矩阵](../maintenance/network-traffic-v8-m5-verification-plan.md)。

## 1. 核心不变量

1. SOLID 优先；文档获取、解析、合并、匹配、存储、草稿转换与 UI 各有清楚职责。
2. 文档是辅助信息。没有文档、文档损坏或无法获取时，抓包、DSL 分组及既有请求调试继续可用。
3. 获取、识别、应用导入、采用草稿和发送是不同意图。打开页面、选中流量、恢复库、预览差异不能触发网络请求或请求发送。
4. 只有显式获取调用文档 GET；业务请求只走 M4 的显式发送入口。文档导入器不执行脚本，不访问 `$ref`、示例、图片或安全方案中的外部地址。
5. 导入事实、手工修订、绑定和捕获事实分别存储；刷新不能覆盖手工层，不能更改规则、历史、模板、现有草稿或在途请求。
6. 关联结果可解释。无匹配、歧义、失效绑定、未知快照分别显示；不从名称、导入顺序或令牌相似性猜接口身份。
7. 任何内容都先限制输入、展开、保留和显示预算。取消有真实资源收口，旧任务不能写入新页面或新库修订。
8. 只安排本地 Debug 开发验证；不使用 AIFLOW、Windows CI 或发布门禁，发布阶段另行启用。

## 2. SOLID 与朴素职责划分

| 原则 | 本期落点 | 审查证据 |
| --- | --- | --- |
| S 单一职责 | 获取器只取受限字节；Reader 只做格式投影；Matcher 只做只读关联；Merge 只算差异；Store 只做原子提交；Builder 只造建议；ViewModel 只组织交互 | 单测能分别运行，不启动 UI 或代理也能解析、匹配、合并和生成草稿 |
| O 开闭原则 | 来源种类用小枚举，3.0.3 Reader 为明确实现；以后出现第二种真实格式再提炼共用接口 | 不预建自动发现/反射注册/动态导入框架；新增来源不修改捕获转发链 |
| L 里氏替换 | Fake/HTTP 获取器一致区分成功、无变更、失败、取消、超限；Fake/文件库一致执行 CAS、未来 schema 保护和全有或全无提交 | 共用契约测试及真实 HTTP/文件故障测试；Fake 不返回生产端不可能产生的完整成功 |
| I 接口隔离 | `IDocumentSourceFetcher` 接收地址/临时凭据/限制/取消，返回受管理结果；`IDocumentationStore` 提供读快照与 CAS 提交 | UI 不拿文件路径、HttpResponseMessage、数据库或泛型万能仓储 |
| D 依赖倒置 | 应用层依赖上述窄端口及现有 RequestDraft/预算契约；Infrastructure 实现端口，组合根注入 | 不静态取容器，不由 MainDocument new HttpClient，不从 Reader 调用请求发送器 |

预计位置：`Application/Documentation/` 放模型、Reader、引用解析、ImportService、Matcher、Merge、DraftBuilder；`Infrastructure/Documentation/` 放 HTTP 和文件适配；`Features/Documentation/` 放页面与说明面板；`Plugin/` 只注册与收口。先留在现有程序集，不为分层创建多个工程。类名可调整，职责边界不随意合并。

文档库容器共享，页面状态独立。共享服务不得持有 View/ViewModel、Dispatcher 闭包或页面取消源；用小型订阅和可释放句柄通知库修订变化，沿用现有方式，不建设消息总线。

## 3. 数据模型、身份与版本

| 模型 | 最小字段与用途 |
| --- | --- |
| DocumentationSource | SourceId、Kind、Name、地址的持久化安全部分、SourceRevision、LastAttempt、LastSuccess、CurrentImportedRevision；手工来源没有获取时间 |
| ImportedRevision | SourceId、RevisionId、导入时间、源内容摘要、OpenApiVersion、InfoVersion、ReaderVersion、操作投影、诊断和完整性；不可变 |
| OperationKey | SourceId + HTTP 方法 + 原始路径模板；每个来源内唯一，不使用 operationId 作为主键 |
| InterfaceDescription | OperationKey、标题/说明、参数列表、请求媒体类型/示例、响应说明/示例、能力标记；每个字段可追到导入位置 |
| ManualOverlay | OperationKey、OverlayRevision、字段补丁、人工备注、孤立状态；字段按 Inherit/Set/Hide 三态表示 |
| InterfaceBinding | BindingId、BindingRevision、SourceId、精确 Origin、BasePath、启用状态；手工来源同样使用绑定 |
| ImportPreview | PreviewId、SourceRevision、BaseLibraryRevision、FetchGeneration、新投影、Diff、阻断项、过期时间；不包含提交权以外的网络能力 |
| DocumentationMatch | Record/Draft 身份、LibraryRevision、请求快照种类、候选、选中项、匹配依据及不确定原因 |
| DraftSuggestion | 文档来源修订、选定 Binding、字段建议、未满足项、RequestDraft 值快照；没有发送方法 |
| DocumentOrigin | SourceId、ImportedRevision/ManualRevision、OperationKey、OverlayRevision；可附于新草稿/模板，与 Capture 的 RequestOrigin 分开 |

LibraryRevision 只表示一次原子库提交；SourceRevision 是来源配置代次；ImportedRevision 表示已应用文档；OverlayRevision 是手工层修订。OpenAPI `info.version` 只按“文档声明的接口版本”展示，不等于快照时间、库 schema、插件版本或实际服务部署版本。ReaderVersion 在解释语义改变时递增，重解析也必须预览，不静默改变已保存快照。

operationId 缺失可正常导入；重复仅产生可定位警告，禁止按它跨来源合并。方法/路径变更是删旧增新，手工层留在旧键；只有用户明确迁移才复制到新键。路径参数名变化也不能自动搬迁手工字段。

FieldKey 使用位置+原始参数名；Header 名匹配不区分大小写，Query/Cookie/路径字段区分大小写；正文属性使用 JSON Pointer 与媒体类型定位。新增手工字段有稳定 ID，避免以界面行号作为身份。

## 4. 来源获取与网络边界

### 4.1 状态与请求

获取状态为 Idle → Fetching → Parsing → PreviewReady → Applying → Applied；另有 NoChange、Failed、Cancelled、StalePreview。状态属于当前意图，最近成功快照属于持久库，两者并存。错误码至少区分地址非法、认证需要、拒绝访问、重定向待处理、网络/TLS 失败、不支持格式、损坏文档、超预算、提交冲突。

结构化来源支持用户填写的绝对 HTTP/HTTPS 地址，禁止 userinfo、非网络 scheme、CR/LF 与片段作为获取目标；普通网页链接可保留合法 fragment 供浏览器定位。获取使用独立 HttpClient/handler，显式 `UseProxy=false`、不跟随重定向、不用 Cookie/默认凭据、不自动认证、不自动重试；不通过 M4 传输记录器，避免文档 GET 混入真实业务分析。

允许明确填写的内网/回环文档地址，不声称这是公共互联网专用导入器；拒绝当前代理监听地址和解析到该监听端口的别名，避免自代理回环。连接前核对目标并绑定已核对的解析地址，保留 Host/TLS 主机校验；不得以关闭证书验证解决公司文档访问失败。端点、TLS 和重定向证据用真实受控服务产生。

首版使用 HTTP/1.1 请求，保留独立取消；不以此声明其他协议支持。302/307 等显示目标和原因，用户可改来源地址再获取，不自动把临时认证头转给新地址。401/403/429 不重发；429 保留合法重试提示但不启动定时器。断流不把已读前缀当完整文档。

可接受 JSON 媒体类型及在无/错误 Content-Type 下经严格语法检查的 JSON；后者给出警告。HTTP 200 的 HTML 登录页判“不支持/疑似登录页”，不是成功空文档。网络内容编码首版只支持 identity 与单层 gzip；原始与解压后各自限额，手动计费读取，不能先调用无界 ReadAsStringAsync。其余编码明确失败。

用户显式刷新时可以向相同来源发送该来源保存的 ETag/Last-Modified 条件头；304 仅在存在完整已应用快照且地址/身份上下文未变时合法。更新 LastChecked，不更改内容修订或 LastSuccessSnapshotTime；无旧快照的304失败。首版不持久化临时认证上下文对应的 validator，避免跨身份混用。

### 4.2 凭据、链接与持久化内容

需要认证时允许用户输入本次获取的 Authorization 或明确命名的令牌 Header；仅在所属页面内存保存，不放进 Source、快照、日志、诊断或证据。禁止用户控制 Host、Content-Length、Connection、Proxy-Authorization 等协议控制头。无自动登录、SSO、OAuth 跳转或浏览器 Cookie 读取。

源地址中的普通 Query 可以保存；用户标记为敏感的 Query 值转换为必填变量，变量值只在本次获取内存解析，缺值即零网络。UI 保存前展示将保留的地址；日志一律遮蔽 Query 值与认证头。不能自动识别所有令牌，专有签名 URL 如无法安全拆分则只临时获取，不保存完整 URL；重新获取需要再次输入。

导入的描述与示例可能是私有资料，正常保存在本地文档库；不宣称全文已脱敏。只持久化受支持的规范化投影、必要诊断和内容摘要，原始网络字节只在本次有界处理期间保留。摘要用于一致性，不能当作脱敏证明或公开遥测字段。测试只使用合成哨兵，不读真实用户文档/凭据。

普通网页保存来源链接、标题、人工摘录及摘录时间；不自动 GET，不解析 HTML，不加载图片和脚本，不将外部打开成功等同插件已验证可访问。纯手工来源没有伪造的 HTTP 状态或抓取时间。

## 5. OpenAPI 首版支持表

规范核对入口固定为 [OpenAPI 3.0.3 官方规范](https://spec.openapis.org/oas/v3.0.3.html)（2026-10-03 查阅）。它定义路径模板、参数、请求/响应、引用、示例及安全描述。本项目选择以下受限投影和交互约束，**不是完整标准实现，也不把 3.0.3 称为最新版本**。

| 输入 | 本项目决定 |
| --- | --- |
| 根结构 | 仅 openapi="3.0.3"、UTF-8 JSON 对象；要求合法 info/title/version 与 paths；空 paths 可作为明确的空来源预览；严格拒绝重复属性/注释/尾逗号/非法 UTF-8 |
| 方法/路径 | GET/PUT/POST/DELETE/OPTIONS/HEAD/PATCH；TRACE 可展示说明，但 M4 首版不自动生成其请求；path 必须以 / 起始，参数段格式和重复模板歧义可诊断 |
| 名称与说明 | summary、description、operationId、tags、deprecated 作可读文本/标记；忽略扩展字段但登记其存在，不执行 x-* 内容 |
| servers | 操作、路径、根层级提供候选；服务器变量先由用户选择/填写，再校验绝对目标；相对地址只提供待确认候选，缺来源基址时要求手填绑定；不自动选首个 server |
| 参数 | 提取位置、名称、类型、required、description、enum、default 和本地示例；路径层与操作层同位置同名时操作层覆盖；同层重复和缺少路径参数定义为该操作错误 |
| schema | 展示基本类型、properties、items、required、nullable、format、readOnly/writeOnly 及常见约束；保留数值原文精度；不是通用 JSON Schema 校验器 |
| 请求正文 | 读取 requestBody.required、多媒体类型、schema 与内嵌示例；应用到 M4 只支持 JSON、文本和简单 urlencoded，必须用户选择媒体类型/示例 |
| 响应 | 展示状态码/default、说明、Header/schema 和示例；不生成 Mock、不把示例当实际响应，不根据响应 schema 自动断言线上成功 |
| 本地 $ref | 仅当前文档的 `#/...` JSON Pointer；解码 ~0/~1 和合法片段转义，校验目标类型，目标存在才解析；Reference Object的兄弟字段忽略并告警，不与目标混合；缓存节点、检测引用环并限制深度/总访问数 |
| 组合/递归 | allOf/oneOf/anyOf/not/discriminator 与递归分支显示支持受限诊断；不自动摊平、不选分支、不递归生成默认对象；有限展示已知字段 |
| 外部引用/示例 | 相对文件、HTTP、file URI $ref 和 externalValue 仅显示诊断，不读取文件、不联网；可保留来源文字，不能进入可执行目标 |
| 安全描述 | 展示根/操作 security 的需求与覆盖关系；操作显式空集合表示其声明无需求；引用不存在给诊断；不推断真实权限、不登录、不构造认证值 |
| 不支持格式 | YAML、Swagger 2、其他 OpenAPI 版本、XML 文档、压缩包、专有 HTML/脚本；整体明确拒绝并保留原已应用修订 |

“字段可展示”“字段可填入草稿”“整个操作可生成候选”分别标记。可读说明不证明可发送。已知字段的格式/语义错误不得按未知扩展忽略；根必需结构损坏整体拒绝，局部操作错误保留诊断并禁用其自动构造，其余合法操作可在清楚标注不完整的预览中提交。

Reader 保留引用节点身份和访问路径，避免一个公共 schema 被多处引用时复制指数级子树。循环分支显示“递归结构未展开”；不把合法递归一概当坏 JSON，也不绕过预算。解析时间超限或总资源超限是整次失败，不提交被截断的半份导入。

## 6. 手工层、更新和删除语义

有效说明 = 当前已应用导入投影 + 手工覆盖层 + 手工新增字段。覆盖补丁包含三种语义：Inherit 跟随导入、Set 使用明确值（包括空字符串）、Hide 隐藏导入字段。人工备注独立追加；用户“恢复来源值”删除对应补丁，不能靠把值设为空实现。

| 更新情况 | 预览与提交行为 |
| --- | --- |
| 导入字段变更，无覆盖 | 显示旧值→新值，用户应用后跟随新值 |
| 导入字段变更，有 Set/Hide | 显示来源变更和“保留手工修订”；有效手工值不变，可显式恢复来源 |
| 导入操作/字段删除，有手工内容 | 保留孤立项和关联来源，不再自动匹配已删导入操作；可查看、转纯手工或明确清理 |
| 新增接口 / operationId 改名 | 新接口按新身份加入；operationId 改名不迁移 OperationKey |
| 路径或参数名重命名 | 删除+新增，列出待人工迁移项；不依靠名称相似度搬迁 |
| 来源地址/绑定改变 | 使待提交预览、关联缓存失效；不会重写过去的模板和捕获记录 |
| 获取失败、解析失败、取消 | 已应用修订与手工层不变；本次尝试单列失败/取消 |
| 相同内容 / 304 | 不创建假内容修订，更新最近检查状态；保留原快照时间 |
| 两页面同时更新 | CAS 对 LibraryRevision 校验，后提交者得到冲突并重新预览，不能后写覆盖先写 |

导入预览默认整份来源一起应用，不支持把半份修订伪装完整；局部不支持的操作以诊断记录保留。应用前再次验证来源代次、库修订和取消；原子提交一旦成功，后续取消不能把“已提交”说成“未应用”，界面报告已提交修订。

删除来源属于产品中的显式操作：展示受影响绑定及手工项数量，提供“保留为手工来源”或“删除全部”并确认。仍被页面/旧模板引用的 DocumentOrigin 只保留稳定身份和失效说明，不因引用存在重新下载或自动复活来源。保留手工内容时转换与解绑同一次原子提交，失败不丢数据。

## 7. 关联与匹配算法

1. 取得请求身份、版本及可信请求快照；默认按当前所查看的快照关联。旧记录只有 LegacyObserved 时按可证地址查看，不伪造 Original/Effective。
2. 选择已启用且精确匹配 origin 的 Binding；scheme 与规范化 host/有效端口参与匹配，HTTP 与 HTTPS 不混用。目标以用户显式绑定为准，文档托管域名不参与猜测。
3. BasePath 按完整路径段前缀剥离；`/api` 不匹配 `/apix`，不重复拼接文档 paths 与绑定前缀。手工编辑绑定时给出合成完整地址预览。
4. HTTP 方法精确匹配；HEAD 不自动降为 GET。比较 URI 的转义路径，保留大小写、尾斜杠和重复斜杠；只规范化合法百分号十六进制大小写，不解码 `%2F` 为分隔符、不重复解码 `%252F`、不做 Unicode 模糊匹配。
5. 静态全路径优先于模板路径；模板占位只匹配单个非空段。同级多个模板匹配即歧义，不按参数名/字段值或来源顺序猜测。
6. 跨来源多个同样优先级的候选保留多项。用户可以为当前查看选择一个候选；选择只作用于对应请求/修订，若要长期优先则通过显式绑定管理收窄范围。
7. 输出 NoMatch/Matched/Ambiguous/Unavailable 与原因、绑定、来源修订、OperationKey；捕获记录自身不被改写。

Query 值、Cookie、Header 和正文不用于首版自动判别接口；同一方法路径通过 Query 的 action 区分多个业务动作时，允许查看候选和人工选择，不承诺自动识别。匹配结果不是服务端路由执行证明。

索引按 LibraryRevision 建立并有界缓存；只读交换新索引，旧租约完成后释放。流量列表不逐行展开 schema，不为每条请求扫描整个文档库；详情仅解析当前候选。库变化后说明面板提示已更新并重新关联，不更改历史事实或请求编辑值。

## 8. 请求草稿辅助与 M4 接入

### 8.1 支持的转换

| 内容 | 生成建议的规则 |
| --- | --- |
| 目标 | 用户选择 Binding 和 M4 环境；不将 OpenAPI 第一个 server 或文档 URL 自动当发送目标；`${baseUrl}` 按现有 M4 变量语法使用 |
| path | 仅 simple、explode=false 的标量建议；路径变量按单段编码一次，必填未填则候选不可采用；不把 OpenAPI `{id}` 原样交给 M4 当成普通路径 |
| query | 首版支持 form 标量及 explode=true 的标量数组，数组变有序重复键；其他 style、对象或 allowReserved=true 显示需人工输入，不猜序列化 |
| header | 仅 simple 标量，经过 M4 名称/值校验；协议控制头由 M4 处理，Authorization/Cookie 等转敏感占位，不从示例自动复制凭据 |
| cookie | 可展示字段解释；自动构造 Cookie 首版不支持，标记需在 M4 手工处理，不能把未完成身份需求伪装已填 |
| JSON | 用户明确选一个内嵌完整示例，经大小/语法校验复制；无示例不递归生成所有必填字段；存在 readOnly 字段/不支持 schema 时显示逐字段提示并要求检查，不能悄悄过滤而称原始示例 |
| 文本 / form | 文本按 UTF-8；urlencoded 仅平面标量/标量数组，键值交给 M4 编码一次；复杂 encoding 拒绝自动构造 |
| binary / multipart | 仅展示要求，不读 example 路径、不自动打开文件；用户转到 M4 自选其支持的 RawFile；multipart 保持未支持 |
| 示例/default | 作为建议逐项采用，多个示例要求选择；无值与 null/空串/0/false 区分，数值原文不经 double 损失；默认值不是线上服务行为保证 |
| 安全方案 | 展示多个备选/组合需求，用户明确选择；只提供敏感变量名称，不获取认证值；暂不支持的方案保持提示 |

不支持的必填字段不能静默遗漏。DraftSuggestion 列出 MissingRequired、UnsupportedSerialization、NeedsCredential、NeedsManualBody 等；用户可填入支持值，或明确选择“转为空白/部分草稿手工完成”。后一条保留未完成提示，不能标为“已按文档完整构造”。M4 不升级为完整 OpenAPI 校验器，文档约束只在建议页检查首版支持的类型/必填/枚举，实际协议安全仍由 M4 最终校验负责。

### 8.2 采纳与状态保护

Builder 是纯函数，不调用网络、模板库或 UI。建议中的 Method/URL/字段/Body 是值快照；DocumentOrigin 是追溯元数据，不是运行时动态数据源。新草稿有新 DraftId/Revision，默认 ApplyRules=false，不能把文档来源写成捕获 OriginRecordId 或 TrafficSource.Captured；实际发送后仍是 M4 Manual 来源。

采用建议前展示变更摘要；现有未保存草稿提供保留/放弃/取消。接受后走 `RequestWorkspace.Load` 并撤销原预览，用户再编辑、预览、显式发送。禁止文档页面绕过 RequestPreparation 或取得 IRequestTransport。

保存模板由现有明确命令触发，保存未解析草稿与可选 DocumentOrigin；不保存临时认证值或解析后敏感正文。旧模板无 DocumentOrigin 时照常打开，来源删除/不可用也不阻止模板编辑和正常 M4 预览。用户显式“从新版文档创建新草稿”才读取新版，不能点击发送时悄悄更新字段。

M3 规则与双快照分支沿用当前能力检查；M5 不能通过合成有效快照或纯规划器绕过未完成前置。完整端到端验收要等待 M3/M4 真正接入。

## 9. 存储、事务与恢复

独立文档库 schema1 包含小索引、来源/绑定/手工层及不可变导入资产，放在插件受管理 Documentation 子目录。路径由存储适配器按内部 ID 生成，不直接使用 URL、operationId 或接口名；拒绝目录穿越、reparse/symlink 越界。

提交步骤：取得当前修订并构造新快照 → 申请磁盘额度 → 写同目录临时资产并校验 → 写新索引临时文件 → CAS 核对修订 → 原子替换索引 → 通知库变化 → 延迟清理无租约旧资产。失败后旧索引仍可用；孤儿资产下次启动按可证明的引用关系清理，不猜用户文件。

CAS比较与索引替换必须在同一提交临界区内完成；不能“先读修订，再无锁覆盖”。同一容器串行提交，同目录的另一进程/Store实例通过可取消且有期限的排他文件锁互斥；取得锁后重读修订再决定提交，锁忙明确失败，不长时间阻塞UI。此锁只保护本地索引提交，不扩展为通用分布式事务。

当前和前一份已应用导入最多保留两份，另允许有界待提交候选；保留范围用于差异与追溯，不建设无限版本历史。手工层随库提交保存，不因旧导入淘汰删除。全部临时/旧/新资产、索引与原子副本都计入预算；不足时拒绝新提交，不能先清空旧库再写。

现有 ManagedDiskBudget 的 33 MiB 预留服务于原索引等内容，不能假设已覆盖文档库存储；文档索引和副本作为新增消费者显式计费，共享 4 GiB 根上限不变。启动先登记现有占用，再允许抓包/请求资产和文档写入竞争额度。

损坏库保留文件并显示修复/另建库选项，不自动用空库覆盖；未知未来 schema 只读保护且禁止写回。恢复只加载必要索引，不恢复 Fetching/Applying 网络任务、不自动刷新、不恢复临时认证值。旧 M1 存档不附带文档全文，M4 模板仅新增可选来源字段；相应存储 schema 如需升级，须显式迁移并测试旧版和未来版保护。

## 10. 资源、性能和取消预算

以下为本期初始开发上限，需要在 V8-15 的指定设备上测量；不是发布容量承诺。调整必须先说明依据，并同步设计、profile、测试边界和记录，不允许仅为使测试变绿降低要求。

| 项目 | 初始上限/阈值与超限行为 |
| --- | --- |
| 来源 / 操作 | 最多 32 个来源，单来源 1000 操作，全库 10000 操作；超额整次导入拒绝；条目上限不保证一定能容纳超长文本 |
| 获取 | 容器并发≤2，每页/来源同一代次≤1；不排无限队列；Header 10 秒、整次含正文 30 秒；取消真实结束≤1秒 |
| 字节 / 解析 | 传输原始与解压后各≤4 MiB；UTF-8；JSON 深度≤64、token≤200000；解析/投影≤2000ms，超限不提交 |
| 引用 | 引用深度≤16、总访问≤20000、唯一解析节点≤10000；循环标记且停止展开；超总预算整次失败 |
| 单操作显示 | 参数≤128，单说明≤32 KiB UTF-8，单示例≤256 KiB；超字段上限明确诊断，不能静默截断成完整内容 |
| 内存 | 文档消费者子上限24 MiB且从现有共享32 MiB申请；获取/解析每任务≤8 MiB，索引≤4 MiB，展示/缓存合计≤4 MiB；共享不足立即有意义失败 |
| 内存计费 | 原始缓冲、解析节点、字符串、索引和待提交结果在分配前保守计费；UTF-16字符串按至少2×字符数加对象开销，缓存/引用不重复展开；实际私有内存另测 |
| 文档磁盘 | 文档目录总额≤128 MiB，单规范化资产≤8 MiB、库索引≤8 MiB；同时受共享4 GiB根限制；含旧版/临时/原子副本，不给每个源单独128 MiB |
| 预览 / 差异 | 导入预览最多存活120秒；差异≤2000项、计算≤2000ms；超限显示摘要及逐操作分页，不伪称全量详细差异已展示 |
| 匹配 / UI | 10000操作合成库下详情匹配P95≤50ms（≥200样本）；可见字段列表虚拟化、选择仅一个当前面板，UI P95≤200ms/max≤1000ms（≥200样本） |
| 重复挂卸 | 20轮开关页面与获取/解析/提交等待点取消；停止后自有在途任务/临时租约=0，句柄增量≤32 |
| 混合运行 | 600秒，继承V7捕获20+主动4/至少5持续流，同时≤2文档获取，每5秒一次刷新意图、两页面切换；私有内存预热后增量≤256 MiB |
| 全部退出 | Host退出/全部工作区停止≤10秒；记录真实任务/流/租约终止，不以放弃await或隐藏窗口作为释放证据 |

并发阈值是最高接纳值，不保证两份最大文档在共享内存已满时同时成功；必须清楚返回“资源不足，保留旧文档”。纯解析不持有整个 JsonDocument 再另复制无限投影；选择流式 Utf8JsonReader 或同等可计费方式。样本触及每个上限前、等于、超过，并检查已经消耗的字节和时间，而非仅断言常量。

页关闭撤销本页获取/预览资格并取消其任务；关闭文档面板不关闭共享抓包或另一页调试请求。取消发生在原子提交之后时报告“已应用”，发生在提交前时零库变更。UI 入队后的回调仍需验证页面身份、来源代次和库修订；旧 finally 不清掉新操作的 Busy。

## 11. 生产 UI 与交互要求

- 文档工作区提供来源列表、识别/更新预览、接口详情/手工编辑三个主要视图。来源类型、获取状态、最后成功快照和本次失败分开显示。
- 支持新建、编辑来源、获取/取消、应用/放弃预览、绑定目标、手工说明、来源删除处理和创建请求草稿；危险的产品数据删除在 UI 内清楚表达目标及保留选项。
- 捕获详情和 M4 编辑页使用同一说明面板；展示接口名称、方法/路径、匹配原因、来源链接、快照/声明版本、字段/示例和限制。
- 面板阅读不加载外部资源；Markdown/HTML按普通文本呈现，链接单独作为经过校验的用户操作。错误诊断不泄露 Header、敏感 Query 或整份文档。
- 窄屏通过页面切换保留选择与滚动；两主题、三个尺寸测试按钮、焦点、长文本、空态、认证失败、格式不支持、歧义、冲突、孤立项、草稿未完成及取消。
- UI 自动验证使用生产 View 和真实命令路径，Fake 只替代外部 I/O。至少18张截图：上述三个主要视图×两主题×三尺寸；说明面板和 M4 入口另有交互断言。

## 12. 中文注释与设计说明样例

下例是待实现契约的说明样式，不表示仓库已有此方法，也不要求照抄类结构：

```csharp
/// <summary>
/// 计算新导入与手工覆盖叠加后的显示结果。本方法没有网络或持久化副作用。
/// 手工层独立保存，是为了让上游文档刷新后仍保留用户修订；空字符串也是用户的明确选择，
/// 因此必须用 Inherit/Set/Hide 区分“跟随来源”“改为空值”和“隐藏”，不能用 null 合并三种意图。
/// </summary>
public static EffectiveDescription Compose(ImportedDescription imported, ManualOverlay overlay);

// 取消只能撤销尚未提交的意图。原子提交完成后必须返回已提交修订，
// 否则用户看到“未应用”后重试，会误以为旧数据仍有效，并造成不必要的重复变更。
// UI 发布前仍要核对页面与来源代次，避免已关闭页面的成功提示覆盖新页面。
```

重点覆盖：百分号编码与路径段边界、引用环/预算、快照时间与检查时间、手工字段三态、CAS失败、解析后/UI投递后的取消、凭据不持久化、草稿冻结、单次GET与业务发送隔离、门禁固定清单和失败反例。注释应解释原因、失败后果与所有权，避免只把方法名翻译成中文。
