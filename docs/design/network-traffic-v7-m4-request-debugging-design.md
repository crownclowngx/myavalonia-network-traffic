## 1. SOLID 与朴素设计

| 原则 | 具体落实 | 审查证据 |
| --- | --- | --- |
| S 单一职责 | 草稿描述输入；变量解析只产出值；准备器产出不可变候选；协调器管理接纳/取消；传输器发送；记录器保存事实；比较器只读；页面管理交互 | ViewModel 不操作 HttpClient/文件/JSON diff；协调器不包含控件或模板序列化 |
| O 开闭 | 正文种类和对比类型用有限枚举及显式分支；新增格式只扩展对应构造/校验/比较位置 | 不在捕获器和 DSL 内散布 Manual/Replay 特判，不为未来插件式格式搭框架 |
| L 里氏替换 | Fake/真实传输与文件端口对未发送、取消、部分响应、写后未知、提交失败有相同契约 | 共同契约测试加真实端点探针；Fake 同步成功不能替代真实取消释放 |
| I 接口隔离 | 预览只持正文读取和规则规划能力；执行才持传输；历史读取不能发送；存储不提供任意路径写入 | 没有包含所有请求功能的大接口；纯函数不强制套接口 |
| D 依赖倒置 | Application 依赖领域类型、窄端口和 TimeProvider；Infrastructure 负责 HttpClient、磁盘和连接；Features 调用用例 | Application 不引用 Avalonia/Titanium，不使用服务定位器；组合根负责实例寿命 |

使用不可变记录、构造注入、普通 MVVM、枚举与显式状态转移、小范围原子提交。共享协调器是插件容器内服务，不能是静态全局单例。避免抽象基类层级、通用执行管线、状态机框架和消息总线。

中文注释要说明约束及原因。例如：“预览引用不可变正文租约，不能在用户点击发送时重新读取原文件，否则用户看到的摘要与实际发送字节可能不同”；测试注释要说明观测点和错误实现为何会失败，脚本注释说明为什么缺证据必须失败。

## 2. 分层、数据与所有权

```text
Features/Requests：编辑、预览、发送/取消、历史、模板、对比
                   ↓
Application/Requests：草稿校验 / 变量解析 / 请求准备 / 执行协调 / 纯对比
        ↓复用                     ↓窄端口
Application/Rewrite        Infrastructure/Requests：传输、正文暂存、原子库
Application/Content        Infrastructure/Capture：有界记录、内容和存档
```

以下是拟新增或扩展的概念，命名可按代码风格调整，职责与事实不可合并丢失。

| 模型/服务 | 必须包含 | 寿命 |
| --- | --- | --- |
| RequestDraft | draftId/revision、方法、地址、Query/头行、BodySpec、环境引用、规则方式、来源选择 | 每 Document 独立，可变编辑态 |
| RequestOrigin | sourceSessionId/recordId/revision、Original/Effective/LegacyObserved、来源摘要 | 不可变，允许源文件已淘汰；不是发送权限 |
| BodySpec | None/Text/Json/Form/RawFile、内容类型、编码、正文资产引用、完整性 | 不把 byte[]、外部绝对路径长期挂在历史行上 |
| EnvironmentRevision | id/revision、普通变量、敏感变量名称、baseUrl | 保存后不可变；敏感值另存运行期 |
| PreparedRequest | token、draft/environment/rule generation、最终 method/URI/头/BodyLease、内容摘要、expiresAt、预算租约 | 每页最多一个；消费、失效、到期或关闭释放 |
| RequestAttempt | attemptId、preparedToken、origin、source、接纳时间、发送/响应/保存状态、错误阶段 | 一个执行独占；终态不可逆转 |
| RequestResult | 真实 status/headers、TTFB/总耗时、观察字节/保存字节、BodyDescriptor、终态 | 使用 M1 查看器，正文按需读取 |
| RequestTemplateRevision | templateId/revision、未解析草稿、变量名称、正文资产 ID | 无敏感值、无正在执行的 token/句柄 |
| IRequestTransport | 单次发送 PreparedRequest，并报告响应头/受控响应流及发送阶段 | 容器共享适配，单 Attempt 拥有响应资源 |
| IRequestBodyStore | 从授权输入暂存完整正文、按 ID 获取只读租约、删除未引用资产 | 负责路径校验、配额、摘要、原子资产提交 |
| IRequestLibraryStore | 加载/按预期修订原子保存模板、环境与脱敏历史索引 | 文件基础设施；不用通用仓储 |
| IDebugRecordWriter | 建立/更新一个调试记录和完整性终态 | 唯一写入者，UI 只读 |
| RequestExecutionCoordinator | 原子接纳、并发槽、取消、状态、终态和资源归还 | 容器共享，无 View 引用 |
| RequestWorkspace | 草稿、选择、预览令牌、局部忙碌、本页取消及订阅 | 每 Document 独立 |

`HttpRequestMessage`、`HttpResponseMessage`、Stream、Socket 只在基础设施/受控租约内存活。PreparedRequest 中的 BodyLease 对应用暴露受限读取能力；不提供任意路径。实际类型可用普通类实现 IDisposable/IAsyncDisposable，无需每个模型都定义接口。

## 3. 编辑器和输入语义

### 3.1 方法、地址和 Query

- 内置 GET/POST/PUT/PATCH/DELETE/HEAD/OPTIONS；允许符合 HTTP token 规则的扩展方法，保留输入大小写。CONNECT/TRACE、协议升级首版不支持。
- 地址只接受 HTTP/HTTPS 绝对 URI，拒绝 userinfo、fragment、控制字符、反斜线、非法端口和无效转义。不能把片段静默丢弃后发送。
- GET/HEAD 首版不允许非空正文；其他方法可显式选择无正文。None 与“空文本/空文件”分别记录，但网络派生字段按冻结的协议契约生成。
- URL 和 Query 表是同一有序模型。重复键、空值、无等号项保留；无编辑项保持原转义和顺序。表格只对改动的键/值执行 UTF-8 百分号编码，空格 `%20`、加号 `%2B`，不二次转义。
- 修改 URL 后重新解析 Query；表格存在尚未提交的非法编辑时不能把它静默覆盖。诊断说明字段位置和原因，不能退回上个 URL 发送。
- 最终 URI 在准备阶段完成规范化。若生产传输会改变转义或路径语义，V7-02 必须以端点证明可保持，或在预览前明确拒绝该输入；不能宣称支持任意原始 HTTP 字节复现。

### 3.2 Header 与派生字段

头行有顺序、启用开关和重复名称；名称比较不区分大小写，值不做统一 Trim 或逗号合并。非法 token、CR/LF/NUL 均拒绝。传输库无法表示的重复头组合明确诊断，不悄悄丢值。

Host、Content-Length、Transfer-Encoding、Connection、Proxy-Connection、Proxy-Authorization、Keep-Alive、TE、Trailer、Upgrade、Expect、Content-Encoding、伪头和 Connection 指定的逐跳字段不可手工设置；从捕获提取时列出这些被重新派生/移除的字段。主动请求绕行代理，不能将旧代理认证值发送给目标服务。V7 首版不发送 Expect，不提供协议控制字段编辑器。

Content-Type 从正文模式或 RawFile 的受校验媒体类型字段生成，不能同时编辑两份。正文变化后移除 Content-MD5、Digest、Content-Digest、Repr-Digest 等旧摘要，长度由冻结字节计算；业务签名不自动重签，界面显示需用户自行更新的普通签名头。

Cookie、Authorization、Origin、Referer 和业务头可显式填写；不启用自动 CookieJar、默认凭据、认证协商或跨请求隐式继承。401/407 作为一次响应呈现。切环境不保证身份值有效；不自动从宿主登录状态取凭据。

## 4. 环境变量与模板值

### 4.1 语法和优先级

仅支持 `${name}`，名称 `[A-Za-z_][A-Za-z0-9_.-]{0,63}`；`$${` 表示字面 `${`。单次扫描，替换结果不再次解释；变量值内再含占位符作为普通文本，不支持递归、表达式、文件/系统环境读取或脚本。

优先级从高到低：**本次草稿覆盖值 → 所选环境修订 → 模板默认普通值**。同一作用域不允许重名，不存在隐藏全局值；界面可查看每个变量来源。敏感标记在任一来源存在即向下传播，不能用覆盖值把同名变量重新标为可持久化。缺失为错误，空字符串是明确的值，最终目标/字段仍要校验。

baseUrl 是保留的目标 origin 值：仅 scheme + host + 可选 port，无 userinfo、非根路径、query 或 fragment。支持 `${baseUrl}/v1/orders`；不允许把普通变量嵌入 scheme/host/port，避免编码和目标含义不清。URL 也可以直接使用完整绝对地址。

| 使用位置 | 插值规则 |
| --- | --- |
| baseUrl | 校验 origin 后替换一次，再校验完整目标 |
| URL 路径段 | 变量按单个段编码，`/` 编成 `%2F`，不能注入路径层级 |
| Query 表键/值、URL 中 Query 值 | 先解析占位符及原始片段，再按组件编码；保留未编辑原始项 |
| Header 值 | 字符串插入后做协议字符和大小检查；不编码成 URL |
| 文本正文 | 按字面字符串插入，再 UTF-8 编码和计费 |
| JSON 正文 | 只在 JSON 字符串值内插值，由 JSON 序列化器转义；不在属性名、裸数字/布尔/null 位置插值 |
| urlencoded 表单 | 对解码后的键值插值，再编码一次；空格用 `+`，字面加号 `%2B` |
| RawFile | 不替换内容或外部文件路径；文件选择独立完成 |

JSON 中 `${count}` 即便为数字字符串，也保持 JSON string 类型；需要数值时直接编辑合法 JSON 数值。本期不建设类型化变量表达式语言。

### 4.2 敏感值和落盘

Authorization/Cookie 及用户标记的值默认敏感；从记录提取时将支持的敏感位置转为必填变量，Proxy-Authorization 按保护头规则直接移除。不能根据字段名识别所有私密数据，因此界面必须允许用户将 Query/Header/正文变量标为敏感，并在保存前显示实际保存内容范围。

运行期敏感变量存放在页面内存；PreparedRequest/Attempt 持有执行所需内存快照，终态后释放该执行的引用，页面输入在用户清除或关闭时释放。包含这些变量的最终文本/JSON/form正文也使用有界内存租约，不能交给文件暂存器落盘；RawFile不做变量插值。取消/关闭清理引用和自有字节缓冲，不承诺托管字符串可以被物理抹除。敏感值清除或替换使相关预览失效，不允许清空后继续发送旧 token。

普通环境值可以持久化；敏感变量仅保存名称和标记。模板不保存解析后的 URI/Header/Body。自动历史默认不持久化原始请求/响应正文，URI只保留origin及能证明不含敏感值的静态路径，Query值和敏感路径段遮蔽；规则变换后无法追踪敏感来源时隐藏整个path/query，头值脱敏。敏感内容不得进入日志、异常、ToString、测试 JSON、文件名或摘要身份字段。内部正文 SHA-256 用于冻结校验，不当作脱敏手段对外导出。

调试请求的文件型元信息日志同样使用上述脱敏投影，不能以“只是临时journal”为由写入明文变量。敏感请求正文不交给磁盘记录器，执行结束后记录为“敏感正文未保留”；后续重发需要重新填写变量。服务器响应和用户自行选择的文件仍可能含私密原文，按明确的内容记录策略处理；不能据此承诺所有网络内容只在内存或已被通用脱敏。

显式“保存调试记录”沿用存档机制，可能包含用户选择的原始正文/响应；保存前在产品中说明其范围。此说明不等于当前编写文档需要用户再批准。历史元信息不因保存失败重发请求。

## 5. 正文、文件和完整性

| 类型 | 首版契约 |
| --- | --- |
| None | 已明确无正文，与未捕获正文区别处理 |
| Text | UTF-8；最多 256 KiB；Content-Type 默认 text/plain，可选合法文本媒体类型 |
| JSON | 严格 UTF-8、无 BOM/注释/尾逗号/重复属性；最大深度32、token16384；不经 double 损失数值精度 |
| Form | application/x-www-form-urlencoded，UTF-8，有序多值；保留重复键和空值 |
| RawFile | 单个有限文件，最大64 MiB；流式暂存、已知长度、完整摘要，默认 application/octet-stream |

multipart、压缩请求实体、未知内容编码、无限上传和仅有正文前缀的请求不自动转为支持类型。完整 identity 二进制捕获体可转 RawFile；完整文本/JSON/form 选择对应编辑模式，超过编辑额度可按受支持原始文件处理。`Representation=Unknown` 或 DecodedEntity 无法证明发送实体含义时拒绝直接重发，允许用户显式提供新正文。

正文是否完整至少核对：请求方向传输终态、捕获完整性、编码表示、期望/观察/提交字节、文件存在和摘要。Content-Length 缺失不能单独证明有正文或无正文；传输为 Complete、观察字节为0且其余事实一致才能判为无正文。响应完整不证明请求完整。

暂存步骤：申请磁盘额度 → 流式复制到专用目录临时文件 → 在读取过程中计费与计算摘要 → 检查源是否在复制中变化/截断 → 完整后原子提交资产 → 返回只读租约。不可重开原始用户路径作为发送体。发现源变化时要求重新选择；即使无法锁住原文件，也必须保证预览与发送都使用同一个已冻结资产。

正文资产内容地址/ID、长度与完整性成为模板/预览引用；暂存、模板与执行可以共享只读资产引用，但要引用计数。删除模板不删除仍被执行持有的资产，取消也不能提前复用仍在网络写出的缓冲。失败只清理本次受管理临时路径，清理前检查位于对应根目录且拒绝 reparse/symlink 越界。

## 6. 原始/有效快照与规则应用

来源选择与规则选择是两个正交维度：

| 来源 | 不应用当前规则（默认） | 显式应用当前规则 |
| --- | --- | --- |
| 手工草稿 | 发送解析环境后的用户输入 | 对解析后的用户输入运行一次冻结修订 |
| Original | 编辑冻结原始快照后发送 | 对编辑后的原始输入运行一次当前修订 |
| Effective | 编辑当时已生效快照后发送 | 作为新输入再运行一次当前修订；界面明确这会再次改写 |
| LegacyObserved | 仅在旧记录足以证明观察输入时提供 | 同上，但不能冒充 Original/Effective 来源 |

旧 schema1 只有一份头/正文，不能因 OriginalUri/EffectiveUri 两字段存在就推导两套完整请求。URI 不同或其他事实不充分时原始/有效选项均不可用；显示缺少哪些事实，用户可以手工重建新请求，但不能保留“精确原始重发”的承诺。

所有 M3 表达式针对**这次解析后的输入快照**求值；来源原始快照和本次执行输入各自保留，不把历史规则再次隐式应用。M3 规划器复用现有 block/冲突/一次路由/正文预算；例如 64 MiB RawFile 遇到依赖正文的规则会按 M3 256 KiB 限额阻断，不能跳过规则继续发送。

产品规则能力以 M3 接入完成状态为前置；不可用时禁用并说明原因。纯规划单测不授予产品启用权，完整 M4 门禁也不能因主动客户端可读取自有 Body 而跳过 M3 真实能力。

## 7. 预览与发送一致性

准备顺序固定：

1. 冻结草稿 revision、所选来源和受支持完整正文资产。
2. 固定环境/本次变量代次；按字段上下文替换一次并校验。
3. 决定规则模式；若应用，冻结当前可用改写修订，对本次输入规划一次。
4. 派生协议字段；检查最终 URI、头、正文和目标约束，形成不可变候选。
5. 生成 PreparedRequest token、正文摘要、代次、到期时间及只读差异；没有网络发送。

预览显示：来源与快照种类、环境/规则修订、最终 method/URI、最终头和正文摘要/有限内容、改变/移除字段、敏感值状态、协议、规则执行次数。默认遮蔽敏感值，可按用户操作临时查看，不记录到自动日志。

草稿、环境、敏感变量、正文资产变化，以及页面关闭/令牌到期，均使预览失效；选择应用规则时还检查所选规则/启用代次，不应用规则的请求不受无关规则切换影响。发送前通过同一原子接纳点核对这些代次、所有权和预算并消费 token；失效则要求重新预览，不自动使用新规则/新环境发送。

接纳后修改草稿、规则或环境不改变在途 Attempt；在途使用冻结字节和修订。运行期目标检查仍可拒绝危险/自代理目标或失败连接，但不能悄悄替换 URI、重跑规则或回到来源环境。检查拒绝要记录阶段。

DNS 解析不作为 HTTP 发送，但“预览”首版也不触发 DNS/HTTP；实际连接时校验地址。需将已校验目标地址用于同一次连接，并保留最终主机的 Host/TLS 校验；具体公开适配路径由 V7-02 证明。若无法固定连接地址，不以一次 DNS 预检声称避免了别名或解析变化形成的自代理回流。

预览一致性指已声明 method、最终 URI、可控头及正文语义/字节一致。HTTP framing、传输库头名大小写等实际派生信息记录在发送元信息中；不宣称等同重放原 TCP 字节流。

## 8. 发送协议与结果状态

### 8.1 主动传输

拟使用已有 .NET HTTP 客户端能力，由单独适配器封装；V7-02 先核实并测试具体配置。固定 HTTP/1.1，不经系统或本插件代理，禁用自动重定向、默认凭据、CookieJar、自动认证和应用级重试。默认保留 TLS 证书验证；测试仅向隔离客户端注入受控测试信任，不安装系统证书。

允许普通局域网/回环受控服务，拒绝目标为本插件监听端点，包括 localhost、IPv4/IPv6、别名、多地址和解析变化；不能简单禁止所有 localhost 导致测试与本地接口不可用。不得向真实业务端点加内部去重 Header。

HTTP 客户端可能存在连接级行为，不能仅凭“不写重试循环”证明一次发送。探针覆盖复用连接断开、上游在收头后断开、302/307、401/407、发送中断；目标端点按 Attempt 的测试关联记录收头次数。若库会透明重复应用请求且无法通过公开配置/适配避免，V7-02 判为阻断。

按响应头到达即返回的模式读取响应流，沿用 M1 的有界记录和 SSE/NDJSON 解析；不先 ReadAsString/ReadAsByteArray 把整个响应读完。gzip 等响应仅按既有有限解码能力展示，实体记录与解码预览分别标记；自动解压配置不得让 Content-Encoding、长度与保存事实不一致。

### 8.2 一次执行与终态

```text
Draft → Preparing → Ready
Ready --原子接纳并消费 token--> Accepted → Sending → Receiving → 终态
Ready --编辑/到期/关闭--> Invalidated
任何发送前拒绝 → NotSent
进入真实传输后的取消/超时/连接故障 → 按已知事实标记，可能 OutcomeUnknown
```

一个 token 最多接纳一次，重复点击返回同一 Attempt 或“已接纳”。终态后“再次发送”必须产生新的预览/token/AttemptId；相同 URL/正文的两个明确意图是两次合法请求，不能被全局哈希去重。

应用端至多一次调度不等于远端业务 exactly-once。应用不能证明上游业务是否已经提交时，保留未知；不自动重试 POST，也不自动重试 GET。

| 事实维度 | 值及表达 |
| --- | --- |
| 发送状态 | NotSent / DispatchStarted / ResponseHeadersReceived；进入适配器后不能仅凭异常猜测零字节 |
| 传输状态 | Receiving / Completed / Cancelled / TimedOut / Failed / Interrupted |
| HTTP 结果 | nullable status；4xx/5xx 是已取得 HTTP 响应，不是“没有响应” |
| 远端业务结果 | 通用调试器不推断业务成功；无可信完整响应时显示“结果可能未知” |
| 保存状态 | Complete / Partial / MetadataOnly / Failed，与网络终态独立 |

发送前校验失败或接纳前取消可证明 NotSent；已进入网络传输后取消/超时不得标“服务器未执行”。收到响应头后读流失败保留 status、头和已观察字节，显示响应不完整。记录磁盘失败不重发、不中断已取得事实，不将 HTTP 200 伪装成正文保存完整。

取消要实际中止请求、读取和清理；超时用单调时间。连接/响应头最长30秒，正文无数据空闲60秒，单次执行总寿命30分钟；SSE 心跳字节计入活跃。限制可在将来调整，但本期固定 profile 并测试，不偷偷沿用普通 HttpClient 默认总超时打断流。

## 9. 来源、记录、历史和持久化

### 9.1 独立调试记录会话

Manual 与 Replay 使用单独调试记录会话，不替换当前抓包 session，不依赖监听器是否启动。复用最小记录写入/内容组件和共享配额，不能复制一份有不同完整性语义的记录器。

每次执行只建立一条权威记录：AttemptId 唯一，Manual 的 OriginRecordId 为空；Replay 记录直接来源 record/session/revision 和 snapshotKind，链式重发只引用直接前驱，不递归执行。源已淘汰则保留身份并显示“来源内容不可用”；新旧记录相互独立。

捕获默认视图和 M2 分析默认 Sources 为 capture；新增手工来源不能通过原来 `Source=null` 的默认路径意外混入。旧 SavedView 未写 sources 时仍解释为 capture，显式选 all/manual/replay 才包含主动请求；Coverage 显示排除数。摘要、DSL source 名称和持久化枚举同时扩展。

### 9.2 模板/环境库

独立调试库 schema=1，不与捕获存档 schema 共用版本。资产路径按受管理 ID 解析；采用同目录临时文件 + 校验 + 原子替换，CAS 检查预期库 revision，冲突不覆盖另一页的新修订。

模板保存未解析结构和变量引用。RawFile 模板要先把完整资产纳入持久化配额，提交失败不出现“有索引无正文”；只保存外部绝对路径不算成功模板。无引用资产延后清理，仍持租约资产不能删除。敏感值不入库；下一次打开要求重新填入。

损坏 JSON、缺资产/坏摘要、未来 schema、非法路径/符号链接和配额不足分别诊断；保留旧可用库，不在打开失败时自动写空库。

### 9.3 历史和重启

自动历史最多保留脱敏摘要及关联，允许记录的正文仅当前受配额调试会话保留，可能使用临时磁盘；它不是可恢复的历史正文。插件正常退出清理该调试缓存，下次启动只清理经根路径/资产引用校验的遗留临时文件，不误删模板资产或显式存档。关闭重开后未保存的正文显示“未持久化”，不能用缓存前缀生成新可执行草稿。用户明确保存的快照可通过存档读回完整性事实；敏感请求正文未保留时存档也不能补造它。

进程退出时还在执行的历史恢复为 Interrupted，并按最后发送事实标未知；不自动重新发送、重新启用规则、重新选中敏感环境值或启动代理。持久化 Attempt 摘要在接纳/发送阶段先记录意图；若崩溃边界无法证明发送未发生，恢复采用保守未知，不能伪造 NotSent。

捕获存档的 M3 双快照 schema 目前未落地。V7 实施时以实际 V6 schema 为基础另行确定是否需要升版，不提前声称已经有 schema2/3。旧 reader 遇到不支持版本应明确拒绝，不能错误恢复为 Captured；新 reader 读旧版保留未知。

## 10. 对比语义

对比对象是两份冻结记录修订/结果 ID，默认来源与本次执行，也允许用户选择另外一次历史结果。请求差异与响应差异分开，读档/对比不调用发送器。

| 内容 | 比较方式 | 完整性限制 |
| --- | --- | --- |
| 方法、最终 URI、规则/环境 | 显示旧/新及字段变化，Query 按有序多值 | 保留原始转义；不把相同解码值一概视为相同发送 URI |
| Header | 名称不区分大小写，重复值保持序列；无默认忽略 Date 等字段 | 不把多个 Set-Cookie 合成一行；遮蔽值显示“敏感值未比较” |
| status/耗时/大小 | 显示两侧真实值和有依据的差值 | 未取得值显示未知；不以一次耗时差宣称性能改进 |
| 文本 | 严格受支持编码，按行对比，保留换行差异说明 | 任何一侧截断/解码失败时不显示“全文相同” |
| JSON | 对象属性顺序忽略、数组按下标、类型敏感；拒绝重复属性，保留数值精度 | 无完整 JSON/超深度预算转为有限文本或不可比较，并解释原因 |
| 二进制/文件 | Content-Type、完整性、长度及完整实体摘要 | 只有两侧完整且摘要可信时报告内容摘要相同；前缀摘要不证明全体相同 |
| SSE/NDJSON/在途 | 冻结当前已保存片段进行显式比较 | 显示截取时刻和部分范围，不把快照标作终态全文 |

diff 限定输入字节、行数、节点、操作数和期限；不采用未限制的 O(n²) 大矩阵。可以用有预算的逐行匹配，超限提供两侧有限文本及不可完整比较原因，不为视觉效果放大内存。

## 11. 预算、资源与寿命

以下均为**初始开发验收阈值，尚无 V7 实测结果**。实现时写入 `m4-profile.json` 并用边界测试核对；调整需同步设计/矩阵与理由，不能事后只改报告阈值。

| 项目 | 首版上限/目标 | 超限或退出行为 |
| --- | --- | --- |
| URI/头 | URI8192字符、头256行/64 KiB，沿用 M3 上界 | 准备失败，零发送 |
| Query/form/变量 | Query256项、form256项；每作用域64变量，每值4096字符 | 定位诊断，不截断发送 |
| 编辑正文 | Text/JSON/Form 编码后256 KiB；JSON深度32/token16384 | 拒绝或用户显式改用受支持 RawFile |
| 文件输入 | 单体64 MiB，暂存总256 MiB | 复制前预留，读中复检，失败清理 |
| PreparedRequest | 每页1个、容器最多4个，120秒到期 | 新预览替换旧租约；发送后租约转交 Attempt |
| 并发发送 | 每页1个、全容器最多4个，无后台等待队列 | 忙碌明确返回；不挤掉已在途请求 |
| 内容内存 | 沿用全容器32 MiB；每准备/比较操作最多预留4 MiB | 与 M1/M3 共享，不额外给每页32 MiB |
| 请求草稿/库投影 | 容器合计16 MiB，模板200个、环境50个 | 拒绝新增并解释；历史行不持正文数组 |
| 记录/磁盘 | 沿用元信息64 MiB、每会话2 GiB、根目录4 GiB；调试/暂存/模板资产纳入同一根额度 | 不扩大 M1 配额；响应记录降级不影响发送事实，模板提交失败保留旧库 |
| 自动历史 | 最多1000条且索引≤8 MiB；分页展示 | 只淘汰终态摘要，不移除在途执行资格 |
| 模板资产 | 合计≤256 MiB，计入根额度 | 持租约资产不删除，达到上限保存失败 |
| 对比输入/结果 | 每侧256 KiB、4000行、JSON16384 token、100000操作、差异500项 | 标记部分/不可比较，不静默等同 |
| 对比并发/期限 | 每页1项、容器2项、2000ms | 取消并保留旧结果，不无限后台排队 |
| 请求期限 | 连接及首响应头30秒、读体空闲60秒、总寿命30分钟 | 记录阶段；有发送可能即未知，不重试 |
| 取消/退出 | 取消后1000ms内业务/资源收口；Host全部停止≤10000ms | 真实任务必须结束，不能只放弃 await |
| UI | 至少200样本，P95≤200ms、max≤1000ms；两主题×三尺寸 | 留原始采样，超限失败 |
| 资源回归 | 600秒混合运行、20轮挂卸；私有内存增量≤256 MiB、停止后句柄增量≤32 | 复用 M1 测量方法，观察持续增长和归零 |

代理20在途与主动请求4在途是两组并发上限，混合负载按最高24个验证；共享内容/根磁盘限额不相加。录制队列继续使用既有4 MiB上限，记录量最大10000按原会话策略执行。资源测试同时观察租约真实归零、输入/响应流释放和后台任务退出。

单页关闭：取消该页准备/发送/比较、释放订阅与预览，另一页保持；调试会话保留已取得结果供历史查询。停止代理：只停代理链，不取消独立调试请求。Host退出：取消全部请求并等待实际清理，同时按既有协议停止代理；容器Dispose是幂等兜底。

## 12. 生产 UI 和中文反馈

桌面宽屏用输入/结果分栏，800×600收紧表格与操作区，520×420改用“编辑/预览/结果/历史”切换；发送/取消、最终目标、来源与完整性始终可找到。沿用宿主主题资源，不硬编码一套颜色。

地址栏提供方法、环境、规则方式；参数/Header/Body用显式页签，预览区域列出最终目标和变化。发送只对当前有效预览可用；执行中可查看结果和取消，本页编辑不改变在途请求。再次发送需新预览，不能在载入模板、切页、选择历史或恢复窗口时触发。

诊断至少区分：输入非法、变量缺失、正文不全、规则不可用/阻断、预览失效、并发已满、目标拒绝、未发送、发送后结果未知、响应部分保存、模板冲突和对比不完整。信息显示在发生操作的区域，不能把所有错误堆成一个全局“请求失败”。

请求列表/时间线右键提供“提取为调试请求”；原始/有效选择依据事实启用。历史显示 Manual/Replay、来源定位、规则修订、状态、时间、完整性；不把HTTP错误和保存错误混成同一图标。所有关键输入有标签、键盘顺序和错误定位，窄屏仍能完成闭环。
