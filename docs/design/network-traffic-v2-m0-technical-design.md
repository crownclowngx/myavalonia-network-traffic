## 1. SOLID 如何落实

| 原则 | 本阶段约束 | 审查证据 |
| --- | --- | --- |
| S：单一职责 | 运行编排、库适配、路由决策、有限记录、界面投影分开 | Document 不解析 HTTP；适配器不决定页面寿命；记录器不改网络目标 |
| O：开闭原则 | 将 Titanium 放在一个适配边界；路由先用纯函数，后续 M3 替换决策来源 | 新增路由条件不修改启停和 UI；不预建通用插件引擎 |
| L：里氏替换 | 替身与真实 runtime 对取消、状态、错误和释放遵守相同契约 | 公共契约测试 + 真实端点测试；Fake 不能把失败变为空成功 |
| I：接口隔离 | 控制运行、接收有限记录分别提供窄边界 | UI 不拿证书管理器/网络会话；记录器不要求实现代理控制 |
| D：依赖倒置 | 应用编排依赖插件自有契约；基础设施实现它；组合入口选择实现 | Application/Features 不引用 Titanium 类型或 Host 内部类 |

使用适配器是为了隔离第三方库变化，使用协调器是为了保证单一运行所有权；它们都是普通类。无真实替换、I/O 或独立测试需求时，直接使用具体类；不做每类一个接口，不用继承层次模拟状态机。

## 2. 代码位置、依赖方向与所有权

以下保留最初分层建议，实际文件以[当前运行说明](../reference/network-traffic-m0-runtime.md)为准；保留现有三个项目的职责，为隔离测量只新增一个开发探针宿主，不拆业务程序集。

```text
src/NetWorkTrafficPlugin.Plugin/
  Application/Proxy/
    ProxyContracts.cs             # 插件自有状态、选项、失败和观察模型
    IProxyRuntime.cs               # 真实代理 I/O 边界
    ProxySessionCoordinator.cs    # 启停、运行代次和有界收口
    RouteTargetResolver.cs        # 原始地址到有效地址的纯决策
  Infrastructure/Proxy/
    TitaniumProxyRuntime.cs       # 第三方 API、网络事件和错误转换
    ProxyCertificateFactory.cs   # 创建运行所需证书，明确所有权
  Infrastructure/Capture/
    BoundedBodyRecorder.cs        # 有界队列、前缀落盘和记录结果
    IBodyRecordSink.cs            # 写入/完成/取消边界，便于注入慢盘和失败
  Features/Main/                 # 既有 Document/View 的最小诊断投影
  Features/ProxyStatus/          # 插件级状态 Tool，提供显式停止
  Plugin/                       # 复用既有唯一组合入口
tests/NetWorkTrafficPlugin.Tests/
  Proxy/                        # 状态、决策、有限记录、组合与生命周期
  Integration/                  # 实际代理、TLS、h2、SSE、A/B
  Resource/                     # 独立进程运行的大文件和持续流
  Fixtures/                     # 端点、生成器、受控证书、时间/同步夹具
tools/NetWorkTrafficPlugin.TechnicalProbe/
  Program.cs                    # 仅承载生产代理的独立测量进程，不进入插件交付
```

`Features → Application`，`Infrastructure → Application`，`Plugin` 组合二者；Application 不引用 Features、Titanium 或 UI 调度器。若 `IBodyRecordSink` 被应用层消费，接口移到 Application 契约目录，不能出现 Application 反向引用 Infrastructure；文件位置服从实际依赖。

| 对象 | 生命周期与释放者 |
| --- | --- |
| `ProxySessionCoordinator` | 每插件服务容器一个；容器/公开 Host 寿命入口关闭，不跨容器静态共享 |
| `TitaniumProxyRuntime` | 协调器每个运行代次拥有一个实例；启动失败、停止、容器退出均归还 |
| 第三方监听器/上游连接/回调 | runtime 创建和释放；只订阅一次，释放后无活动监听 |
| 活动请求与运行取消源 | 属于运行代次；请求完成/取消后释放，不挂在 Document 上 |
| 记录器与缓冲区 | 属于运行代次；分块所有权只能转移一次，写完/拒绝入队/取消均归还 |
| Document | 每次打开的 Scope；只释放自己的订阅、显示缓存和等待令牌 |
| 状态 Tool | 按公开 SDK Tool 生命周期；读取同一状态，不拥有监听器 |
| 端点、测试根证书、探针目录 | 每轮夹具拥有，finally 清理；不访问真实用户数据 |

Standalone 必须通过 `AddNetWorkTrafficPluginServices` 解析对象；不保留当前手动构造 Document 后又另建代理的路径。SDK 已确认公开 ShutdownAsync 入口并接入；实际 Host 是否按契约调用仍需 H03 联调。

## 3. 最小契约与状态机

### 3.1 数据契约

| 模型 | 必要字段/语义 |
| --- | --- |
| `ProxyOptions` | 回环监听地址/端口、显式代理模式、协议策略、证书配置、探针预算；启动时复制成不可变快照 |
| `ProxyStatus` | State、RunId、Generation、实际监听地址、错误摘要、活动请求数和截断计数；不持有库对象 |
| `ProxyFailure` | Stage、Kind、可供中文展示的消息、RequestId；启动失败/证书失败/上游失败/取消/记录失败分开 |
| `RequestObservation` | RunId、Generation、RequestId、Source、原始/有效 URI、开始/完成时间、两侧协议、路由版本 |
| `RouteDecision` | 原始目标、有效目标、Matched、Reason、Revision；一请求一个不可变决定 |
| `BodyCaptureSummary` | ObservedBytes、StoredBytes、ExpectedLength（可空）、CaptureState、TransportState、截断/失败原因和有界文件索引 |
| `ProbeOutcome` | 场景 ID、输入条件、实际测量、断言结果、错误与证据位置；不能用日志字符串代替结构化状态 |

请求头保留重复值，不用一个字符串字典把多值头压扁；原始路径/Query 不先解码再拼装。Source 在 M0 使用合成探针标记，预留后续真实捕获/手工请求身份，不写死公司字段或 `at`。

记录完整性与传输终态正交：`CaptureState = MetadataOnly / Partial / Complete / Failed`，`TransportState = Receiving / Completed / Cancelled / Failed`。未知长度在 EOF 前没有总量或百分比；正常完成且所有字节确实存下才允许 Complete。传输完整而记录截断是合法组合；200 状态码不能自动推出记录完整。

### 3.2 启停与取消

`Stopped → Starting → Running → Stopping → Stopped` 是成功路径；启动或运行不可恢复错误进入 Faulted，Dispose 最终进入 Disposed。重试启动只允许在旧资源确认释放后进行。

| 输入/竞争 | 契约 |
| --- | --- |
| Running 时同配置再次 Start | 返回同一运行快照，不新建监听器 |
| Running 时不同配置 Start | 明确拒绝，要求先停止；不偷偷修改在途配置 |
| Starting 时重复 Start | 合并同配置等待；一个等待者取消不终止其他等待者的启动 |
| 预取消 Start | 不产生运行或任何外部副作用 |
| Starting 时 Stop | 使该代次失效并取消启动；迟到成功执行回滚，不发布 Running |
| 多个 Stop | 共享一次收口操作；资源只释放一次 |
| Stop 等待者取消 | 取消当前等待，已经接纳的停止过程继续；不能留下无人拥有的代理 |
| Stopping 时 Start | 返回“正在停止”，完成后可显式重试 |
| Faulted 后 Start | 先确认监听/任务已清理；残留未解除则拒绝重新启动 |
| Dispose 与任意操作竞争 | 先使运行失效，停止并释放；后续 Start 拒绝，Stop/Dispose 保持幂等 |

协调器用一个短临界区管理状态和任务身份，锁外执行真实启动/停止与等待。用 Generation/RunId 校验结果和通知；不用大锁包住网络 await，不在 UI 上同步等待。

每个独立等待者的令牌与运行令牌分离。启动一旦被接纳，寿命归协调器；页面关闭仅退出等待。显式 Stop、容器退出或运行故障才结束运行。异常任务必须被观察；通知订阅者异常不能反向打断转发。

停止顺序：拒绝新请求 → 失效当前代次 → 取消请求/记录任务 → 等待有界排空 → 停止库与释放连接 → 退订事件/归还缓存/关闭文件 → 验证监听释放。软等待预算到期后执行中止和最后清理；仍有残留时报告 Faulted 与残留事实，不能发布 Stopped。清理不再沿用已经取消的页面令牌。

## 4. 代理、HTTPS 与 HTTP/2

### 4.1 显式代理为 M0 唯一接入模式

默认仅监听 `127.0.0.1`，客户端显式指定代理并关闭“本地地址绕过”，上游直接连接测试端点。测试先断言请求确实经过代理，以防 localhost 自动直连造成假成功。固定版本的环境代理、PAC/WPAD 或链式代理行为在启动配置中显式核对；M0 不自动接管系统设置。

普通代理转发沿用库的协议实现，插件只选择目标和观察受限数据，不实现第二套 HTTP 转发器。测试端点可以使用 Kestrel/原始受控流分别验证协议与特殊分块，不能用 Stub 模拟真实转发通过。

### 4.2 两段 TLS 分开验证

1. 客户端访问 `https://source-a.test`，经显式代理 CONNECT 后由代理签发 source-a 的证书；测试客户端只信任本轮代理测试根。
2. 代理上游连接 A 或 B，独立验证目标证书链、有效期、SAN 名称和 SNI 目标。B 的证书只涵盖 `target-b.test`，避免通配符掩盖改写错误。
3. 测试根仅注入到该连接/客户端的自定义信任链。自定义回调需要保留名称检查和链验证，不能忽略 `RemoteCertificateNameMismatch`，不能把所有 `SslPolicyErrors` 当作可接受。
4. 过期、错误 SAN、未知根、握手失败作为负例；客户端未信任代理根与代理未信任上游根分别显示原因。

确切证书与名称解析 API 由 V2-01 按固定版本验证。若公开 API 无法隔离信任与回环解析，先更换受控夹具方案/候选版本并记录理由；禁止为了自动测试通过去改全局证书校验。

### 4.3 协议证据

每请求保存 requestedVersion/policy、clientProxyVersion、proxyOriginVersion、实际端点协议、TLS/ALPN 可观测信息、成功/失败/降级原因；无法观察的字段标为 unknown，不能推断成 h2。

HTTP/1.1 是必过。h2 分 exact 请求和允许回退两种路径；CONNECT 外层版本与隧道内被解密的协议分开。确实支持的 h2 路径还要验证并行流、单流取消、目标映射和持续响应。若无法证明上游协议，不能给该组合支持结论。

HTTP/2 exact 被明确拒绝也可以作为能力调查结果，但不是 h2 通过；必须完成失败可见性、允许回退行为和首版范围决策。HTTP/3、h2c 扩展、WebSocket/gRPC 专用分析不自动纳入 M0。

## 5. 增量观察、记录背压与大资源

链路为“端点 → Titanium 转发 → 客户端”，观察器旁路生成有限记录。有限记录队列不承担网络传输队列职责；慢盘只能降低记录完整性，不能不断延迟客户端或引起无界分配。

处理每一块数据时：先更新原子字节计数 → 检查记录/队列预算 → 仅复制允许保留的部分并入有界队列 → 写入结束后归还缓冲。第三方回调的数组可能被复用，必须核对其有效期；不能直接把借来的内存留给后台任务。

队列不足或单体/总配额耗尽时，本请求永久转为部分记录，已入队前缀继续有序写完，后续块只计数。这样保存的是连续前缀，不产生看起来连续、实际中间缺字节的正文。磁盘错误时保留错误和实际已写字节；无法安全保留部分文件时标记不可读并清理该文件。

如果所选库回调只能提供完整 Body，或异步 hook 必须等待磁盘导致传输受阻，应作为选型问题回到 V2-01；不能用任务无限排队伪装增量支持。

SSE 只做本阶段最小事件验证：增量 UTF-8 Decoder 保留跨块状态，事件分隔符跨块也能组装；支持注释/心跳、多个 data 行、CRLF/LF 和流结束时未完成事件。单事件过大进入明确截断状态，不无界扩容，也不自动重连。界面只显示受限摘要。

正文长度以明确的层次记录：转发链路 Body 字节（不含 chunk framing）、观察到的编码前/后层次、磁盘保存字节分别注明；有压缩时不能把解压后长度和 Content-Length 比较为一致。M0 的主要大文件夹具不压缩；压缩场景只验证原始转发完整性，解码预览预算留 M1。

128 MiB/1 GiB 的代理由开发控制台 `NetWorkTrafficPlugin.TechnicalProbe` 独立承载；生成器和客户端增量哈希运行在测试进程。控制台只引用 Plugin 并复用注册入口，不包含第二套代理、UI 或 Host 模拟。测试通过本轮专用输入/控制通道传入 runId、预算和测试信任配置，等待监听就绪后发送流量；标准输出只含结构化状态与采样，禁止输出证书私钥。退出时先发停止指令并等待结果，超过预算才终止本轮子进程，强制终止不能算正常释放通过。

SHA-256 对比完整客户端数据；记录前缀哈希只证明前缀，不能替代传输完整性。发生中断或长度不符，客户端/记录状态都不能标 Complete。普通协议测试仍可在单测试进程运行，资源结论必须来自这个独立代理进程。

## 6. 改写与系统状态所有权

### 6.1 一次决策与一致目标

最小规则为精确匹配 `source-a.test`，并可追加合成头 `X-M0-Route: B` 的条件；匹配后改为 `target-b.test:<B 实际端口>`。只有指定请求命中，路径、百分号编码、重复 Query、方法和 Body 默认原样保留。此配置只作为探针输入，不设计通用 DSL。

一请求在接纳时冻结规则修订和 RouteDecision，适配器据此一致更新连接目标、Host/authority、上游 SNI 与证书名称。原始/有效 URI 分开存放，不在共享会话对象上跨请求保存“最近目标”。连接池键必须包含有效 scheme/host/port 和适用的 TLS 身份；以同连接交错命中/未命中探针验证复用不会串目标。

域名规范化由 URI/DNS 语义处理，测试大小写、显式端口和非法 URI；不是字符串 Replace。拒绝不支持的 scheme、userinfo、目标指向代理监听端点及已识别的回环别名。M0 使用已知 A/B 目标白名单验证循环防御，不把它宣称为完整公网重定向防护。

M0 不跟随上游 3xx 自动发起额外代理请求；客户端重定向行为单列，不计作代理自动重试。B 失败按请求返回明确失败，不尝试 A。Cookie、Authorization、Origin/Referer 仅使用合成值，按输入保留；不自动迁移业务身份，不声称更换域名即可跨环境登录。

### 6.2 系统代理与证书恢复决策

M0 自动路径选择“显式代理 + 进程内证书信任”，因此**系统代理与证书存储的写入次数必须为零**。验证前后核对设置快照，不能写“恢复成功”掩盖实际没有恢复实现。

真实客户端若需要系统信任，另行在指定的隔离开发环境手动验证并记录证书指纹、原状态、操作人和清理结果；自动门禁不触发安装。私钥只存在本轮内存/受控临时目录，不提交、不写日志。进程退出和测试失败均清理自己创建的文件。

后续若选入系统代理管理，必须先有变更日志：保存原值和写入值、持有者身份、启动中断补偿；恢复前比较当前值是否仍等于本实例写入值，外部已修改则提示冲突而不覆盖。证书只能按精确指纹/所有权处理，不按显示名批量删除；原已存在的证书不归本插件。该策略是 M0 的设计决策，具体 OS 管理实现留后续选入阶段。

## 7. 探针预算与测量判定

下表为 **V2 首轮探针的拟定限制**，尚未测试，不是 M1 默认值或性能承诺。V2-01/06 在运行前把数值、机器和原因写入本轮 profile 并固定；需要调整时保存旧失败与新 profile，不事后放宽阈值把同一轮改成通过。

| 项目 | 初始探针限制/测量方式 | 超限行为 |
| --- | --- | --- |
| 活动代理请求 | 20；最早基础探针从 1 开始 | 接纳前拒绝/受控排队，排队长度也有上限；错误可见 |
| 单请求预览 | 64 KiB；SSE 单事件同样有界 | 截断预览，继续转发 |
| 单请求记录 | 1 MiB 连续前缀 | Partial，继续计数和转发 |
| 记录总磁盘 | 每轮 64 MiB，不含独立诊断/TRX；诊断目录另限 16 MiB | 后续仅元信息，明确配额命中 |
| 记录队列/插件 Body 缓存 | 队列总计 4 MiB；预览、排队、正在写入等 Body 缓存合计最多 32 MiB | 不等待磁盘而无限增量；停止本请求后续正文记录 |
| 元信息/事件 | 最近 1,000 请求、最近 256 条事件，每项文本长度也受限 | 淘汰最旧项并累计丢弃计数 |
| SSE 常规/持续探针 | 常规有限握手脚本；资源探针持续 10 分钟 | 到期主动取消并测释放，无自动重连 |
| 停止时间 | 软等待 5 秒，中止及最终清理另 5 秒 | 总预算后仍有残留即失败，报告残留对象 |
| 资源采样 | 每 250 ms 采样私有内存/工作集/托管堆、活动数、队列、文件和句柄；冷启动与预热分开 | 缺少关键采样不能给资源通过结论 |

独立进程固定预热后串行测 128 MiB 与 1 GiB；两种大小分别做三次受控传输，报告每次峰值与中位值。初始本地诊断阈值：代理进程相对预热的私有内存增量不超过 256 MiB；1 GiB 的三次峰值增量中位数比 128 MiB 不多于 64 MiB；插件 Body 缓存始终不超过 32 MiB。只读结尾内存、主动 GC 后的值或平均值均不能替代过程峰值。

该阈值只约束固定探针配置，不声称每台设备有相同吞吐。运行前登记最低环境；不满足条件则环境检查失败，不跳过后算通过。10 分钟持续流需要曲线无持续积压、队列不超限，且停止后活动数为零、文件关闭、监听可重新绑定；托管堆未立即回到冷启动值不单独判泄漏。

吞吐、直连/代理延迟差、首事件延迟在 M0 记录原值与环境；首事件必须发生在端点结束前，采用夹具握手证明而非设一个任意毫秒 SLO。M1 的产品目标据这些证据确定。

## 8. 中文注释与设计思路要求

新增接口、状态模型、并发方法、证书验证与 Body 回调要写中文 XML/行注释。注释重点是为什么、谁拥有、什么时候失效、失败后保留什么。不得以“线程安全”“已释放”四个字替代具体契约。

以下仅为设计注释示意，实际签名须与实现一致：

```csharp
/// <summary>停止当前运行，并等待监听与在途任务完成有界清理。</summary>
/// <param name="cancellationToken">
/// 仅取消调用者等待。停止一旦被接纳仍继续执行，防止页面关闭后留下无人管理的监听器。
/// </param>
/// <remarks>
/// 先失效运行代次，再调用代理库停止；旧回调即使迟到，也不能重新发布运行状态。
/// 网络等待发生在状态锁外，避免停止与请求回调互相等待。清理失败必须保留故障状态。
/// </remarks>
public Task StopAsync(CancellationToken cancellationToken);

// 第三方回调中的内存可能在返回后被池复用，只复制预算允许的前缀。
// 队列满后本请求永久停止正文记录，保证落盘仍是连续前缀；真实网络转发继续。
// 入队失败时由当前方法归还缓冲，成功后由写入者归还，不能重复释放。
```

测试注释应说明哪个竞态或故障被控制、为什么需要真实端点；门禁脚本注释说明报告的新鲜度和判失败理由。API 更改同时更新注释，不提交与代码相反的设计说明。

## 9. M0 交给 M1 的边界

可复用：运行契约、代理适配、原始/有效目标、来源身份、有限记录语义、生命周期和受控测试。需要在 M1 正式实现：捕获列表与详情、存储索引、图片/文本查看、可配置预算、用户证书引导、真实客户端使用流程。

测试端点、特殊证书、合成规则、生成器和资源 profile 留在测试/开发工具边界，不随正式插件运行。M0 探针成功只证明列出的协议与配置，M3 仍须用真实规则执行链重新验证改写。

## 10. V2 实施差异与已核定范围

生产实现遵循以上 SOLID 边界；实际契约集中于 ProxyContracts.cs，证书实现为 ProxyCertificates.cs，资源测试在 Integration/ResourceProbeTests.cs。页面由 UI Timer 轮询快照，不引入网络事件订阅。

Titanium 固定 7.0.13：普通 HTTP/2 已测试；配置映射时整次运行协商 HTTP/1.1，exact h2 失败。回环 IP/localhost 与不同 SAN 代替私有 DNS 注入。库 IdleRead 在响应复制期间是一次性截止，现由适配器按最后数据活动判断空闲；h1 短读主动结束会话。

错误使用阶段中文摘要/异常类型；预览、256 条事件历史和完整 UI 留到 M1；SSE 增量解析器已有独立测试。资源曲线从 20 请求各 16 MiB 的固定并发预热后采集；另记录启动就绪快照，冷启动过程峰值未测。更紧的 4 MiB 队列限制当前插件正文缓存，完整进程峰值另行采样。
