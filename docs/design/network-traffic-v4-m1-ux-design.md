# V4 · M1 工作台 UX 专项设计

> 编写日期：2026-09-30。状态：**设计契约，尚未实现或验证**。
> 配套：[V4 执行计划](../roadmap/network-traffic-v4-m1-ux-plan.md)、[V4 专用验证矩阵](../maintenance/network-traffic-v4-m1-ux-verification-plan.md)。
> 继承：[M1 当前运行边界](../reference/network-traffic-m1-runtime.md)、[V3 设计实际取舍](network-traffic-v3-m1-capture-design.md#13-首版实际落点与设计取舍)。

本设计以 SOLID 为首要规定，使用普通 MVVM、组合、纯函数和必要的平台适配。所有新类型名称均是职责建议，实施时按实际拆分选用；不要求为凑齐表格创建类、项目或接口。不使用 AIFLOW、Windows CI 或发布门禁。

## 1. 信息架构与布局

主工作区固定为“代理/文件操作 → 筛选 → 请求列表与详情 → 状态栏”。普通状态下无页内大标题、常驻说明卡片和展开式诊断区。宿主标签或 Standalone 窗口标题保留“HTTP 工作台”。

宽屏布局示意仅表达位置，不是生产截图：

```text
● 运行中  127.0.0.1:端口 [复制] [停止]       [保存会话快照] [打开 ▾] [设置]
[搜索域名 / 路径…………] [方法 ▾] [HTTP 状态 ▾] [更多筛选]
┌────────────────────────┬──────────────────────────────────────────┐
│ GET /api/users  200 128ms│ GET /api/users  200 128ms  [复制地址] [⋯]│
│ api.example  已存 4.2KB │ 正文  概览  参数  Headers  Cookie         │
│ …                      │ [请求 / 响应] [格式化 ▾] [查找] [导出]    │
│ [新增可见 N 条，回最新] │ 当前正文，异常时显示一条可展开提示        │
└────────────────────────┴──────────────────────────────────────────┘
实时 · 匹配 36 / 保留 820               累计 900 · 已淘汰 80
```

### 1.1 布局规则

| 可用逻辑宽度/状态 | 行为 |
| --- | --- |
| Document ≥720 DIP | 列表/详情并排；默认列表约 40%、详情约 60%，分隔条可拖动 |
| Document <720 DIP | 列表与详情互斥；选中后显示返回、请求身份和上/下一条，隐藏列表筛选栏 |
| 宽屏最小分栏 | 列表至少 260 DIP、详情至少 360 DIP，剩余空间扣除边距/分隔条后再约束比例 |
| 宽窄来回切换 | 保留 RecordId、方向、模式、筛选及阅读状态；恢复最近合法宽屏比例 |
| 侧栏/弹层 | 设置覆盖主内容，不改变底层 Grid 行高；窄屏使用同一内容的受约束弹层；关闭后恢复焦点 |
| 顶栏空间不足 | 文件动作进入有文字的“更多”菜单；代理状态与停止入口常驻，不通过无限换行消耗正文 |
| 标签空间不足 | 使用可键盘访问的溢出菜单；保持当前标签可识别，不堆叠多排标签 |
| Tool 280/420 DIP | 状态、启停、地址优先；详细配置/诊断按需展开，整区单一主滚动，不裁掉停止入口 |

720 是现有断点的延续，不按物理屏幕像素或操作系统缩放后截图宽度判断。窗口客户区、Document 可用区和截图物理像素需分开记录。比例只在当前 Document 内存活，不新增落盘偏好系统。

### 1.2 量尺与可读性目标

以下作为 V4 初始开发验收阈值，须在实施前固定到 UX profile；不是当前已达成指标。

| 项目 | 目标与测量条件 |
| --- | --- |
| 顶部占用 | 800×600、900×600、1200×720 DIP，正常状态、无展开面板和筛选标签时，从工作区顶端到请求内容框顶端 ≤104 DIP，设计期望 80～100 DIP |
| 默认请求行 | 普通双行 44～52 DIP，基准 48 DIP；长路径省略而不增加行数；异常徽标占已有行，完整说明在详情 |
| 一屏请求数 | 800×600 DIP、双行模式、20 条普通样本、正常状态，至少完整显示 8 条 |
| 窄屏正文 | 520×420 DIP，详情正常状态、无展开诊断/查找面板，实际正文滚动视口 ≥160 DIP |
| 操作尺寸 | 常用控件高度 28～32 DIP，图标命中区域至少 28×28 DIP；不能为数字达标裁切文本或焦点框 |
| 字号与间距 | 正文 13～14、次要信息不低于 12 DIP；代码/JSON 等宽，界面字体沿用主题；间距采用 4/8/12 DIP |

主题使用项目/宿主可用的动态资源，避免硬编码纯黑/纯白。选择、悬停和焦点有区别；异常同时有文字/图标，不只靠颜色。中文、长域名、高 DPI 下逐图复核；放大字体时允许布局调整，不能缩小字体硬守普通密度阈值。

## 2. SOLID 职责与依赖

| 原则 | 本轮落实 | 验收依据 |
| --- | --- | --- |
| S 单一职责 | MainDocument 组合；代理模型只处理代理意图/状态；筛选状态维护条件；详情状态协调读取/方向；阅读状态计算跟随决策；View 管控件几何与焦点 | 修改行排版不影响归档；修改滚动策略不需要网络对象；一个错误归属于具体操作 |
| O 开闭原则 | 行摘要/状态文案用纯投影；新增呈现模式局限于内容投影与选择分支，不侵入传输/保存状态机 | 树形/格式化/原文切换不改 CaptureState，也不增加网络请求；无提前设计的插件式查看器框架 |
| L 里氏替换 | 实时/只读 reader、文件选择/剪贴板适配及替身保持取消、错误和身份契约 | 同组契约测试验证替换；只读源不支持的网络动作不能伪造成功 |
| I 接口隔离 | 复用 ICaptureReader/ICaptureSession/ICaptureArchive；平台选择器与剪贴板按实际边界提供窄能力 | 页面不依赖包含代理、磁盘、窗口、剪贴板的万能接口；纯格式化函数不建接口 |
| D 依赖倒置 | Application 不引用 Avalonia 控件或 Titanium 会话；平台交互由 UI 适配，构造组合在公开服务入口完成 | 纯筛选/跟随测试不启动桌面；可控失败替身替换平台而不替换业务逻辑 |

建议按变更理由提取 `CaptureFilterState`、`CaptureDetailState`、`ReadingFollowState` 等小对象，但允许简单逻辑保留为函数；不以文件数量证明 SOLID。`CaptureWorkspace` 保留会话选择与子状态协调，不能退化为几十个互相转发属性的空外壳，也不能继续承担所有解析、存储与平台工作。

控件几何、ScrollViewer 偏移、焦点和用户输入来源属于 View；会话/记录身份、跟随意图、水位和当前方向属于页面状态。通过类型明确的事件/方法传递意图，不把 Control、TopLevel 或 ScrollViewer 塞进 Application 模型。

## 3. 代理操作、设置和共享状态

| 真实状态 | 顶部呈现/允许动作 |
| --- | --- |
| Stopped | 已停止；“启动代理”；无实际地址时复制不可用 |
| Starting | 正在启动；禁止重复启动；保留现有 Stop 契约允许的取消/停止动作 |
| Running | 运行中、实际监听地址；同一位置显示“停止代理” |
| Stopping | 正在停止；防重复触发；没有终态前不得显示已停止 |
| Faulted | 发生故障及诊断入口；重试停止/启动由协调器真实可执行条件决定，禁止界面直接清状态 |

单个主操作位置用于正常启停；故障恢复动作可通过紧邻菜单提供，不为追求一个按钮丢失收口入口。设置打开时，其可视区域也须保留可达的代理停止动作，不能用弹层完全遮挡唯一入口。

设置内容分为监听/记录、HTTPS 接入、诊断；端口、记录模式和目录有明确标签。运行中修改只形成下次启动草稿，显示“下次启动生效”，旁边可查看本次实际配置。保存配置不自动重启、不换 CA、不恢复“正在运行”意图。

Document 和 Tool 共享代理事实，配置草稿按页面隔离，实际生效状态以协调器为准。关闭设置只影响显示；关闭最后页面仍继续捕获。保留公开证书、指纹、有效期、重启后证书更换说明、客户端信任未知和 h2 空闲仅提示，不把安全/协议事实藏成无法发现的悬停文本。

## 4. 请求列表和摘要口径

第一行：方法、路径、HTTP 状态、耗时。第二行：域名、已保存大小和必要的传输/记录异常标记。路径按显示宽度省略，完整有效 URI 仍用于既有查询；不合并同 URL 的多次请求。

现有 TrafficSummary 的观察/保存字节为**请求与响应合计**，V4 默认大小必须标注“已存”，通过提示/详情明确为双向合计，不改称“响应大小”。详情分别列出请求与响应观察、提交和期望字节；未知长度显示未知，不显示 0 或假进度百分比。

HTTP 状态、传输状态、保存状态独立：例如 HTTP 200 + 传输完成 + 仅保存前缀，展示“200 / 部分保存”。接收中且尚未完整保存是进度事实，不每次刷新弹警告；因配额、写失败或缺口而终止记录则显示原因。Cancelled、Failed、MetadataOnly、MetadataPartial 都可辨认。

正常完成不重复显示大段 Completed/Complete；序号、毫秒时间、来源进入概览。基础字体不靠 11 DIP 小字堆密度。列表保留虚拟化，禁止为所有记录创建正文、JSON 树、图片或复杂可视控件。

## 5. 筛选契约与本页范围

| 条件/操作 | 固定语义 |
| --- | --- |
| 关键字 | 沿用完整有效 URI、长度限制及 200 ms 消抖；输入法组合未完成时不提交查询 |
| 方法 | 一个规范化集合是唯一有效来源；快捷选择修改该集合，多选 OR，集合内去空/去重且方法名不区分大小写 |
| HTTP 状态 | 状态类与精确状态码使用明确的互斥选择；输入精确码后替代类条件，切回类时清除精确码；100～599 校验 |
| 传输状态 | 全部/接收中/传输失败单选，替换当前两个可同时勾选但有优先级的复选框；与 HTTP 4xx/5xx 分开 |
| 时间 | 开始包含、结束不包含；空值为不限制；非法格式或开始晚于结束就地显示错误，不提交错误查询 |
| 不同维度 | AND；不新增 DSL、正则或隐含网络操作 |
| 清除筛选 | 清关键字/方法/HTTP 状态/传输状态/时间，保留本页清空游标及阅读意图 |
| 清空本页 | 只移动本页序列游标；活动请求按现有 CaptureQuery 规则仍可见；不删除共享数据 |
| 恢复本页范围 | 移除“仅看清空后”范围标签，把本页游标重置；与清除筛选是不同动作 |

以上是 V4 明确的交互调整：现有实现的清除筛选会同时重置游标，状态类/精确码可叠加，方法文本会覆盖下拉框，接收中/失败有隐式优先级。实施应更新相关生产测试及文案，不把旧控件排列当作不可修改的业务契约。

区分筛选草稿与最后已应用条件。非法输入保留最后有效结果并标明“尚未应用”；有效查询进行中保留旧结果并显示正在更新。只在当前 QueryRevision 完成时按身份应用差异；旧结果不覆盖新条件。筛选标签显示已应用条件，草稿状态另有提示，避免列表与标签对应不上。

选中记录仍在结果中则保持；不在时清选择与旧详情，显示无选择提示，不悄悄选中相同索引的另一条。筛选改变后重建阅读水位/锚点；继续保留用户主动暂停跟随的意图。

## 6. 独立跟随、锚点和新增提示

### 6.1 状态与输入

每 Document 一个列表阅读状态，当前详情一个事件阅读状态；每个使用 `Following`/`Paused` 两态及当前会话/查询/记录身份。默认实时列表 Following，首次进入实时流详情 Following；只读模式无实时新增跟随。

| 触发 | 列表 | 流事件 |
| --- | --- | --- |
| 有新增且 Following | 定位最新，但不自动更换选中 RecordId | 定位最新完整事件；半事件单独展示 |
| 用户滚离最新边界 | Paused，保存可见锚点 | Paused，保存事件锚点 |
| 用户选择旧请求 | 暂停列表跟随 | 新详情按初始化规则处理，不改列表状态 |
| 用户选择正文文本 | 不影响列表 | 暂停事件跟随，避免选择范围移动 |
| 程序恢复偏移/布局变化 | 不改变用户意图 | 不改变用户意图 |
| 用户点击“回到最新” | 仅恢复列表跟随 | 仅恢复事件跟随 |
| 没有新增的普通刷新 | 不滚动 | 不滚动 |

最新边界容差采用 2 DIP；只有用户输入导致的离开才触发暂停，普通 ScrollChanged 不能直接当作用户意图。暂停后即使手工滚回边界，也保持暂停，直到明确点击继续，避免布局变化或事件淘汰意外恢复。每轮最多排一个合并滚动恢复操作，不对每条记录逐次滚动。

### 6.2 锚点与数量

列表锚点为 SessionId、QueryRevision、RecordId、Sequence、行内逻辑偏移；事件锚点增加当前 RecordId/Direction 和事件 Sequence。暂停时，顶部插入或记录修订后恢复同一锚点；恢复后的可见坐标误差目标 ≤2 DIP。摘要替换不清当前选择，不因相同 RecordId 修订重建未变化正文。

锚点因淘汰/筛选消失时，在当前保留结果中选择序列最接近的较旧记录，若无则选择较新记录；这是**视口锚点**回退，不自动替换用户的 Selected。无结果显示空状态。事件锚点淘汰则定位最早仍保留的事件，并显示“较早事件已淘汰”；不跳到最新。

列表提示采用“新增可见 N 条”，N 只计暂停水位之后、当前筛选匹配且仍保留的记录，不把观察到的批次数当作新增请求数。相同请求修订不累加；无需无界已见 ID 集合。筛选、清空或换会话时重置计数基线。若保留范围发生淘汰，独立提示有淘汰，不能声称该数字是暂停以来全部到达量。

事件提示同样依据当前保留环与序列，不隐藏累计淘汰/解析缺口。切换记录或请求/响应方向初始化新事件状态；同记录同方向切换正文模式不改变跟随意图。页面内只保留当前记录的阅读状态，不建立无界历史缓存。

## 7. 详情内容与敏感字段

详情顶部固定请求身份及 HTTP 状态/耗时，常用内容标签收敛为正文、概览、参数、Headers、Cookie。“导出”是当前记录/方向上的动作，不再占内容标签。

请求/响应方向对正文、Headers 和导出一致生效，默认响应；概览同时列两侧事实；参数始终标注请求 Query；Cookie 明确区分请求 Cookie 与响应 Set-Cookie，不把二者混成无方向文本。切换记录保留方向偏好；新会话回到响应并关闭敏感字段展开。

| 内容 | 默认与切换 | 约束 |
| --- | --- | --- |
| 完整有效 JSON | 默认格式化，可切树形/原文 | 同时只有一个主视图；保留重复字段顺序和原文语义，不回写原始数据 |
| 部分/无效 JSON | 有限原文及原因 | 不把截断前缀修补成完整 JSON，树形/格式化不可用时有说明 |
| 普通文本 | 有限原文，可查找/复制当前文本 | 可切自动换行；查找只在已载入范围，无全文搜索暗示 |
| SSE/NDJSON | 完整事件列表、独立跟随和统计 | 半事件紧凑独立呈现，不放一个常驻大空文本框；缺口始终可见 |
| 图片 | 有界缩略图、尺寸和类型 | 不同时显示无意义空文本框；沿用完整性/尺寸/解码预算 |
| 文件/二进制 | 元信息及已有有限十六进制 | 不播放、不补下载；导出明确已保存范围 |

原文指按既有编码策略解码的有限文本；gzip/br 的实体文件与解码文本不是相同字节。所有模式共用既有预算：普通文本输出 64 KiB，JSON 输入/格式化输出各最多 1 MiB、深度 64、节点 10,000，共享内容预算 32 MiB。视图切换新增字符串、树和位图须纳入实际预留，超限时降级并说明，不按模式各自分配一份独立总预算。

默认编码推断说明收进信息入口；替换字符、解析失败、预览截断、记录缺口和写失败保留一条可见提示，展开看原因。用户能分别判断“网络成功”“正文保存完整”“本次预览完整”。

“显示敏感字段”只控制既有 Header/Query/Cookie 等结构化字段展示。默认复制与当前遮罩一致；复制地址沿用地址脱敏规则，显式展示原值后才可按明确动作复制完整值。正文不宣称自动脱敏，存档/正文导出仍含实际记录内容，保存界面保留原有说明。不得用该开关把整个界面宣称为已脱敏。

正文查找为当前有限文本上的字面量查找，查询长度最多 256 字符，默认不区分大小写，不支持正则；只维护当前匹配位置，下一处按需扫描。树形/图片等视图不可直接查找时，明确切到可用文本视图后再查找；不后台遍历未展开全部树，不扫描文件，不搜索被遮罩字段的隐藏原值。

## 8. 文件选择、操作代次与反馈

平台选择器与剪贴板属于 UI 适配；按当前 Avalonia/公开 Host 能力核对可用性。无可用平台能力时显示可理解原因并提供受同一校验约束的手工路径输入，不抛未处理异常或静默假成功。

保存分为选择外部父目录和填写新子目录名；父目录可已存在，最终存档目录必须未存在。打开/恢复选择已有目录；正文导出选择未存在文件。所有路径仍经归档服务验证，不允许 UI 绕过捕获根、重解析路径、占用、覆盖和预算规则。平台默认“覆盖已有文件”流程不能改变本项目禁止覆盖的契约。

“保存会话快照”保存当前源会话仍保留的全部可存档记录，包括筛选隐藏项；不包含此前淘汰的全部历史。打开档案后的另存也指当前只读源。用户完成路径选择并最终确认后才冻结快照水位，显示实际快照时刻，不把打开选择器的时间误认为冻结时刻。

开始保存流程时锁定源会话身份；选择器期间切换源或关闭页面，迟到结果应丢弃并要求针对当前源重新发起，不能保存另一会话。导出从发起时锁定记录和方向，在任何异步完成点重新核对身份/代次；身份已变化就取消操作意图，不把旧响应写到当前请求名下。

页面关闭取消本页持有的读取/等待和已由本页发起的保存操作；共享代理仍运行。每容器原有单保存约束保持，第二个页面尝试保存需明确忙碌原因。选择器取消不调用保存/打开/导出服务，不显示失败。

每个操作有独立身份和阶段反馈；旧 finally 只清自身 busy，旧成功/错误不覆盖新操作。成功提示可在 3 秒后消失，鼠标悬停/焦点停留时暂停消失；失败保留直到处理或显式关闭，保留完整可复制原因入口。取消按钮只在可取消的保存阶段出现；进入原子提交临界段后按实际服务契约显示状态，不能承诺已经撤销。

## 9. 焦点、空状态与寿命

键盘只作用当前页面/相关控件：Ctrl+L 请求搜索，Ctrl+F 当前正文查找；列表上下键维持现有行为，文本编辑时不劫持光标。窄屏上一条/下一条按当前筛选排序导航，到边界禁用；不因新请求到达偷偷换选中身份。

Esc 顺序：最上层平台对话框/临时面板 → 正文查找 → 窄屏返回列表；一次只处理一层。关闭菜单/设置返回触发按钮，返回列表定位原选中项。屏幕阅读名称、焦点可见性、Tab 顺序及鼠标命中需要生产控件验证。

空状态分别说明：代理未启动、代理已运行但无请求、筛选无匹配、当前未选中、只读记录为空。运行但无请求提供复制地址/接入诊断；无匹配提供清除条件；不以空正文冒充读取失败。

状态寿命：代理/捕获及内容预算属于插件容器；筛选/选择/分栏属于 Document；当前详情/事件锚点属于当前记录和方向；几何锚点与输入订阅属于已附着 View。Detach 时停计时器、解订阅并撤销待执行滚动；Dispose 取消读取、丢弃平台迟到结果、归还位图和内容租约。关闭设置或隐藏 Tool 不调用共享 Stop。

现有 100 ms 刷新、每轮最多 200 行和查询 200 ms 消抖保持。没有新正文修订时不重建编辑器内容，避免清选区和滚动位置。JSON/图片读取沿用后台解析与选择代次校验，不让 UI 线程执行全文件读取或全量格式化。

## 10. 中文注释与设计思路示例

以下为设计示意，不是现有 API 或可直接编译的实现要求。

```csharp
/// <summary>
/// 决定本页列表是否跟随新记录；它不暂停代理接收、正文记录或流事件解析。
/// 用户滚离最新位置后保留暂停意图，程序恢复锚点不能再次解释为用户滚动。
/// 当前查询或会话变化时重置新增计数水位，避免把旧筛选下的数据算到新条件中。
/// 只依据当前仍保留的摘要统计可见新增，不保存无限增长的“曾见过的请求”集合。
/// </summary>
public FollowDecision Observe(ListReadingInput input);

// 设计原因：索引会因顶部插入和旧行淘汰变化，因此先找 RecordId，再恢复行内偏移。
// 找不到原锚点只回退视口，不替用户选中另一请求；记录淘汰与正文缺口是不同提示。
// 恢复过程中屏蔽程序滚动反馈，避免一次刷新把 Following 意外改成 Paused。

// 选择器返回时页面可能已关闭，或用户已经切到另一会话/正文方向。
// 此处再次核对操作代次后才发起写入，旧 finally 只能清理自己持有的忙碌状态。
// 用户取消路径选择是正常结果：不创建文件，也不显示“导出失败”。
```

测试注释解释输入意图、固定时序屏障、被保护的不变量和反例；脚本注释解释必测清单为何独立于映射、为什么拒绝旧截图/旧报告、为何超时只终止本轮拥有的进程树。无需为简单赋值重复注释，但跟随、取消、预算、遮罩和归档范围必须写清设计原因。

## 11. 实施核对与变化管理

| 核对项 | 处理方式 | 关闭依据 |
| --- | --- | --- |
| Avalonia 用户输入与程序滚动区分 | 使用当前锁定依赖的公开事件/输入 API，必要时在 View 内加小型适配和重入保护 | 单元决策 + 实际滚轮/拖动/键盘生产 UI 证据 |
| 原生选择器与剪贴板 | 核对当前 TopLevel/Host 可用能力，真实适配与取消/失败替身分别验证 | I04、UI08、H01/H02，不把替身当原生对话框 |
| JSON 模式切换的内存 | 复用有界解析结果，按需物化树，释放旧模式对象；不能假定 IsVisible=false 已释放对象 | U13、P02、真实预留/释放曲线 |
| 旧 UI 测试的控件索引依赖 | 改为稳定语义名称及真实命令目标断言；保留 V3 场景原意，更新映射和截图身份 | R01、G08，不能删测试凑通过 |
| 密度与高 DPI | 以 DIP 测量布局、以物理像素验证 PNG；字体缩放另列条件 | UI01、H01，无法达到时记录实际差异后调整设计/profile |

不得为通过检查静默放宽 M0/M1 资源阈值、隐藏警告或删掉难测功能。需要调整 V4 初始布局阈值时，先说明实测原因并同步本设计、执行范围、profile 和矩阵，再运行新基线；历史结果不重写。
