# V5 · M2 单元测试、验证矩阵与本地开发门禁

> 日期：2026-09-30。状态：**待实施的验证契约；本文没有业务测试通过结论**。
> 配套：[V5 执行计划](../roadmap/network-traffic-v5-m2-dsl-grouping-plan.md)、[DSL 与分组专项设计](../design/network-traffic-v5-m2-dsl-grouping-design.md)。

SOLID 为首要规定，朴素使用设计模式，代码/测试/脚本使用详细中文注释并解释设计思路。不使用 AIFLOW，不新增或触发 Windows CI，不运行发布门禁。允许本机 Windows Debug 开发验证；发布相关检查在正式发布阶段另行使用。

## 1. 验证层次与完整集合

V5 固定 **64 项业务自动场景**：L10 + E12 + Q8 + T6 + S8 + I6 + UI8 + P4 + R2。另有 A01～A04 工程审查、G01～G12 门禁正反例、H01～H04 人工验收，分别统计。一个场景可以对应多个测试及参数行；64 不是预填测试方法数或通过数。

| 层次 | 必须证明 | 不据此推定 |
| --- | --- | --- |
| 语言/领域单元 | 解析、状态、多值、类型、依赖、分组、时间和稳定顺序 | 已接通真实捕获与磁盘 |
| 存储/会话集成 | 生产适配器、冻结水位、原子修订、历史重算、取消/寿命 | 任意客户端与真实 Host 已验 |
| 生产 UI | 实际 View 的输入/按钮/绑定/焦点/导航、两主题与窄屏 | 物理输入、原生桌面和 Host 完全相同 |
| 资源探针 | 生产分析路径、受控负载、原始曲线和峰值 | 未指定硬件下的性能承诺 |
| 门禁自身 | 错误 TRX/映射/证据/范围与超时被汇总入口拒绝 | 合成门禁夹具已完成业务测试 |

测试落在现有 `NetWorkTrafficPlugin.Tests`；拟新增 `Dsl/Analysis/Rules`，复用现有 Fixtures/Integration/Ui 和探针宿主。使用 xUnit 现有能力，不为了指标再引入另一套测试框架。关键数据驱动测试必须验证所有参数行，不能只认同名方法有一行 Passed。

P01 10轮 p95 使用 nearest-rank（升序第 ceil(0.95*N) 项），记录所有轮次而非只报平均。P03 保留250ms原始进程/队列/额度采样及真实时间段、完成/预算拒绝/取消数量，不把50次全部无工作取消算通过。规则与负载应使至少45次完整分析成功，其余只能为明确注入的预算/取消分支；否则失败。P04 预算归零指该测试所有页面/候选已释放后，不能要求仍有页面持有结果时为零。

新增分析内存额度是64MiB的硬限制，不代表可额外突破整进程原256MiB增量指标。若不能同时满足，先减少持有/复制并测量；变更profile须同步设计、说明原因并重测，不自动提高旧门槛。
