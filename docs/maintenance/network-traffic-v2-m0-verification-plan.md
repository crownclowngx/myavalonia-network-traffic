# V2 · M0 专用验证矩阵与本地开发门禁

> 编写日期：2026-09-29。状态：**验证设计，以下业务场景和专用门禁均未实现、未执行**。
> 配套：[V2 执行计划](../roadmap/network-traffic-v2-m0-technical-baseline-plan.md)、[技术设计](../design/network-traffic-v2-m0-technical-design.md)、[总验证计划](network-traffic-verification-plan.md)。

本文件规定 M0 要证明什么及如何防止假通过。场景 ID 不是测试数量，也不表示已有自动覆盖。实施后必须映射到实际测试方法及本轮产物；门禁只面向本地开发，不包含 Windows CI、发布 Smoke、ZIP、签名或发布门禁，不使用 AIFLOW。

## 1. 分层、夹具与适用性

| 层次 | 方法 | 结论边界 |
| --- | --- | --- |
| U 单元测试 | 纯决策、可控 runtime/sink、可推进时间、任务屏障 | 状态/预算正确；不能证明网络到达目标 |
| P/S/B/R 本地集成 | 真实 Titanium、A/B 回环端点、严格测试信任链、生成式内容 | 实际转发和测量；不能代表任意客户端/公司服务 |
| L 组合与生命周期 | 真实注册入口、多个容器/Document、同步与异步释放 | 插件对象图；不能代替真实 Host 生命周期 |
| G 门禁自测 | 构造报告错误、失败/挂起子进程、坏映射和证据 | 检查器确实拒绝错误；不能代替业务测试 |
| D/A 审查与依赖检查 | 资产、公开 API、依赖图、实际代码与中文契约 | 选型/设计理由；不以字符串匹配测试代替审查 |
| H 人工开发验证 | 最小诊断入口、真实客户端/Host、停止退出 | 当次环境结论；独立于正式发布 |

自动测试使用合成域名、身份和正文，不访问公司服务，不导入系统根、不修改系统代理或 hosts。每轮唯一临时目录和证书，仅清理自身资产。真实传输测试必须证明经过代理；关闭本地绕过，A/B 收件记录与 RequestId 对应。

普通场景与资源场景分进程执行。纯逻辑测试可并行；共享代理/证书/端点的同一夹具序列化；独立夹具有独立端口与文件。计时用单调时钟，UTC 仅做证据关联。使用显式握手与屏障控制时序，不用长 Sleep 碰运气。

M0 强制通过 HTTP/1.1、HTTPS、SSE、大文件与目标映射。HTTP/2 必须调查，不允许 Skip：支持时断言支持路径，不支持时断言 exact 请求失败、协商回退/拒绝行为和限制文档。能力配置须来自实际观测并通过审查，不能任意把失败功能标 unsupported 绕过检查。

## 2. D：依赖与接入

| ID | 场景 | 必须获得的证据 |
| --- | --- | --- |
| D01 | 固定 NuGet、许可与公开 API | 中央版本、实际 lock、包哈希和 API 签名一致；许可/来源登记；不拿 develop 文档代替二进制 |
| D02 | 私有依赖和 Host 共享程序集 | Debug 输出/依赖资产无遗漏；共享 SDK/Avalonia/Microsoft.Extensions 不误私有复制；冲突有处理结论 |
| D03 | 测试证书、代理与名称解析隔离 | OS 设置前后相同；无条件证书放行不存在；临时目录、监听与证书属于本轮 |
| D04 | 公开 SDK 寿命入口 | 登记实际 API 与调用路径；单容器单服务；同步/异步释放契约可执行，未引用 Host 内部项目 |

D01/D02/D04 由构建检查、组合测试和人工审查共同支撑，不凭一份手填 JSON 自动判定通过。

## 3. U：单元测试矩阵

| ID | 场景 | 关键断言 |
| --- | --- | --- |
| U01 | 正常 Start/Stop、重复同配置 Start | 状态顺序合法，仅一个 runtime/监听所有者，重复返回同一运行身份 |
| U02 | 启动失败、初始化一半抛错、清理失败 | 已创建资源逐项归还；保留原始失败类别；有残留时不能报 Stopped |
| U03 | Start 与 Stop 竞争、旧启动迟到 | 停止接纳后旧代次失效；迟到成功被清理，不发布 Running |
| U04 | 多次 Stop、Stop 与 Dispose 竞争 | 一次收口、释放幂等；所有等待者有确定结果，无未观察异常 |
| U05 | 预取消、启动等待取消、停止等待取消 | 预取消零副作用；取消某个等待者不破坏共享运行/清理；页面令牌不决定运行寿命 |
| U06 | 已知/未知长度及传输终态 | 完整、部分、失败分开；未知长度不伪造进度；短读/取消不报完整 |
| U07 | 单体额度、队列额度、全局缓存预算 | 精确边界/超一字节/空块；不超限分配；拒绝后仍计数，无重复释放 |
| U08 | 慢 sink、写入失败、总磁盘配额 | 回调不无界等待；保存连续前缀或明确失败；真实转发语义不被记录状态覆盖 |
| U09 | UTF-8/事件分隔符跨块、超长事件 | 中文/多字节字符不损坏；事件顺序正确；尾部不完整和截断可辨 |
| U10 | 旧回调/通知异常/订阅释放 | 不覆盖新运行，不触达已关闭页面；订阅者抛错不终止转发 |
| U11 | 两容器、不同配置、停止中启动、释放后启动 | 无静态共享；非法状态明确拒绝；Faulted 残留未清不得重新启动 |
| U12 | 精确映射与 URI 边界 | 大小写/端口/百分号编码/重复 Query 有确定结果；原始地址不变 |
| U13 | 命中/不命中交错、规则快照 | 一请求一次决策；在途修改配置不改变已接纳请求，无共享目标污染 |
| U14 | 非法 scheme、userinfo、自代理循环 | 在发送前拒绝；无静默回退、无无限路由；失败类型可解释 |

单元测试拟放在 `Proxy/ProxySessionCoordinatorTests.cs`、`BodyCaptureTests.cs`、`RouteTargetResolverTests.cs` 等文件。名称为计划；实施时用真实完全限定方法名建立映射，不提前声称文件已存在。

## 4. P：真实 HTTP、HTTPS 与协议

| ID | 场景 | 关键断言 |
| --- | --- | --- |
| P01 | HTTP GET/POST、重复头/Query、空 Body | 端点收到与输入一致的方法/路径/值和 Body 哈希；响应回传；代理确实在链路中 |
| P02 | HTTPS CONNECT 后解密代理 | 客户端严格信任、代理严格验证上游；代理能观察请求 HTTP 元信息，客户端得到真实响应 |
| P03 | 客户端不信任代理根 | 握手明确失败，不自动信任，不改变 OS 根存储 |
| P04 | 上游未知根、错误 SAN、过期证书 | 每个负例失败，不绕过验证；区分客户端信任问题和上游问题 |
| P05 | 端口占用、绑定竞争、启动中失败 | 失败状态与地址可诊断；释放临时资源；有限重试，不杀占用端口的其他进程 |
| P06 | 上游拒绝/超时、请求取消、回调异常 | 请求错误分类正确；其他请求不串错；无自动 POST 重发；停止后监听可重绑 |
| P07 | exact HTTP/2 | 记录实际两侧协议/ALPN与端点结果；支持则真实 h2，不支持则固定失败与限制证据 |
| P08 | 允许版本协商/回退 | 记录实际版本和客户端行为；h1 回退不能冒充 h2，配置不允许时不偷偷降级 |
| P09 | h2 同连接多流与单流取消 | 支持路径下其他流继续、身份不串；若不支持，产出范围诊断而非跳过/伪成功 |
| P10 | keep-alive、压缩正文、无正文响应/上游 3xx | 多请求隔离；传输字节语义准确；不因观察器全量解压；不把 HEAD/204 当短读或自动跟随 3xx |

P07～P09 的 unsupported 是协议调查结论，不是“功能支持通过”；门禁汇总分别给出 `assessmentPassed` 与 `supported`。三项均需实际断言及场景证据，不能只有能力开关。

## 5. S：流式与增量

| ID | 场景 | 关键断言 |
| --- | --- | --- |
| S01 | 第一块后等待客户端确认再继续的 SSE | 客户端首事件和插件增量记录发生在服务端结束前；确认超时失败，能发现全量缓冲 |
| S02 | 多字节 UTF-8、CRLF/LF、跨块分隔符 | 输出事件和合成文本准确，无乱码、重复或丢失；断言内容而非只计事件数 |
| S03 | 心跳、空事件、多个 data 行、尾部半事件 | 组装符合声明范围；尾部未完成不冒充完整事件；保留有界数据 |
| S04 | 在接收中取消、上游中断、长时间无输出 | 有界结束；区分用户取消、网络失败与空闲预算；已接收内容标部分 |
| S05 | 慢记录器/记录截断时持续转发 | 客户端仍增量接收，记录队列不超预算；截断后不把后续块拼为连续全文 |
| S06 | 10 分钟持续流与停止 | 资源样本完整、无持续积压；Stop 后请求归零、任务结束、端口释放 |

S01/S02 要先直接验证夹具会按预期分块/等待，再通过真实代理运行；客户端使用响应头完成模式并读取流，不能自身 `ReadAsStringAsync` 后推断代理没缓存。

## 6. B：大文件与资源

| ID | 场景 | 关键断言 |
| --- | --- | --- |
| B01 | 128 MiB 与 1 GiB 已知长度 | 客户端增量长度/哈希等于生成器预期；代理内存满足固定 profile，非完整 Body 数组断言 |
| B02 | 未知长度/分块传输 | 接收字节真实、总长度为空；EOF 前无伪百分比，正常 EOF 后传输完整性正确 |
| B03 | Content-Length 不符、早断、中途取消 | 客户端失败/取消可见，记录部分，文件关闭；不报 Complete |
| B04 | 仅元信息、有界记录、无记录三模式 | 输出相同；保存量按模式变化，记录哈希只表示已保存范围 |
| B05 | 配额/磁盘满/无权限/慢盘 | 降级或失败按契约，网络不会因记录无限阻塞；超限原因和保存量准确 |
| B06 | 20 并发中混合流式和大响应 | 队列、缓存、活动数均受限；超额接纳行为明确；停止所有请求有界 |
| B07 | 三次大小对照、释放和残留 | 每次曲线/峰值均保留；按设计 profile 比较两种大小；监听/任务/文件/句柄有释放证据 |

资源配置以[技术设计](../design/network-traffic-v2-m0-technical-design.md)第 7 节为唯一数值来源，不在脚本复制另一份阈值。实施后 profile 文件包含相同字段并记录变更理由。B01/B07 在独立代理进程测量，生成器/客户端另进程，门禁编排负责收集全部结果及退出码。

## 7. R：域名改写与并发

| ID | 场景 | 关键断言 |
| --- | --- | --- |
| R01 | 命中到 B、不命中到 A | A/B 端点按 RequestId 证明实际目标；每个输入只到一个预期端点 |
| R02 | HTTPS 目标身份一致 | B 的 Host/authority、SNI、证书名称、连接端口一致；客户端源域名证书仍正确 |
| R03 | 路径/重复 Query/编码/POST Body 保留 | 端点原始目标和内容哈希一致；原始/有效地址均可追查，无意外二次编码 |
| R04 | 同/多连接交错并发与连接复用 | A/B 请求不串路由；连接池按有效目标隔离；未命中不受前一次命中影响 |
| R05 | B 拒绝、超时、证书失败 | 请求失败，不回退 A；POST 到达次数符合发送事实，无代理层自动重放 |
| R06 | 自代理/非法目标、在途配置变化 | 发送前拒绝非法映射；固定修订，只改后续请求；无循环 |
| R07 | 映射后的 SSE/大文件/h2 适用路径 | 持续输出和完整传输不退化；h2 遵循已确认范围，缺口明示 |

## 8. L：组合、页面与退出

| ID | 场景 | 关键断言 |
| --- | --- | --- |
| L01 | Plugin 与 Standalone 同一注册入口 | 解析得到同一套生产业务；多 Document 共享协调器，局部状态独立 |
| L02 | 关闭发起页/非最后页/最后页 | 页面订阅释放，运行继续；Tool 可观察并停止；关闭某页不取消其他页面等待 |
| L03 | 关闭/重开状态 Tool 和 Document | 不创建第二个监听器、不自动启动；重新读取当前运行状态 |
| L04 | Standalone 正常退出、启动中退出 | 调用有界停止/释放，迟到回调无效；文件和端口释放，异常被观察 |
| L05 | 容器同步/异步释放和重复释放 | 两种实际支持路径都收口，失败不谎报成功；UI 线程不同步等待网络 |
| L06 | 既有模板行为迁移 | 保留标题/命令隔离/取消/并发等仍适用行为；替换示例记录测试去向，不只删测试消除失败 |

L 主要是服务/Document 行为测试；最小按钮和状态绑定按实际实现补必要 View 测试。M0 不为没有复杂交互的页面建立截图数量门槛；真实界面和 Host 由 H 观察。

## 9. A：设计和注释审查

| ID | 审查点 | 完成依据 |
| --- | --- | --- |
| A01 | SOLID 与依赖方向 | 关键类型职责清晰、真实替换边界才有接口；无跨层库对象/Host 内部依赖 |
| A02 | 中文注释和设计思路 | 契约、缓冲区所有权、代次、取消、证书、退出与失败有准确中文解释 |

审查记录写明审查者、代码摘要、结论与未解决项；代码改变后重新检查受影响项。人工结论不能由测试 Trait 自动生成。

## 10. G：本地开发门禁设计

### 10.1 计划入口与运行顺序

V2-09 将建立 `tools/verify-development.ps1`，拟提供 `-Mode Docs` 和 `-Mode M0`；辅助文件为 `DevelopmentChecks.ps1`、`test-development-gate.ps1`、`m0-test-map.json`，资源 profile 的最终位置随实现登记。**当前这些文件尚不存在，下列为实施后的命令设计，不能当作现行已可执行入口。**

```powershell
# 实施后：仅文档变化，不生成 M0 业务通过结论。
pwsh -NoProfile -File tools/verify-development.ps1 -Mode Docs

# 实施后：全量 M0 开发检查，包含模板回归、协议与资源探针。
pwsh -NoProfile -File tools/verify-development.ps1 -Mode M0
```

完整入口依次做：环境/源码身份快照 → 门禁失败自测 → locked restore → Debug 零警告构建 → 普通全量测试 → 独立资源探针 → TRX/场景/证据校验 → 文档/空白检查 → 源码身份复核 → 写本轮结果。失败立即使本轮失败，但 finally 仍清理自己启动的进程和临时资源。

核心标准命令基于现有工程；资源测试的分类和拆分由 V2-09 落地，不在这里伪造不存在的入口：

```powershell
dotnet restore NetWorkTrafficPlugin.slnx --locked-mode
dotnet build NetWorkTrafficPlugin.slnx -c Debug --no-restore -warnaserror
# 以下 Category 约定及资源用例待实现；脚本还须指定本轮独立结果目录。
dotnet test tests/NetWorkTrafficPlugin.Tests/NetWorkTrafficPlugin.Tests.csproj -c Debug --no-build --no-restore --filter "Category!=ResourceProbe" --logger "trx;LogFileName=ordinary.trx"
dotnet test tests/NetWorkTrafficPlugin.Tests/NetWorkTrafficPlugin.Tests.csproj -c Debug --no-build --no-restore --filter "Category=ResourceProbe" --logger "trx;LogFileName=resource.trx"
git diff --check
```

资源用例统一标记 `[Trait("Category", "ResourceProbe")]`，由测试启动开发控制台 `NetWorkTrafficPlugin.TechnicalProbe` 作为独立代理进程，夹具/客户端留在测试进程。该控制台在 V2-03 新建、纳入 Debug 构建且不进入插件交付；其启动失败、异常退出、失联或被强制终止均使相应用例失败。两批测试各自必须发现并执行用例，合并映射后不得遗漏既有回归和 M0 必测场景。

新增依赖时先普通 restore 审查 lock，再进入 locked 检查，不通过删除 lock 消除错误。仅文档修改无需执行这些构建/业务测试；文档检查要包含未跟踪的 Markdown，不能只看 `git diff`。

默认开发超时拟为自测 60 秒、restore/build 各 300 秒、普通测试 300 秒、资源探针 1,200 秒、整轮 1,800 秒。资源批次含 10 分钟持续流，不能沿用普通单测短超时；每个场景另设上界。超时必须失败并终止本轮拥有的进程树，保留诊断，不能按进程名杀其他开发进程。用户可中断，不能因此写通过结果。

### 10.2 判定矩阵

| ID | 检查 | 必须拒绝的情况 |
| --- | --- | --- |
| G01 | 标准命令与构建 | 非零退出、超时、输出缺失；依赖/lock 漂移；新增警告或构建失败 |
| G02 | 每批 TRX | 缺报告、旧报告、损坏/截断 XML、零发现、零执行、失败/跳过/取消、不一致计数；必须逐条 Passed 且计数一致 |
| G03 | 实际场景映射 | 必测 ID 缺失、映射到不存在/未执行方法、理论用例必需行未执行、映射有 ID 无真实断言；不能只检索 Trait |
| G04 | 网络/资源证据 | 缺 A/B 回执、h2 unknown 却报支持、采样缺失、哈希/大小不符、超预算、残留监听；只有客户端 URL 或日志字符串不能通过 |
| G05 | 本轮身份和源码一致性 | runId/源码摘要/阶段不符，旧证据混入，期间代码变更，必需证据字段缺失或默认空值 |
| G06 | 门禁失败自测 | 本节任一规定坏输入被接受，进程超时后有本轮残留，正例不能通过 |
| G07 | 文档与范围 | 本仓链接/锚点失败、状态矛盾、V2/M0 映射漏项；文档入口误宣称业务通过；引入发布步骤 |
| G08 | 结果记录 | 缺命令/环境/时间/实际统计/未验项，未区分自动与人工，检查未完成却生成整体成功 |

场景映射拟为 ID → 测试类/方法/参数组合 → 必需证据名。一个方法覆盖多个场景时，每项都需对应断言；“场景全部映射”不等于人工审查通过。模板回归也包含在实际 TRX 中。审查 A/D 与人工 H 使用独立状态，不计入自动测试通过数。

### 10.3 门禁失败自测清单

至少注入：成功子进程、非零退出、超时子进程及其子进程；有效 TRX、缺失/旧/截断 TRX、零测试、Skipped/NotExecuted/Aborted、统计与逐条结果矛盾；缺必测 ID、不存在方法、缺参数行；有效/损坏/旧 runId 的 JSON、缺采样/回执、错误哈希、伪 h2 支持、源码摘要变化；坏链接、坏锚点、未跟踪 Markdown 中的坏链接。

这些是报告解析和编排的有效分支测试，不为脚本每个字符串或每行命令写镜像测试。失败注入的报告放在独立自测目录，禁止作为 M0 业务证据汇总。自测也不调用真实发布工具。

### 10.4 证据组织

计划输出到 `TestResults/NetworkTrafficM0/<UTC时间-随机ID>/`，每轮新目录，不覆盖历史。V2-09 同步忽略此生成目录；当前文件尚未生成。大文件只生成/传输，不入 Git；私钥临时文件运行结束即清理，不归档。

| 产物 | 必需内容 |
| --- | --- |
| `verification.json` | schemaVersion、runId、UTC 起止、HEAD/脏状态/源码摘要、OS/SDK/架构、命令及退出码、实际测试统计、自动检查状态、未验项 |
| 普通/资源 TRX | 每批实际发现/执行/逐条结果，与本轮时间和运行目录匹配 |
| `protocol-probes.json` | P/R 场景、requested/observed 两侧协议、TLS 身份、目标 A/B 回执、能力调查和限制 |
| `stream-probes.json` | 服务端首段/客户端首内容/记录器首观察/结束与取消时序，内容和完整性断言 |
| `resource-profile.json`、`resource-samples.csv` | 运行前固定的预算、机器、负载、采样及每次峰值；不是产品性能声明 |
| `resource-probes.json` | B/S06 场景的大小/哈希、转发/保存量、停止、端口/文件释放及预算判定 |
| `scenario-coverage.json` | 场景到本轮测试方法/参数/证据的实际映射，缺口与适用性理由 |
| 带日期 Markdown 记录 | 设计/许可审查、实际技术结论、人工状态、已知限制与证据索引 |

源码摘要包含会影响行为的受跟踪及未跟踪源码、项目/包锁、脚本、profile 和映射，排除 bin/obj/TestResults；运行前后复核。不强求工作树干净，不用 HEAD 代替未提交代码。必需证据校验 schema、runId、摘要、场景身份、时间、字段和内容一致性，不能只检查文件存在。

自动报告中 `realClientVerified`、`hostVerified`、`manualAccepted`、`deployed`、`windowsCiExecuted`、`releaseGateExecuted` 为 false，表示本自动入口没有做这些工作。独立人工记录可以有不同结论，但不能回写伪造原始自动证据。运行失败也留失败摘要，不能复用上次成功报告。
