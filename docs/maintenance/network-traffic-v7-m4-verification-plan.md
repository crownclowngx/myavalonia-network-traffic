# V7 · M4 请求调试专用验证矩阵与本地开发门禁

> 日期：2026-10-03。状态：**验证要求，尚未实现和执行；没有 V7 通过结果**。
> 对应：[V7-01～18 执行计划](../roadmap/network-traffic-v7-m4-request-debugging-plan.md)、[V7 专项设计](../design/network-traffic-v7-m4-request-debugging-design.md)。
> 仅使用本地 Debug 开发验证，不使用 AIFLOW、Windows CI 或发布门禁。现有开发入口还没有 M3/M4 模式；M3 真实接入受 [V6-02](network-traffic-v6-body-capability.md)阻断。

## 1. 分层、计数和通用断言

本矩阵固定 **80 项自动业务场景**：A8 + E8 + B8 + S8 + X8 + H8 + D8 + U8 + R8 + C8。编号完整写作 V7-A01 等；J01～J05 为工程审阅，G01～G12 为门禁自测，H01～H06 为人工验收，均不计入80项业务场景。人工 H 不带 V7 前缀，与历史业务组 V7-H 明确区分。

完整累计要求为 **359 项业务场景**：M0 50 + M1 53 + UX 40 + M2 64 + M3 72 + M4 80。359 是将来必需覆盖的清单数量，不是现有测试方法数、TRX行数或已通过数量。M3 尚未闭合时不允许完整 M4 自动通过。

| 层次 | 主要对象 | 工具与证明边界 |
| --- | --- | --- |
| 纯单元 | 草稿、变量、正文模型、来源转换、状态、预览、比较、库冲突 | 复用 xUnit；Fake/可控任务/TimeProvider；不访问真实业务网络 |
| 存储与共同契约 | 正文暂存、原子库、引用寿命、取消、损坏/未来版本、Fake一致性 | 隔离临时目录、失败注入；不读取用户配置或模板 |
| 真实协议集成 | 主动生产传输、受控HTTP/HTTPS、目标身份、次数、流式/失败 | 复用 ControlledOrigin 等夹具并扩展观察点；不能只验证内存 URL |
| 生产 UI | 真实 View/Model、菜单/命令、输入、焦点、两主题/三尺寸 | Avalonia Headless/Skia与现有UiProbe，使用生产控件 |
| 资源/寿命 | 大响应、文件暂存、混合并发、取消、20轮页面与退出 | 独立进程、实际采样、任务/流/租约归零；不伪造资源曲线 |
| 门禁自测 | TRX、场景映射、身份、预算、缺前置、坏证据 | 临时合成正反例；只证明检查器，不算产品通过 |
| 人工 | Standalone物理输入、指定真实Host/客户端和用户流程 | 实际日期记录；不能由截图或本地自动测试推定 |

通用断言：准备/预览/对比/读档/打开模板/恢复窗口零网络；非法输入零上游请求头；一个接纳意图最多一次本应用发送；来源记录字节和revision不变；结果未知不重试；取消后真实任务和资源结束；同一轮证据绑定实际源码与配置。

测试以端点收到的目标、方法、转义、头、正文摘要、次数，以及 AttemptId/代次/状态/事件和额度为断言，不仅检查一个 IsBusy。参数化边界采用 N−1/N/N+1，覆盖每个等待点取消；并发通过受控完成顺序安排 A 晚于 B，避免随机碰撞或长时间睡眠。

## 13. 本地开发门禁的实现契约

### 13.1 新增文件和入口

拟新增 `tools/m4-profile.json`、`tools/m4-test-map.json`、`tools/M4DevelopmentChecks.ps1`、`tools/TestM4DevelopmentGate.ps1`，扩展已有 `verify-development.ps1` 的 M4 分支。M3入口/映射/证据要先按V6完成，不能凭空引用不存在的M3脚本。

测试拟放入 `tests/NetWorkTrafficPlugin.Tests/Requests/`、现有 `Integration/`、`Ui/` 和 `Fixtures/`；场景映射在真实方法实现后登记 FullyQualifiedName、参数化行数及执行分组。本次不生成只有空方法/假成功的map。

完整入口执行顺序：

1. 文档路径/锚点和差异格式检查；建立唯一runId及独立输出目录。
2. 固定HEAD/dirty、行为sourceHash、文档摘要及全部profileHash；包含生产代码、测试、脚本、锁文件、可执行样例，排除输出目录。
3. 运行M4门禁正反例并通过完整入口验证前置继承；不将合成数据放进产品证据目录。
4. locked restore、Debug build并将警告作为错误；普通全量测试及所有适用专项组。
5. 同轮运行M0/M1/UX/M2/M3/M4协议、资源、UI与停止验证；不复用历史成功TRX/JSON/PNG。
6. 校验80项新场景与359项累计映射，以及生产能力证据、阈值、图片及元信息；检查开始/结束行为摘要相同。
7. 生成成功/失败报告并给出相同含义的退出码。只有上述全部通过才令 `automaticPassed=true`；真实Host/人工/发布保持独立字段。

原有入口默认M0无需因本期自动更改；如后续决定默认M4，要同步所有可执行说明并单独验证。开发运行的时间预算按完整继承链实测设置，不缩短旧专项持续时间以换取总时长通过。

### 13.2 映射和证据

- 每个场景映射到真实方法及预期参数行数；必须实际执行且所有行Passed。Failed/Skipped/NotExecuted/零测试/缺方法/重复或多余执行身份都阻断。
- 方法重构要同步map，但不能靠删场景缩小必需列表。必需ID由检查器固定，map不能自我声明“只需这些”。同方法可证明多个场景，需审阅实际断言，不得全映射到一个空成功方法。
- 每轮检查继承场景并用阶段前缀区分，旧207项、M3的72项、新80项分别报告；方法数与参数行数去重统计，不能相加虚报测试数。
- 拟产物：`m4-send.json`、`m4-snapshots.json`、`m4-library.json`、`m4-compare.json`、`m4-lifetime.json`、`m4-resource.json`、`m4-layout.json`、18张生产截图及对应metadata、TRX和汇总。尚未实际产生。
- 端点证据含目标/协议/脱敏测试关联、收头次数、Body摘要、发送阶段和计数；规则次数来自生产规划调用，不能写死1。
- JSON包含schemaVersion、runId、sourceHash、profileHash、时间、观测值及计量单位，类型严格；字符串`"true"`不是布尔true。缺字段与0不同。
- 图片须解码、尺寸/主题/viewKind校验、摘要匹配、生成时刻属于本轮；只检查文件存在不够。资源证据要求原始采样和profile重算结果一致。
- 报告固定单列 `realClientVerified`、`hostVerified`、`manualAccepted`、`windowsCiExecuted`、`releaseGateExecuted`；本地自动轮后两项为false，不能因运行在Windows本机标为Windows CI。
- 未解决M3的证据应显示受阻及具体能力；不得把 `supported=false` 改成true、把复现断言方法列入可用证明，或将M3场景标“可选”。

### 13.3 门禁自测（G）

每组都要有有效正例、逐字段/逐边界破坏的拒绝反例，以及恢复后的正例。修改只发生在校验过的隔离目录，清理前验证绝对路径范围。失败检查必须经真实M4检查入口执行，不仅单测一个未接入辅助函数。

| ID | 注入内容 | 必须结果 |
| --- | --- | --- |
| G01 | TRX失败/跳过/零条/缺字段/损坏/重复ID/不符参数行数 | 非零退出，automaticPassed=false，指明方法/行 |
| G02 | 逐个删80项新场景、未知方法、空映射、ID拼错/重复 | 固定清单拒绝，不以总数凑够80放行 |
| G03 | 删除旧阶段场景/专项文件、漏继承分支、M3缺口false | 拒绝完整M4，不用旧M2通过代替M3 |
| G04 | 不同runId/sourceHash/profileHash、过期证据、起止源码变化 | 同轮身份不一致即失败，不能只更新文件时间绕过 |
| G05 | JSON缺必需字段、wrong type/null、数值负数/溢出、伪造supported | 按契约拒绝，错误数据不能被默认0/true吞掉 |
| G06 | 端点两次收头、错误目标/Body摘要、预览期发网、重复应用规则 | 可观测不变量违规拒绝，不只看测试是否Passed |
| G07 | 截图缺失/损坏/空白替代、错尺寸/主题/摘要/viewKind、缺组合 | 拒绝不完整生产UI证据，Headless不得标realHost |
| G08 | 内存/磁盘/并发/期限超限、采样不足、负值、统计与原始样本不符 | profile重算拒绝，固定布尔bounded不能代替观测值 |
| G09 | 取消后任务/租约不归零、关闭污染新页、Stop超时 | 生命周期证据拒绝，不能以丢弃await放行 |
| G10 | 自动索引/日志含敏感哨兵、部分正文标Complete、恢复重发 | 凭据/完整性/静默恢复不变量失败 |
| G11 | 外部命令非零/超时、报告残留成功、只跑定向测试冒充全轮 | 退出码与报告一致，失败保留日志，无旧结果复用 |
| G12 | Docs漏新文件、坏链接、未来命令冒充现成、发布/CI调用混入 | 文档和入口审查拒绝；恢复正例后通过 |

G07中“空白替代”需结合生产生成来源、视图交互数据与图像内容检测，不能宣称单靠PNG非空就证明生产页面。G10用已知合成敏感哨兵检测，不读取用户真实凭据。
