# V3 · M1 专用验证矩阵与本地开发门禁

> 编写/实施日期：2026-09-29。状态：**V3 测试、M1 本地门禁与证据生产已实现；实际通过范围和 H 待验见[实施记录](../archive/2026-09-29-v3-m1-implementation.md)**。
> 配套：[V3 执行计划](../roadmap/network-traffic-v3-m1-capture-plan.md)、[V3 技术设计与预算](../design/network-traffic-v3-m1-capture-design.md)、[分阶段验证计划](network-traffic-verification-plan.md)。

本文件规定如何证明 M1“可用抓包”。SOLID 为首要规定，设计模式朴素使用，测试、脚本及关键实现有详细中文注释。不使用 AIFLOW、Windows CI 或发布门禁；所有自动检查均为本机 Debug 开发验证。

## 1. 验证层次与执行原则

| 层次 | 执行方式 | 证明边界 |
| --- | --- | --- |
| 单元 U、Q | 纯数据、可控时间、可控任务及故障替身 | 契约、解析、预算、筛选和竞争，不证明真实网络 |
| 受控集成 P、S、B、D、L | 生产适配/存储、本地 HTTP/HTTPS 端点、生成式内容、独立代理进程 | 请求实际转发、双向记录、持久化及资源，不代表所有客户端 |
| 生产 UI | 生产 View/Model 与真实绑定，Headless 或专用本地 UI 宿主 | 按钮、列表、布局、选择、投递，不替代真实 Host/物理输入 |
| 回归 R | 所有适用 M0 和模板测试/证据 | 保留前置语义，不继承旧轮成功身份 |
| 门禁 G | 隔离有效夹具 + 逐项破坏，必须经完整 M1 路径 | 校验器确实会拒绝缺失/坏结果，不作为产品功能证据 |
| 设计 A / 人工 H | 代码依据、实机步骤、实际观察与日期 | 单独登记，不混入自动测试数量 |

业务必测场景共 **53 项**：U01～U16、P01～P06、Q01～Q04、S01～S04、B01～B05、D01～D06、L01～L04、UI01～UI06、R01～R02，均带 `V3-` 前缀。另有 A01～A04、G01～G08、H01～H04。

每项至少覆盖表中全部条件，必要时映射到多个 Fact/Theory 及参数行。53 是需求场景数，不是实际测试数量。参数化方法必须登记所需参数行，不可仅匹配方法名；不得用固定“测试数超过 N”替代覆盖核验。

测试采用合成 Cookie/token、本地证书和回环端点，不访问真实账号/公网服务，不安装根证书、不写系统代理或 hosts。纯逻辑竞争用屏障/假时间，集成超时设截止并记录实际顺序，不靠长 Sleep 猜结果。

## 4. 真实协议与接入（P）

| ID | 必须覆盖 | 核心断言 |
| --- | --- | --- |
| V3-P01 | HTTP/HTTPS GET/POST、流式上传、chunked/未知长度、100-continue、请求中取消 | 端点收到方法/重复 Query/Header 与正确 Body 哈希；上传结束前已有增量；不全量缓存上传 |
| V3-P02 | gzip/br 请求/响应、HEAD/204/304、重定向、重复头、206 | 三方字节层和长度有依据；重复头不丢；无正文不是记录缺失；206 不称完整文件；无额外跟随请求 |
| V3-P03 | 端口无效/冲突、上游拒绝/响应头超时、无效 CA/域名/过期、客户端不信任 | 中文 Stage/Kind 明确；启动失败无残留；不关闭证书校验、不自动重放 POST |
| V3-P04 | 当前 CA/重启新 CA、公开导出、客户端信任未知/成功、不走代理 | 只导出公钥；指纹/运行身份变更；一次连接不代表全机信任；系统代理/信任库快照不变 |
| V3-P05 | 普通 h2 两侧实际版本、同连接多流，列表/请求体/响应体归属 | 实际两侧 h2 证据；RecordId、连接/流归属不串；映射 h1 限制继续可见 |
| V3-P06 | 用户确认的 h2 产品降级：同连接沉默流仅提示；客户端取消该流，其他流继续；全局停止 | 实际两侧 h2、同客户端连接；空闲时 Receiving/Partial、有明确限制，自动取消支持为 false；客户端取消后另流事件继续、活动数为 1；Stop 后为 0；h1 自动空闲超时与活跃流仍回归 |

P01 是进入双向抓包实现的技术前置。仅 POST 短正文成功不证明大上传有界，需同时执行 B01。

取消上传必须在代理 Stop **之前**验证请求记录终态，避免停止强行 Cancelled 掩盖错误 Complete。未知长度取消允许无回执或一个已接收前缀回执；用端点实际哈希与生成体完整/观察前缀哈希核对，不能把“回执数非零”直接等同完整上传。chunked 原始结束块以公开 IsLastChunk 回调核实。

P06 于 2026-09-29 根据用户“直接引用 GitHub 发布版本”和“不能实现就从产品层面降级”调整。官方最新正式版本仍为 7.0.13；门禁要求 `idleCancellationSupported=false`、`idlePolicy=notify-only`、限制诊断、诚实状态、同连接与取消后继续的实际证据。不会删除 P06 或把不支持写成 true。接入面板在启动前后显示同一说明，H 项仍需真实客户端验收。

## 6. 流式内容（S）

| ID | 必须覆盖 | 核心断言 |
| --- | --- | --- |
| V3-S01 | SSE 每字节切块、跨块 UTF-8/BOM/CRLF、CR/LF、多 data、空 data、心跳、event/id/retry、未知字段 | 按规范组装并保留字段，EOF 半事件不算完成；不触发重连；所有切分位置有参数化断言 |
| V3-S02 | SSE 正常结束/取消/失败、超长事件、事件环淘汰、预览丢块、磁盘记录到顶 | 保留/累计/淘汰/缺口可区分；不把截断事件显示为完整；磁盘满仍可有界观察实时事件 |
| V3-S03 | NDJSON LF/CRLF、跨字符、空行、坏行后好行、超长行、正常/异常 EOF 末行 | 合法行独立解析；错误不吞后续；异常尾行标未完成；普通 JSON 不误识别为流 |
| V3-S04 | 端点首事件→代理预览→生产 UI→响应结束、暂停/继续跟随、十分钟活动流 | 第一事件在结束前显示；暂停接收量继续增长；继续到最新并披露淘汰；时延有真实时间戳 |

SSE 行为依据 [WHATWG 解析规则](https://html.spec.whatwg.org/multipage/server-sent-events.html#parsing-an-event-stream)，适用范围及诊断差异见技术设计。自动观察者不得在块回调里写文件或同步操作 UI。

| V3-B01 | 128 MiB/1 GiB 上传与下载，有长度/未知长度、三种记录策略，至少各三次比较 | 客户端/端点增量哈希正确；峰值不随完整体积增长；记录前缀长度/哈希符合所选策略 |
| V3-B02 | 慢盘、拒绝写/磁盘满、队列满、请求/响应并发争额度、保留上限 | 转发继续且记录标部分/失败；队列/预留/物理占用不越界；终态可查 |
| V3-B03 | 默认 1 GiB 会话/显式 2 GiB、根目录 4 GiB、元信息 64 MiB、残留/清理失败 | 临时和残留计费；1 GiB Body 在默认会话可能部分，完整探针明确用 2 GiB；不删除用户外部目录 |
| V3-B04 | 正常/损坏/超像素 PNG/JPEG、压缩膨胀、图片反复选择、文件/视频/206 | 不做全文件预览或无限解码；缓存和解码名额有界；未知总量不伪造百分比；不播放/补下载 |
| V3-B05 | 20 路混合、至少5条活跃流、一万摘要、保存时滚动筛选、20次页面开关 | 代理+UI 资源分别采样；没有随轮次增长的存活订阅/任务/位图；时延及停止符合 profile |

资源测试不能在服务端/断言先构造完整 1 GiB 数组；使用固定 64 KiB 生成、复制和哈希缓冲。真实磁盘满用受控限额存储/故障适配模拟，另验证真实目录权限错误；不填满用户磁盘。

B01 每轮重复使用独立受控目录并在完成取证后释放该轮自有文件，防止上一轮占用根配额改变下一轮记录模式；B03 专门保留跨会话占用来验证累计配额。两类夹具不得混用。

## 8. 保存、回看与恢复（D）

| ID | 必须覆盖 | 核心断言 |
| --- | --- | --- |
| V3-D01 | 文本/JSON/小图/文件/SSE/元信息/部分/失败混合保存并重开，含正文到顶但实时预览继续 | 身份、顺序、头、来源、状态、长度、摘要一致；部分仍部分；未落盘实时尾部不冒充存档内容；零网络/零监听 |
| V3-D02 | Receiving 时保存；冻结后旧块/新块写完、终态到达；不同记录并发变化 | 每记录来自同一捕获快照 Revision，Body 仅冻结水位；UI 明示保存时接收中，不等待 SSE 结束 |
| V3-D03 | 复制/flush/manifest/改名各阶段失败或取消，目标重名，退出与保存竞争 | 无假成功，无覆盖旧目标；只清自己的临时目录；残留计费，租约释放，退出有界 |
| V3-D04 | manifest 损坏/未来版、JSONL 尾行截断、Body 缺失/哈希错/长度变动、重复 ID | 不误报完整；单条降级和整体无法加载区分；诊断说明具体范围 |
| V3-D05 | 路径越界/绝对/UNC/重解析点、超记录数/元信息行长/总量、整数溢出 | 在分配/读取前拒绝；不跟随外部文件；不执行存档内代码或网络地址 |
| V3-D06 | 异常进程退出后恢复、未提交临时目录、正在读取时删除、部分 Body 导出 | 保留 Interrupted/缺口；不自动重抓；活动租约拒绝删除；导出仅已有字节且哈希正确 |

存档摘要需流式验证，不能一次读入全部 Body。每个失败点使用独立目标/夹具，避免前一个失败残留恰好使后一个测试通过。

## 11. 负载、阈值与测量方法

预算值以技术设计第 5 节和实施后 profile 为准；以下阈值已冻结到 profile，实际结果见实施记录。

| 测量 | 负载与方法 | 初始开发门槛 |
| --- | --- | --- |
| 代理内存 | 独立进程；20×16MiB预热；128MiB/1GiB各3次；250ms采样，含每种策略 | 私有内存增量≤256MiB；大/小文件峰值增量中位差≤64MiB；M0阈值不放宽 |
| UI内存 | 同一生产UI进程一万摘要稳定预热；先20路混合、保留5流持续10分钟，完成20轮页面打开/关闭 | 相对预热私有增量≤256MiB；有限缓存≤profile；释放后业务订阅/任务/位图租约=0 |
| 流式首预览 | 受控端点发首事件并等待预览确认才发结束；记录端点、客户端、捕获和UI时间 | 首事件在响应结束前可见；从捕获可解析时刻到UI可见≤1秒（生产UI宿主测） |
| UI投递响应 | 一万摘要+5条流，记录至少200次输入投递到处理完成的延迟 | p95≤200ms，最大≤1秒；页面待投递数≤1；批量每次≤200 |
| 列表虚拟化 | 固定一万行，滚动头/中/尾并记录实现容器数 | 容器数≤当前可见行数×3+20；不因总行数实现一万控件 |
| 十分钟流 | 至少5条持续流+普通请求，M0已有10条流基线仍完整回归 | 活跃流不中断；预览/磁盘/事件预算不超；淘汰和缺口计数正确 |
| 退出 | 有并发网络/保存/预览时停止；包括故障路径 | 正常释放≤10秒；超时必须失败且Faulted；端口重绑/文件独占打开成功 |
| 句柄/残留 | 独立进程停止前后、20轮生命周期，列举自身文件/任务 | 无仍活跃监听/写入/订阅；句柄增量≤M0的32且无逐轮增长趋势 |

机器/SDK/Debug、采样时钟、重复数、空闲基线、所有峰值和原始曲线都入证据。受控时序使用单调计时，UTC只用于关联。Headless 不适合证明物理输入延迟，UI时延必须由生产UI宿主实测；执行环境缺失使完整 M1 未验证，不能自动跳过。

慢盘/坏图测试采用固定故障安排，阈值改变须在运行前写入 profile 并记录理由。测试不得打印机密正文；原始曲线使用合成流量标识。
