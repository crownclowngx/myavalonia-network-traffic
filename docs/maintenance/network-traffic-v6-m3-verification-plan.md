# V6 · M3 单元测试、验证矩阵与本地开发门禁

> 日期：2026-09-30。状态：**验证设计，M3 测试/门禁待实现，业务结果未执行**。
> 配套：[V6 执行计划](../roadmap/network-traffic-v6-m3-dsl-rewrite-plan.md)、[V6 改写专项设计](../design/network-traffic-v6-m3-dsl-rewrite-design.md)。

SOLID 是首要规定；朴素使用设计模式，代码、测试及脚本使用详细中文注释并解释设计思路。不使用 AIFLOW，不新增或触发 Windows CI，不运行发布门禁。本机 Windows 的 Debug 单元/集成/UI/资源验证允许执行，发布相关门禁留到正式发布。

## 1. 完整集合与验证分层

V6 固定 **72 项业务自动场景**：L8 + D8 + W8 + B8 + P8 + S8 + T6 + F6 + U6 + Q4 + R2。另列 **A01～A04 工程审查、G01～G12 门禁正反例、H01～H04 人工验收**，不混入 72 项。完整 M3 同轮继承当前 M0/M1/UX/M2 的 207 场景，累计 **279 项**；场景数不是测试方法数或预填通过数。

| 层次 | 必须证明 | 主要位置 |
| --- | --- | --- |
| 领域单元 | v2 解析/类型、状态、优先级、冲突、动作、预算、修订接纳 | `tests/NetWorkTrafficPlugin.Tests/Rewrite/`，旧 Dsl/Rules 回归 |
| 适配与存储集成 | 真实有界字段源、规则库、原子存档、旧格式、取消和资源归还 | 现有 Integration/Fixtures，新改写夹具 |
| 受控真实协议 | 生产 Titanium 链路、目标接收计数、Host/SNI、字节/长度、零重试 | ControlledOrigin/ProxyFixture 扩展，不只 Mock HttpClient |
| 生产 UI | 真实 View/Model 绑定与按钮，预览/保存/启用区分，差异和全局状态 | 现有 Ui 与 UiProbe，禁止另造展示专用页面 |
| 资源与寿命 | 生产路径的耗时/字节/内存/并发/释放，原始曲线 | 新 M3ResourceProbe，继承全部旧专项类别 |
| 门禁自身 | 非零/缺证据/混轮/错误观察/漏前置确实被完整入口拒绝 | M3 检查器和自测脚本 |

沿用现有 xUnit、受控端点、TRX 和证据工具，不另建测试框架。一个场景可映射多个方法/参数行；关键参数必须全部 Passed。仅存在同名测试、Trait、文件或 `passed=true` 不能证明场景通过。

## 4. 协议、状态与持久化矩阵

### 4.1 生产协议（P，8 项）

| ID | 必测输入 | 可观察断言 |
| --- | --- | --- |
| V6-P01 | 全域名与按字段 A→B、未命中 A、并发 A/B/C | 实际端点身份/请求 ID/次数/正文正确；未命中不被全局目标污染 |
| V6-P02 | HTTPS 不同主机/端口/证书、所有动作组合 | B 实际 Host/SNI/端口、path/query/header/body 与计划一致；A 为 0 |
| V6-P03 | 改写模式 h1、允许回退的 h2、exact h2、普通捕获 h2 | 记录两侧实际协议；回退不算 h2 改写成功；普通 h2 回归保留 |
| V6-P04 | 普通模式运行中启用、改写模式中停用/切修订、旧 M0 Mapping 同配 | 拒绝不兼容启用和双重规则来源；不在活跃连接里偷偷切协议 |
| V6-P05 | SSE 跨块字符、NDJSON、慢/大响应、头规则大上传 | 第一事件在结束前可见、字节摘要正确；无全量请求/响应缓存 |
| V6-P06 | 127.0.0.1/localhost/IPv6/别名、多 DNS 地址/检查后变化、当前监听端口 | 循环目标拒绝且没有二次进入代理；实际连接与检查契约一致或保守拒绝 |
| V6-P07 | 目标证书主机名错/过期/不可信、连接拒绝、响应头超时 | 不关闭证书校验，不回 A，不重试；明确本地失败与上游响应 |
| V6-P08 | POST 到 B 后断开/超时、提交部分失败、客户端取消 | B 最多接收一次、A=0；NotSent/MayHaveBeenSent/ResponseObserved 与观测一致 |

P01/P02 记录服务端原始接收结果，不只回显客户端填入的目标。需要证明零发送的场景，端点除应用调用计数外还采集接收头/正文入口；完成取消/清理屏障后核对，不能以固定 sleep 后暂未到达作为唯一证据。

| V6-Q03 | 600 秒、20 并发、5 持续响应流，50 次修订切换；128 MiB 和1 GiB生成式响应 | 实际数量/时长/字节摘要齐全；请求各自固定目标/修订；请求规则不缓存整响应 |
| V6-Q04 | 20 轮页面挂卸和启停，≥200 UI 响应样本，每秒资源采样 | 私有内存增量≤256 MiB；UI p95≤200 ms、max≤1000 ms；取消≤1000 ms、Stop≤10000 ms；活动任务/槽/订阅/租约归零，句柄增量≤32 |
| V6-R01 | 全部 v1 样例、字段/分组/规则库、原生存档 v1/M1 阅读、注册对象图 | 同轮旧 207 场景通过；M2 不误读有效头/Body；Document/Tool/Standalone 复用生产服务 |
| V6-R02 | 普通 h2/空闲仅提示/客户端单流取消、原捕获配额/流式/停止 | 不扩大旧降级范围；全部旧资源证据仍合格，不用历史报告替代 |

Q03 的 20 并发至少含 5 个流与覆盖 A/B/C 的普通请求；Body 并发限额独立保持 4。50 次热切要有每次确认后的新接纳请求，不能只空切状态。资源测量期间至少完成 1000 个普通请求，记录失败类别、端点计数、字节和错路由数（必须 0）。原始 CSV 需覆盖整个 600 秒，不能只采开始/结束。

未修改正文的头规则另用 128 MiB 生成式上传证明无整包缓冲。响应负载沿用 M1 记录模式/磁盘阈值，1 GiB 是传输字节，不强求在所有捕获模式完整保存。硬预算及槽位属于确定性测试；墙钟性能属于受控探针，调整机器/profile 条件要记录依据后重跑，不能改夹具把负载变小而保持相同场景名。
