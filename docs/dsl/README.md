# M2 DSL 使用与设计手册

本文件夹专门说明 HTTP 工作台当前实现的 **DSL v1**：如何写规则、每种语法是什么意思，以及为什么这样设计。内容对应 V5 / M2 实现，更新日期为 2026-09-30。

DSL 是“领域专用语言”。在这里，它把一批已经捕获的请求转换为业务字段，再按条件、时间窗口和业务键分组。例如：从 Query、Header 或 JSON 中提取调用者，把同一租户、同一调用者的请求放在一起，查看调用时间线。

## 先理解这条处理链

```text
当前捕获 / 已打开的原生存档
    → 冻结本轮保留记录
    → 来源选择、时间窗口
    → where 过滤
    → field 按需提取业务字段
    → group by 确定分组键
    → 组列表、未确定身份、调用时间线
```

字段在被条件、分组键或显示列引用时才求值，上图表示职责，不表示先统一读取所有正文。当前规则只读请求，不发送请求、不改写流量，也不读取响应正文来识别业务身份。

三个名字要分清：

- `field` 是单条请求计算出的业务字段，例如 `caller`。
- `view "名称" { ... }` 是一份规则的查询定义，描述过滤、窗口、分组和显示。
- 界面的“保存视图”保存规则修订以及窗口、来源、列等选项。保存后仍需点击“应用/刷新”才能重算当前记录。

## 一份最小规则

```dsl
dsl 1;
field caller = first(original.query["user"]);
view "按调用者查看" {
    where source == "capture";
    within last(30m);
    group by caller;
    columns caller;
    timeline by startedAt;
}
```

它将最近 30 分钟内、来源为捕获的请求，按第一个 `user` Query 值分组。`?user=u1` 和另一条 `?user=u1` 属于同组；未提供 `user` 的请求会进入“未确定”，前提是它通过了来源、窗口和条件筛选。

初次运行时，把“窗口覆盖”和“显示字段”留空，来源保持 `capture`，避免界面选项覆盖规则。操作顺序为“分组 → 规则 → 验证 → 样本预览 → 返回分组 → 应用/刷新”。

## 当前范围与容易误解的地方

- 分析的是本次冻结的**全部保留记录**，请求页筛选、滚动位置和列表清除水位不决定分析范围。已经淘汰或未保存的数据无法补回。
- 样本预览最多 20 条，解释字段和条件；它不执行完整的窗口、来源覆盖统计，也不会替换已应用结果。
- 只有确定的 `True` 通过 `where`。数据不完整产生的 `Unknown` 不会被当作 `False` 再取反选入。
- 每条请求只有一个确定组合键；列表不能直接用于分组，不会把一条请求展开成多个组。
- 相同遮罩文字不表示同组。“组 1”“组 2”用于区分隐藏真实值的组，组数不等于人数。
- `manual` / `replay` 是预留来源名称；当前生产捕获来源为 `capture`，这些名字不表示已经支持手工请求或重发。
