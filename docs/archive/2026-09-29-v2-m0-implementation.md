## 3. 调查中发现并处理的问题

1. Titanium 默认构造器可安装根证书：显式关闭两个信任选项，直接赋值内存根，关闭缓存证书落盘。
2. 普通 h2 不应无条件重写 URL/Host，否则破坏路径处理；改为仅命中映射时操作。跨 authority 映射仍出现 PROTOCOL_ERROR，当前整个映射运行只启用 h1；exact h2 拒绝和回退行为均进入测试。
3. Windows Schannel 不接受夹具签发路径的 ephemeral 私钥。夹具在内存重载 PFX，使用随证书 Dispose 回收的临时密钥容器；不使用 PersistKeySet，不安装信任或写 PFX 文件。
4. h1 短读可能保留客户端连接。适配器在字节不完整时终止该 h1 会话，实际短读测试立即观察失败。
5. 第一轮十分钟测量发现活跃 SSE 提前结束。固定源码 ResponseHandler 在整次 CopyBodyAsync 外只启动一次 IdleRead 截止。改为记录最后 Body 活动，用单个检查任务执行真正的空闲判断；短窗口回归覆盖活跃与沉默两种情况，完整资源探针重新执行。

6. 第二轮完整资源测试在停止后句柄检查失败。固定源码 TcpServerConnection.Dispose 会延迟一秒关闭上游 socket，现等待公开 ServerConnectionCount 归零及尾部调度。临时句柄类型调查进一步确认：单连接预热时 Thread=19/Event=115，并发后停止 Thread=58/Event=178；文件句柄约恢复至基线（73→74）。增加同等 20 请求并发预热，保留原 +32 总句柄及所有内存阈值，短周期退出回归通过；临时原生诊断代码已移除，调查日志保留在 TestResults/initial。

## 4. 实际交付与原设计差异

当前行为以[运行说明](../reference/network-traffic-m0-runtime.md)为准。契约集中在一个文件；错误是分层中文摘要和异常类别；页面轮询代替事件通知；独立 SSE 解析器尚未接入事件 UI；预览缓存/事件历史留到 M1。资源曲线使用并发预热后的独立进程基线，另记录启动就绪快照，未采集冷启动过程峰值。

库没有所需普通上游私有 DNS 注入入口，探针用 IP SAN 的 A 与 DNS SAN 的 localhost B，不修改 hosts。配置只支持运行级不可变精确映射；不做 DSL、热切换或正式环境映射。生产捕获仍为 Captured，探针来源由证据场景标识。
